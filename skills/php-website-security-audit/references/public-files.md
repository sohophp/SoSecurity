# 公开文件访问边界专项

适用于全站安全加固中的服务器文件边界检查，以及上传目录、文档、点文件、配置、源码、备份或开发工具通过网站泄露的检查与整改。范围以用户授权的站点和文件类别为准，不扩展为无关业务改造。

- 保留用户明确要求保留的入口说明或文档内容，通过服务器访问控制阻止读取；不要删改原文、移动文件或仅移除导航来替代修复。
- 检查根目录及嵌套目录的 Markdown、大小写变体、内部文档树和任意层级的点文件／点目录。不要默认为某个隐藏目录保留通用放行；证书验证等确需公开的功能先确认最小例外，再单独验收。
- 按实际部署盘点源码、配置与密钥、依赖及构建元数据、版本控制数据、测试与命令工具、日志、数据库文件、源码映射、临时文件和备份副本。保留正常页面、脚本、样式、图片、公开索引及必要下载，不按所有文本、数据或压缩文件一刀切。
- 规则应在静态响应和应用路由之前生效。核对目录列表、内容协商、目录覆盖、可选模块及替代文件读取入口；有重写规则不等于重写模块确实加载。维护者通过文件系统查阅文档，不为查阅新增公开下载入口。
- 使用只含无敏感内容的测试文件，在隔离 Web 服务器验证规则；覆盖模块启用／禁用、根安装／子目录安装、HTTP 与 HTTPS、GET 与 HEAD、编码路径、扩展名后缀和正常资源。不能仅用不存在文件的错误证明访问控制。
- 获准发布后，再核对生产已知可达文档的实际拒绝、响应正文和正常页面；区分规则已提交、已推送、已部署及已复验。保留文件内容哈希与受控证据，不在报告中复制密钥或内部文档原文。

## 上传目录规则与版本管理

- 先确认服务器类型及配置是否生效。Apache 项目检查根目录与上传目录的 `.htaccess`、`AllowOverride`、父子目录和处理器优先级；其他服务器核对等效配置，不能通过添加不被服务器读取的文件宣称完成。
- 上传目录应禁止目录列表、程序执行、服务器端包含和不需要的内容协商。阻断继承的扩展名处理器，同时拒绝脚本源码读取；仅关闭执行可能变成源码泄露。静态处理限定实际文件，避免改变目录请求行为，勿将该策略套用到整站入口。
- 拒绝规则覆盖脚本大小写、多重扩展名、备份及路径后缀，以及各层级点文件／目录和实际私有目录。保留正常下载；不得把示例项目的目录名直接作为所有项目的完整私有目录清单。
- 无秘密的规则由对应站点仓库跟踪，上传内容继续忽略。首次接管生产已有文件前，在 Web 根目录之外备份并比较自定义规则；共享程序仓库更新不代表子站文件已更新。普通文件发布可完成时不新增数据库迁移。
- 隔离服务器测试须覆盖父级脚本处理器映射、缺少根目录保护和关闭重写模块的场景，使用真实无敏感测试文件同时验证拒绝、目录请求和正常下载。生产测试文件的写入、上传及清理按实际授权执行，不因需要验收而自行新增维护入口。
- 请求先禁用自动跟随重定向，记录原始状态及跳转地址，再分析最终响应与正文；错误页返回成功状态不能证明原文件可读。生产完成还需对应站点的部署版本和规则内容证据，不能仅凭首页正常、隐藏文件拒绝或隔离环境通过认定。

本专项不授权破坏性测试、清空运行目录、替换密钥、改写 Git 历史或发布到其他站点。沿用本次会话已经提供的修复和发布授权。
