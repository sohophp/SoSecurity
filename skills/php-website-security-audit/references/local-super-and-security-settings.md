# 本地 super 与后台认证配置

适用于已确认采用 CoreRepo 兼容本地 super、MySQL 加密配置和 OpenSSL 的 PHP 网站。这里的相对路径、页面名称和服务名是该集成方式的约定，应用到其他项目之前先检查实际代码及用户要求；不强行替换其他项目已有的认证架构。本文只记录实施方法，不保存真实校验值、密码、应用凭据或具体站点地址。

## super 文件保存位置和使用方法

| 用途 | 相对项目根目录的位置 | 使用规则 |
| --- | --- | --- |
| 首选本地 super 配置 | `App/Config/super.php` | 已有文件优先，使用受信任 CoreRepo 的同一组密码校验值；禁止覆盖现有有效配置 |
| 受限托管备用配置 | `uploads/.private/super.json` | 仅首选文件不存在时读取，保存同一配置数组的 JSON 数据；不作为 PHP 执行 |
| dasdk 加密主密钥 | `uploads/.private/settings.key` | 只加解密 dasdk App Key，不作为 super 密码或身份凭据 |
| Turnstile 加密主密钥 | `uploads/.private/turnstile.key` | 只加解密 Turnstile Secret，与 dasdk 主密钥分开 |

### 加载与凭据

- 首选文件存在但无效、不可读或异常时拒绝该本地凭据，不能把异常当成“不存在”而加载备用配置。
- 配置字段为 `password_hashes`，对应两条既有的邮箱与密码绑定校验值。复制相同校验配置不等于新建用户名为 `super` 的数据库账号；登录使用原绑定邮箱和密码。
- `SuperAdminAuth::loadLocal()` 负责选择配置，`verify()` 验证本地凭据。生成新校验值必须明确获得换密授权并使用该项目的邮箱绑定算法；不能用普通 `password_hash(password)` 替换现有绑定格式，也不能自动生成新密码覆盖既有配置。
- 备用 JSON 只能初始化固定路径，并核对可信来源的配置摘要；拒绝上传任意 PHP、任意文件名或任意用户提供的校验值作为初始化来源。备用文件已存在时不静默覆盖。
- 不把 super 校验配置放入数据库可编辑参数、普通后台设置、Session 或日志。不依赖 dasdk 服务、SDK 主密钥或设置锁加载本地 super；企业认证或 SDK 配置损坏不应阻断本地凭据验证。
- 正常认证沿用普通账号→符合范围的企业认证→本地 super 的顺序；任一成功即停止。配置未就绪的受控初始化登录是单独的例外，仅尝试本地 super，不能顺便放行其他身份。
- 身份权限由服务端验证的本地来源决定。企业管理员、程序员或项目管理身份不等同本地 super，不得因职务获得两个安全设置页的访问权限。
- 本地 super 会话绑定归一化邮箱和当前校验配置版本；校验配置改变后旧 super 会话失效。不能把持有某个加密文件或前端声明 `isSuper` 当作认证。

### 保存与部署

- 私有目录为 `0700`，JSON、密钥及锁文件为 `0600`，由实际 Web 进程创建和读取；首选配置按部署用户及 Web 读取需要设置最小权限。不要为修权限开放整个上传目录，也不要由 CLI 抢先创建 Web 不可写的主密钥。
- 首选 super 文件及整个 `uploads/.private/` 均不进入 Git。文件部署、缓存清理、版本回滚和上传清理必须保留私有目录，不能把它当作 `uploads/tmp/`。
- 检查父目录、文件、锁和原子替换路径，拒绝符号链接、路径逃逸、异常类型及过宽权限。Web 服务器拒绝私有目录和配置文件访问，应用下载接口也不能读取它们。
- 启用相同 super 配置与重新分配生产权限是两件事；只在用户授权的目标环境初始化，不借技能授权向其他站点分发凭据。

## 人機驗證設定

后台入口约定为 `/newadmin/turnstileSettings`，实现服务为 `TurnstileSettings`；前后台挂件与服务端验证统一使用 `Turnstile`。

### 配置与使用

- 只有本地 super 能打开页面或提交保存；匿名跳转登录，普通后台账号及企业身份直接 GET/POST 均返回 403。首页覆盖模板与通用布局都应显示 super 专用入口。
- 同一条 `security_settings` 记录 `turnstile.credentials` 原子保存 Site Key 与加密 Secret Key。数据库无记录才使用环境中的 `TURNSTILE_SITE_KEY`、`TURNSTILE_SECRET_KEY`；记录存在、数据库读取异常或密文损坏时不能自动降级到旧环境值。
- 页面显示 Site Key 和 Secret 是否已设置，不回显 Secret。同一 Site Key 下 Secret 留空保留已有数据库值；首次设置、改变 Site Key 或修复损坏配置时必须填写完整的一对密钥。环境预设首次转存也要求完整导入，不能仅更改公开标识而沿用不匹配的 Secret。
- 每次保存需要当前本地 super 密码，保留同源检查、Symfony 请求及用途 CSRF、通用限流，并增加每 IP、每账号各 15 分钟最多 5 次的独立敏感操作预算。成功后重定向，响应禁止缓存，审计不记录密钥或表单原值。
- Cloudflare 中需允许实际站点域名；后端继续校验域名白名单、action、期限和严格成功状态，保留 TLS 校验、5 秒请求超时及测试密钥拒绝。保存成功、挂件成功与真实 Siteverify 成功分别验收。

### 未配置时如何进入设置

此初始化方式仅适用于用户已确认允许本地 super 完成配置或修复的项目，不推广为所有网站默认豁免。

1. 服务端从持久配置判定未配置或本地配置不可读，不接受 URL、表单、请求头或 Cookie 宣称进入初始化模式。
2. 仅在 CSRF、来源、独立 IP／账号限流及当前本地 super 密码全部通过后建立本地 super 会话，并导航到人机验证设置；不尝试普通账号或企业认证。
3. 普通账号和企业账号不能因此免验证；错误 super 密码也不能进入后台。
4. 配置就绪后所有身份，包括本地 super，均恢复正常人机验证。已就绪配置的挑战失败、过期或 Cloudflare 网络异常，不自动触发免验证登录。
5. 已授权的密钥丢失或损坏修复需完整新凭据和当前 super 密码；正常保存禁止静默重建主密钥。修复 Turnstile 不删除或重建 dasdk 密钥。

## dasdk 安全設定

后台入口约定为 `/newadmin/dasdkSettings`，统一解析服务为 `DasdkSettings`。

- 页面和保存接口仅允许本地 super，导航隐藏不能代替服务端权限判断。页面显示 App ID 和 App Key 是否已设置，App Key 不回显。
- 同一条 `security_settings` 记录 `dasdk.credentials` 原子保存 App ID 与加密 App Key。无记录才沿用原环境配置；已有记录、等待重新设置标记、数据库异常或解密失败均不回退旧配置。
- 首次保存和更改 App ID 必须提供 App Key；App ID 不变时 App Key 留空保留已有数据库值，不能把空字符串误作清除配置。
- 正常保存使用 POST、来源与 Symfony CSRF 校验及限流。配置损坏后的明确重新设置还需当前 super 密码及每 IP／每账号 15 分钟 5 次独立预算；先持久化等待重新设置状态，再修复对应主密钥并写入完整新凭据。有效主密钥应保留。
- 已选择简化设置的项目只提供一张配置表单，不自动添加主密钥备份、下载、上传恢复或独立公开重设入口。主密钥丢失且无外部备份时，旧密文不可恢复，只能由本地 super 重新填写完整凭据。
- 登录、身份校验和远端退出通过同一个解析服务创建 dasdk 客户端。解密只用于服务端调用，不把 App Key 放入通用配置、文件缓存、Session 或日志。
- 保留企业邮箱范围、正常账号认证顺序、5 秒请求超时和 TLS 校验；不因加入配置页启用 SSO 或改变企业授权。SDK 配置异常不得阻断普通本地账号及本地 super 的认证，独立人机验证策略仍生效。

## 加密、迁移与验收

- 两类主密钥各为 32 字节随机值、以 Base64 文本保存；加密采用 OpenSSL AES-256-GCM，每次生成新的 12 字节 IV 和 16 字节认证标签。版本封装与 AAD 分别绑定用途及 App ID／Site Key，拒绝未知版本、认证失败及跨配置挪用。
- 首次初始化使用独占锁、排他创建和完整写入检查；正常路径发现已有密文而对应主密钥缺失时拒绝自动生成新密钥。明确修复也必须限制为对应配置，不能影响另一类密钥或 super 校验配置。
- 发布前先备份目标数据库并验证恢复，再执行结构迁移和旧有效配置的加密导入。已有数据库记录不重复导入覆盖；解密比较在服务端完成，仅返回一致性结果。禁止在未经核验的情况下把测试站凭据复制到生产，历史明文不会因加密迁移自动消失。
- Git 发布、数据库建表、私有文件就绪及远端授权分别核验。若需已授权的临时 HTTP 迁移，限定目标、固定操作、有效期及强认证；完成后删除、封禁，并以原有效认证材料复查不可访问。
- 验收覆盖两种 super 文件的优先级、无效首选不启用备用、企业身份拒绝、CSRF／来源、重验密码与限流、配置优先级、密文篡改、主密钥丢失及独立性、初始化限制、配置后恢复验证，以及真实 Web 下私有路径和替代下载入口的拒绝结果。
- 隔离身份及测试密码验证、本地加解密、真实后台保存、真实挑战验证、真实企业登录和远端退出分别报告；未执行的项目不能因模拟对象、保存成功或配置可解密就标为通过。
