# PHP 网站安全自查

在用户指定的 PHP 项目中执行有证据的安全检查。结果包括入口与风险清单、已授权的修复、正常及异常复验、剩余风险和实际发布状态；读取规范或接入组件本身不是安全验收。

## 先读取规范，再确定本次范围

读取 [PHP 网站安全自查清单](references/php-website-security-checklist.md)，先遵守其最前面的文档编写与维护规范。检查相关章节时同时核对最低验收矩阵与例外条件。

- 核对当前仓库约束、运行时与实际配置、Git 状态和用户已有授权，保留既有修改。
- 用户只要求对照或检查时，先输出证据及整改范围；用户已要求修复时直接完成已授权的整改与复验，不重复索取授权。
- 全站检查须盘点前台、后台、接口、异步调用、外部回调及旧入口；专项检查围绕指定范围，记录未覆盖部分，不扩成无边界全站改造。
- 依赖公告、软件行为与外部服务协议依据当前安装版本和维护方资料核对，不能只凭记忆判定。

## 检查、修复与复验

1. 建立入口清单：关联身份来源、方法、副作用、对象权限、CSRF／协议保护、请求预算、故障处理及确认的例外。
2. 逐项记录“待检查、已验证、发现问题、已修改待复验、不适用、已确认例外”，附调用链和运行证据。配置存在、按钮隐藏和扫描命中都不能代替实际行为验证。
3. 优先修复已证实的高风险入口，再补调用点及统一策略。保持目标项目的 PHP 兼容性、认证协议、原权限、文件地址和正常工作流程；必要变化明确记录。
4. 用隔离测试身份与数据验证正常和异常两面，检查拒绝发生在副作用之前；覆盖适用的跨会话、越权、并发、过期与存储故障。清理仅限自己创建且确认归属的测试数据。
5. 数据结构或生命周期变化使用目标项目的迁移机制，核对完整备份、互斥、实际结构成功、幂等及失败恢复。无结构变化不制造迁移文件。
   会话存储切换参照清单第六节核验过期、后端故障与旧状态隔离；功能退役参照第十二节核验动态引用、数据删除授权及备份比较的时间边界。
6. 更新项目维护文档、变更记录和受控报告，给出剩余风险及验证边界；只在出现新的变化或未解决问题时补充相关复验。

全站安全加固、上传目录加固及公开文件暴露专项同时读取 [公开文件访问边界](references/public-files.md)，落实用户要求保留原文件内容的约束，并用真实 Web 服务器验证拒绝和正常访问。适用 Apache 时将 `.htaccess` 优化纳入范围，其他服务器采用等效配置；核对独立子站的规则版本管理和部署，不为纯文件规则更新新增数据库迁移。

## 本地 super、人机验证与 dasdk 配置

涉及 CoreRepo 兼容本地 super 文件位置、加载顺序、后台「人機驗證設定」或「dasdk 安全設定」时，读取 [本地 super 与后台认证配置](references/local-super-and-security-settings.md)。其中的相对路径和服务名是特定集成约定，先核对当前项目，不要求其他项目照搬。

- 本地 super 校验配置与应用加密密钥分开；既有首选配置无效时不得自动启用备用凭据。部署保留私有配置，企业职务不授予本地 super 权限。
- 两类设置只允许本地 super 管理，数据库配置优先，损坏或读取失败不回退旧凭据；不回显秘密，保留来源、CSRF、重验密码及独立限流。
- 仅在用户明确接受初始化策略时，允许未就绪配置下经完整密码验证的本地 super 登录设置；普通及企业身份不豁免，配置就绪后的挑战失败不触发绕过。简化配置流程不自动增加密钥备份／恢复页面。

## 不可忽略的边界

- 项目根目录 `README.md` 只能保留一行一级标题，内容为实际仓库名（`# 仓库名`），不得追加说明、链接、徽章、命令或其他正文；其他项目说明、安全规范、审核报告和操作文档只能放在 `docs/` 下的 Markdown 文件中，并遵守下述固定文档分支规则。迁移已有说明时保留内容，不直接丢弃。
- `docs/` 目录及其所有子目录、文件一律禁止通过 HTTP(S) 浏览或下载，不限于 Markdown 扩展名，也不能只关闭目录列表。拒绝应覆盖静态响应、应用文件读取入口、别名和符号链接；验收必须包含已存在的非 Markdown 文件及正常公开资源。

- 应用仓库的详细安全规范、审核报告及修复说明仅保留在一个固定文档分支，默认使用 `docs/security`，已有明确指定时沿用指定名称。其他分支当前文件树不得包含根级 `docs/`；同步设置忽略规则并在合并、推送前核对实际文件树，不能只依赖忽略规则。文档分支长期保留，不按已合并临时分支清理。
- 清理代码分支的文档前，先完成文档分支的提交、授权推送及远程内容核对；代码与文档分别提交，不将文档分支整体合并回代码分支。部署或检查必需的模板放入受保护的代码目录。只整理当前文件树，保留历史，不因本规则自行扩展推送授权。
- Markdown 文档禁止通过 HTTP(S) 读取，覆盖根目录、任意子目录及大小写变体，不为 README 或仓库执行约束文件保留例外。固定文档分支或独立工作目录（worktree）只隔离版本内容，不构成 Web 访问控制；维护者和 AI 应通过本地文件系统读取，不为查阅文档新增公开站点、目录映射、静态发布或下载入口。核对 Web 根目录、别名、符号链接及应用文件读取入口，避免旁边的文档工作目录被公开。访问规则变更后，仅对已授权环境验证根路径、子目录、编码路径和替代入口均无法取得 Markdown 原文，同时确认正常页面和静态资源仍可访问；本地规则检查不能代替真实 HTTP(S) 验证。

- 同源校验、人机验证、CORS 和管理员身份不能替代 Cookie 写请求的 CSRF 与对象授权。
- 按本地、配置或远程发行方等实际身份来源核验会话；一个模型的撤销修复不能代表其他身份都受保护。
- 企业职务只用于映射明确授权，不因程序员、PM 或组合职务自动获得超级管理员权限或跳过模块／对象检查；移除这类自动提权时同时清理配置入口，验证旧配置和已有企业会话也不能恢复绕过。分别验收企业角色的正常与拒绝路径，不能用程序账号代替 PM 等角色的验收；不得据此自动重写已有授权。
- 对已确认采用普通账号、受限企业认证、配置兜底账号的登录链，按该顺序验证且成功即停止；企业账号范围在网络请求前判定。只有本次符合该来源范围的输入才能显示企业认证消息，普通用户不显示企业错误或版本信息；配置兜底账号不输出专属提示，成功后清除先前错误。具体企业域名沿用项目集成规范，不把某一站点域名推广为通用值。
- 检查其他项目同样执行本站认证导航规则：默认登录／退出留在业务站点，认证调用在服务端完成，覆盖所有身份、旧入口及正常／异常跳转链。仅沿用项目已明确确认的跨站浏览器授权例外；不得为修复错误跳转自动开启远端入口。有效退出先使本站会话失效，远端故障不改变导航边界；分别验证本地退出和远端撤销，不把隐藏地址等同安全或全局退出。
- 退出操作默认使用 CSRF POST 一次点击完成，不为安全加固主动增加确认页；必须检查覆盖父布局的首页、自定义模板及旧退出入口。用户要求取消现有确认页或兼容直接退出地址时，按清单第六节“退出登录实施方法”提供可信顶层导航的自动 POST 桥接，GET 本身不清除身份；排除跨站、同站不同源、预取、iframe 及来源不明请求，安全返回固定登录页或安全页面。仅无脚本桥接保留提交按钮，旧 POST 别名不得丢失方法和令牌。
- 已确认的后台翻译放宽仅适用于对应已授权流程，保留正常批量、轮询和重试；不扩大为整个后台免防护。
- 依赖升级受阻时保留剩余风险和阻挡条件，不关闭扫描制造通过；新随机凭据也不能代表历史凭据已修复。
- 安全修复授权不自动包含生产破坏性测试、在用密钥轮换、提交、推送、发布或部署；这些操作按用户现有授权判断。可继续的本地检查、修复和验证应先完成。

## 补充通用清单

仅当任务包含规范维护，或已有对应维护授权时，提炼已确认且可复用的发现。优先完善已有条目及验收条件，不复制项目报告。保留清单前置规范、业务例外和兼容边界。

公共规范只写通用风险、适用条件、防护与验收，不写真实项目名称、地址、位置、账号、源码标识、实现代码、命令或扫描结果；实际证据留在使用方的受控报告。 用户明确要求保留的集成文件位置和使用约定，放入标明适用范围的独立参考文档，只使用相对路径和必要标识，不混入通用清单或真实部署凭据。

在规范所在仓库维护时，以仓库中的通用清单为维护源，通过仓库的同步脚本更新技能引用副本。独立分发的技能使用随包参考文件，不依赖原仓库或本机路径；仅修改独立副本时说明未同步维护源，不声称所有安装已更新。

## 报告

用简体中文报告，按清单分类列出问题、可达证据、修复、兼容影响与未关闭风险。明确区分“已执行并通过”“已执行但失败”“未执行”；分别说明本地测试、真实浏览器、外部服务和生产范围。推送、部署和数据库完成分别报告，不能相互推断。
