# G4 凭据安装中的会话处置与待完成登录隔离

日期：2026-10-21（Asia/Shanghai）。继续原 P1／G4，不增加阶段或预算。在准确批准的新密码／因子安装中加入原生会话与记住登录清空，并轮换会话 epoch。目标仍 disabled、unverified、无角色、要求 MFA，独立见证仍 quarantined；本组不是最终启用或完整 R1—R6 验收。

## 准确接线与固定效果

`StateCredentialInstallation::prepare()`／`resume()` 在原参数末尾追加可空的 `SessionRegistry $sessions`、`FileStore $sessionStore`，必须同时提供。计划检查原服务确实使用该同一物理存储对象和受保护边界、同一实际因子目录、同一时钟、准确 scope／subject，并由完整来源覆盖。相同目录／namespace 的另一个对象不能替换原实例。`SessionRegistry::credentialInstallationContext()` 只提供配置绑定，不读取记录、不授权、不重置权威；`ManagedSecondFactor::usesRegistry()` 只检查准确目录对象。

显式配置会话处置时生成安装清单格式 3，在既有字段后增加 `session`：准确物理引用、策略摘要、原始字节 SHA-256 和固定空记录。新 epoch 根据准确见证、安装 nonce 和账号确定，写入 `RegistryState` 格式 2 的空 `sessions`／`remember`，`expires=0`。不保存原会话／记住登录令牌或完整旧记录，不接受任意目标文件或用户指定的 epoch。

只读预览、独立当前恢复管理员、审阅后的真实强重新认证及一次性参数绑定批准继续沿用。批准同时绑定新凭据与会话效果的完整清单。安装先持久 pending，再依次持久新因子、空会话记录，随后原子比较并替换账号／目录三行 SQL，最后消费候选和确认结果。底层复用固定条带、受控暂存、CAS 和文件／目录持久化，不提供任意回调来覆盖会话。

会话写入前后、SQL 前后确认失败都保留原 pending。续办必须重新审阅和批准，只接受原会话字节摘要或原定空记录；epoch、账号版本及新因子版本不重新生成。错误实例／时钟／策略、伪造坐标／epoch、缺少新接线和第三种原始数据拒绝。已有格式 2 清单保留旧安装语义，未声称清空会话；向旧清单提供新会话选项或省略格式 3 所需服务均拒绝。旧读取器不支持新清单，不能混合部署。

## 旧授权证据的准确含义

本组先通过实际保护模式创建 TOTP 登录会话、记住登录令牌和未完成的 MFA 登录。随后对正式文件的私有副本使用原生 `SessionRegistry`、`RememberedLogin`、`AuthenticationFlow` 读取，身份提供方和因子绑定使用明确保持旧身份有效的测试桩。清空前旧令牌和待完成登录均成功；实际清空后的字节使会话与记住登录拒绝，未完成登录在因子验证前因 epoch 不同而拒绝。这样不能把“账号被停用”或“换了因子”当作物理清空的唯一证据。

该对照不是最终宿主登录验收，也没有用测试桩代替实际安装加密；新密码／TOTP 的生成、持有证明、封存和目标文件仍使用实际 SDK。记住登录的定位记录可以保留，但其授权条目已清空，旧令牌不能据此恢复会话。旧一次性管理批准依赖被清空的旧会话；本组未逐类完成其物理清理及其他用途证明处置。

源码核对发现旧版 `ApiKeys` 不绑定账号版本，不能用改密或清空会话证明其失效。账号绑定 `CredentialRegistry`、旧 `ApiKeys`、签名链接、重置证明、CSRF／nonce 及启用的其他身份／后台效果仍需按实际配置逐类接线、撤销或对账。最终恢复门禁尚未实现，不能选择旧格式安装然后绕过完整能力验收。
