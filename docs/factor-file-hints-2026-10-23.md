# 原生身份读取的因子文件位置复用

本批继续处理受保护原生凭据流程的本地耗时。修前独立复现显示，同一 `StateAccountPolicy` 连续读取同一账号对时，第二次仍完整捕获两遍来源，仅为再次发现相同因子文件名。SQLite样本两次各272条SQL；保留修前失败于[本地证据目录](factor-file-hints-evidence-2026-10-23/before.log)。

证据日志、修前源码及临时诊断脚本只保留在本地仓库，不随发行包交付。

## 运行时变化与安全边界

`StateAccountPolicy`在自身实例内最多记住16个账号的因子文件位置，账号索引为SHA-256。只保存已成功核验的位置字符串，不保存身份、角色、密码、目录行、因子字节、会话、来源摘要或授权结论。没有公开位置设置入口，不接受调用者捕获对象。

下一次读取仍执行完整组合来源捕获及其原有两次一致观察，核对独立见证的准确摘要，再认证当前SQL目录的根、完整数量、记录HMAC和绑定。只有当前目录推导出的实际文件名与本次选择的提示严格相等，才读取本次捕获的因子字节。位置失效时仍按原路径重新完整捕获并再次核对摘要。

因子封装MAC、站点／范围／代际上下文、因子ID与状态、账号状态／角色／密码、当前会话指纹／强度／期限，以及返回前时钟复核保持。双方都启用MFA时正好选择两个会话和两个因子文件，仍使用原有最多4个文件、每文件65536字节的限制。未扩大资源上限，不缓存权威结果；减少的是发现文件位置造成的额外完整捕获，每次捕获内部的两次一致观察及外层见证复核保持。

位置仅在整次身份及可选会话成功后更新；最多16项，移除最早未被再次成功使用的条目。私有调试输出仍脱敏，序列化仍被拒绝。原有277个公开类／接口签名保持，数据库、文件格式、默认期限、事务与隔离语义不变。

## 保留的失败

详细记录见`findings.json`，不覆盖、不重试到绿色：

1. PHP7.2 SQLite范围撤权检查提前结束，预期审计记录1条而实际0条，首次原因未解释。单次诊断后来得到预期`api_credentials.scope_denied`及1条记录，但不能覆盖首次失败。
2. PHP7.2 MySQL新专项及返回时钟场景，在预设环境阶段明确触发`Deadline`墙钟倒退拒绝。未替换产品时钟、未修改系统、未在失败见证上续办。
3. PHP7.2 MySQL返回拒绝场景，在预定返回检查前出现身份读取不可用；外层未知完成异常携带`api_credentials.identity_unavailable`，原始日志保留，未将其笼统归因为时钟。

首轮私有MySQL控制器在PHP7.2组合结束后退出；随后只执行原先未执行的PHP7.3—8.5，没有重跑PHP7.2来改写结果。PHP8.5早期测试曾误用已弃用的反射方法，已改为仅旧版本调用；这是测试代码修正，不是运行时保护放宽。
