此前原生 Bearer 入口先完成自身见证再返回证明，宿主无法把随后业务写入包含在同一次见证中。现增加 `CredentialRegistry::withAuthorization`：同一独立见证锁内完成原生只读准入、服务端 Intent 与对象／字段 RolePolicy、pending、实际凭证复查、SDK 自有 SQL 事务及完整来源/current。拒绝准确 PDO、未覆盖表、外层边界和已开启宿主事务。现有八个 API 入口签名保留，公开候选新增该方法及纯配置核对方法 `StateAccountPolicy::credentialSqlContext`；见证格式 2／3 不变。

## 责任和故障语义

业务表必须在首次可信初始化前加入完整 SQL 来源，全部写入者共用边界／围栏；SDK 不推断任意业务表或分析 PHP 回调。prepare 是宿主受信任只读加载函数，返回现有不可变 Intent；权限来自原生当前账号、实际范围和纯 RolePolicy，不接受调用者返回 true 代替授权。work 只通过准确 PDO 操作声明表，禁止 DDL、事务控制和外部效果；返回值只有完整入口成功返回才可使用。

新增 `examples/StateDocuments.php` 消费者展示服务端读取 owner／version、editor 与 title 字段授权、准备语句版本比较更新；不在请求中创建表。业务对象身份、参数和版本通过 Intent 指纹绑定回执，业务策略及表名也绑定。回执中的主体仍是实际凭证账号；业务对象由 Intent 绑定，不将账号字段冒充文档目标。

SQL 回滚不会被当作整个认证域已回滚：实际使用记录可能已经写入文件。真实 SQL 回滚、回调提前 COMMIT、提交前到期、提交后时钟观察到期及提交后最终预算失败均保留 pending，原始业务回调不重放。普通凭证／对象／字段／角色／版本拒绝保持无效果。新入口不加入任意宿主事务，不自动重试回调或未知 COMMIT。
