# 当前事务选择与原生归属探测去重

本批继续处理默认签发的本地成本。在普通因子目录与当前工作进程注册读取中，原调用者先探测是否已有SQL事务，再进入enlist时再次探测；修前SQLite及私有MySQL均观测到两次。MySQL每次包含自动提交查询、创建及释放探测保存点。修前计数、六份源码备份及对应上一批摘要核对保存在[本地证据目录](sql-context-evidence-2026-10-23/)。

## 实现与保护边界

- 内部SqlTransaction新增inContext，在确认入口上下文后选择加入宿主事务或执行原有自有事务流程。显式enlist仍要求已有宿主事务，不会自动开始一个新事务。
- 未注册连接没有SDK入口守卫，可合并为一次原生引擎探测。受保护账号连接只有在SqlStateAccess核对守卫与实际StateBoundary提供的原生守卫是同一个对象后，才获得相同优化。
- 原生守卫的代码仅检查StateExecutionContext的进入状态与PID／Fiber所有者，不调用宿主回调。登记只保留一个代码纯度标记，不保留额外边界对象，不缓存授权结果；每次仍调用原有守卫。错误守卫及错误PDO不能借用原生边界登记。
- 自定义或未证明的注册守卫仍保留原来的选择与再次探测顺序。守卫在入口结束宿主事务时会拒绝，不会转为自有事务执行；原生纯度标记也不能让未进入效果上下文的调用通过。
- 自动提交关闭、探测不确定、忙碌／失败单元和只读观察单元均拒绝。旧PDO的SQL开始事务仍通过真实引擎识别，不依赖不准确的inTransaction标志。
- 宿主结果保持临时性，由宿主决定最终提交／回滚；固定回滚边界、独立事务见证、回调后所有权验证、连接超时恢复及清理不确定时的拒绝保持。回调失败不重新选择路径、不重复执行。
- 自有路径使用已经开始的同一Deadline，选择期间的时间不会被重新计时。因子目录与当前工作进程注册的HMAC、完整账本、账号指纹和全部权限阶段保持。

本批WorkerAuthority变更只用于普通操作读取当前注册，不实现或测试跨安全代际工作进程交接。公开277类／接口签名、数据格式、规范DDL、权限与默认预算保持；新增方法属于已有内部SQL类。

## 候选失败与修正

初始候选错误地将所有入口守卫都视为纯断言。新故障样例中，守卫结束宿主事务后，候选又选择自有事务，错误执行并提交了一条测试意图。该问题属于本批中间候选，不是原有双探测实现的既有行为。失败日志及六份候选源码保存在candidate-guard-loss.log与candidate-before-purity/。

修正为只有无守卫或经实际原生边界核对身份的守卫才能合并。guard-loss-fixed.log记录配置拒绝、业务调用0次、框架未提交、意图0条；最终专项同时验证自定义守卫仍探测两次，原生登记不等于授权。失败证据未覆盖，未通过删除测试或放宽事务保护取得绿色。
