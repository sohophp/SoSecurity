# G4 新凭据固定安装与原效果续办

日期：2026-10-21（Asia/Shanghai）。属于原 P1／G4，不增加阶段或预算。新增 `StateCredentialInstallation`、`StateCredentialInstallReview` 和内部清单校验器，将前组独立准备的新凭据实际安装到受保护目标。账号仍 disabled、unverified、无角色并要求 MFA，见证仍 quarantined；不采用当前来源作为新可信基线，不代表 G4／F01／R1—R6 完成。

## 固定操作和权限

计划仅接受准确对象图、完整 SQL／文件来源、实际受管 TOTP 及原先经审计完成的账号禁用清单。正常安装要求准确候选仍有效且已真实证明，绑定完整隔离根和来源；新因子必须使用此前不存在的物理坐标。新密码哈希、新 credential_version 和因子目录指针是固定值，重试不能重新生成或恢复旧权限。

`credentialInstallationReview()` 签发最多 120 秒、绑定完整计划的审阅；实际效果需要独立当前恢复管理员，在审阅之后完成真实密码／TOTP 重新认证，并消费用途 `state.credentials.install` 的一次性批准。无权限请求在访问独立候选状态前拒绝；选中候选仍不等于原账号所有者身份或安装许可。

`installCredentials()` 先持久化 pending 及原效果清单，再通过既有锁条带、临时写入和持久化接口写入新因子，随后在同一真实 SQL 事务比较并替换账号、因子目录记录及账本根三行。全部表在写入前检查触发器、外键和元数据可见性。批准、来源、执行进程／Fiber 和截止时间在效果边界复查；候选消费受准确原生安装上下文限制。确认完成后仍保留隔离和原可信摘要。

## 未知结果与格式

文件确认丢失、SQL 后最终预算拒绝或管理员被撤权等情况保留 pending。`StateCredentialInstallation::resume()` 仅重建已持久化的原效果；`credentialResolutionReview()` 和新的 `state.credentials.resolve` 强批准才能继续。文件只能是未写或原定完整值；三行 SQL 只能整体为 before 或整体为 after。混合行、第三种数据、旧批准及借续办对象开启新安装均拒绝。原候选已消费或到期不使未知结果无法续办，也不能更改其原定版本。

安装清单格式 2 使用严格 Base64 表达二进制行字节，以控制隔离根固定 16 KiB 上限。密码哈希、selector 及完整 before／after 行放在绑定目标与安装 nonce 的认证密文中；公开清单只保留摘要、原因子坐标及必要选择信息。最大完成回执和后续续办字段在消费批准之前预检。

安装审计记录可能大于 HMAC 接口的 16 KiB 原文限制。新恢复审计记录格式 2 对完整规范记录的 SHA-256 使用独立域 HMAC；读取器同时验证原格式 1。审计记录仍限 64 KiB，根仍限 4／16 KiB，总容量仍为 256 条（含孤立记录），没有扩大底层限制或自动采用孤立记录。旧读取器不支持新记录／安装回执，混合版本部署不受支持。
