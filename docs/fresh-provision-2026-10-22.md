# 全新部署的保护模式测试入口

用户允许继续补齐非暂缓功能。当前 goal 为 active；不因旧计划含暂缓范围就认定所有保护模式工作阻塞。本批新增两份隔离测试及独立 MySQL 检查入口，没有修改运行时实现或公开 API，也不将测试基础设施记为新的产品修复。

## 已验证的路径

`tests/state-boundary/fresh-provision.php` 从自行创建的空 SQLite、空栅栏目录、独立见证目录开始，声明完整来源后初始化见证，在边界内首次创建栅栏。边界外初始化和工作均被拒绝；边界内写入后的摘要与见证一致，共14断言。

`tests/state-boundary/fresh-authentication.php` 使用实际 SQL 账号示例、账本、文件来源、语义见证及 Security 工厂。起始账号、账本、因子文件和栅栏均为空；显式初始化首次工作进程根及新账号空因子槽，再建立目录记录。覆盖无状态副作用的工厂构建、请求拒绝时不读取身份、新账号密码登录、会话验证、撤销和见证一致性，共17断言。测试内信任回调仅服务于合成宿主，不代表真实宿主权限验收。

首次工作进程根通过 `FactorRecovery::initialize()` 的公开初始化路径建立，其他恢复回调全部抛错；没有调用恢复确认、最终账号恢复启用、跨代际交接或未知回执续办。新账号激活是 `createPending` 后的首次激活，不能用于重新启用旧账号。显式空因子初始化只针对本测试刚创建的账号，不作为登录失败后的自动备用方案。

旧 `EntryEnvironment` 仍通过 `entryPromote` 调用 `rotateWorkers`，本批没有运行它，也没有改写它来避开原限制。此次独立入口使后续非暂缓入口测试不必依赖该旧测试准备过程。

## 实际结果

- 已执行并通过：SQLite 九版 PHP 7.2、7.3、7.4、8.0—8.5，共18次初轮测试。增加 MySQL 连接分支后，对实际最终认证测试重新执行九版，全部通过；未无依据重复未改动的首次栅栏测试。
- 已执行并通过：`tests/mysql_check.py --fresh-authentication`，PHP7.2原生单调时钟运行时及PHP8.5，各17断言。控制器创建自己的无TCP MySQL，测试仅删除本次成功创建的表，控制器只清理自己的进程和临时目录。
- 已执行并通过：PHP7.2／8.5公开API检查，268类／接口，未重写候选契约。
- 已执行但失败并保留：最初最小测试误读见证字段、临时目录清理遗漏；已修正为实际 `digest` 字段和子目录优先清理。认证初轮缺少显式空因子槽，因子状态读取被拒绝，见证进入未知完成状态。没有对该失败状态续办；下一次使用全新测试资源并补齐首次初始化顺序后通过。
- 未执行：全项目门禁、旧代际交接、未知回执续办、最终账号恢复、完整F01、外部宿主验收。本批没有发行行为或运行时代码变化，因此未重复既有归档／全新消费者测试。

证据位于 [fresh-provision-evidence-2026-10-22](fresh-provision-evidence-2026-10-22/)；`matrix.json` 为初轮命令和结果，`final.json` 为认证测试最终九版、两端API结果及源码摘要，`mysql.log` 为私有MySQL结果；所有初轮失败日志仍保留。新测试接入 `bin/check.sh` 的 SQLite／sodium 分支；本次只运行定向入口，未调用含暂缓套件的完整脚本。
