## 已接入的实际服务图

`authentication.state_boundary` 显式声明四项：

| 字段 | 含义 |
| --- | --- |
| `authority` | 已构造的准确 `StateBoundary` 服务编号 |
| `store` | 已声明覆盖的原始 `FileStore` 服务编号，复用实际对象及其 namespace |
| `scope` | 服务端固定作用域，与因子目录一致 |
| `epoch` | 外部可信代际，与见证及因子工作进程一致 |

该配置要求密码身份提供器、`StateRequestGuard`、受管理因子目录、绑定同一边界对象的工作进程栅栏。当前纯权限视图支持会话与因子共用一个完整文件域；不能因字段名称匹配就接受另一份边界、未覆盖目录或其他物理后端。构造不初始化数据库、见证或栅栏，不发送通知，也不自动修复缺失状态。

在显式保护模式中，`Security` 缓存并复用准确的会话、认证、持久登录、授权服务、目录和因子适配器；普通未保护工厂保留既有构造行为。因子工厂把准确原始 FileStore 登记到相同物理访问边界，并核对时钟及单文件域。持久登录保留设备风险守卫。

`Security::stateAccountPolicy()` 从这份实际缓存图构造纯 `StateAccountPolicy`：调用者提供准确见证／组合／SQL／文件来源、来源名称、账号表及字段映射，SDK 使用工厂实际会话、受管理因子、密钥、作用域和策略。它不依赖调用者重新猜测内部对象，不读取数据库或消费证明。

新增 `LocalEpochFence::boundToStateBoundary()` 与 `TotpFactors::bindStateBoundary()` 仅用于准确对象核对和显式原始存储登记。251 个既有公开类型及其签名全部保留，三项新增方法的准确接口见[核对记录](state-factory-evidence-2026-10-21/api-compatibility.json)。配置结果另增加可空的 `authentication.state_boundary` 字段，不改变凭据、状态封存或数据库格式。

## 诊断与尚未接入项

诊断只检查依赖类型、作用域、覆盖关系和准确栅栏绑定，不执行回调或读取见证当前状态。有效依赖标为 `manual`，缺失／不匹配标为 `fail`；持久化、全部写入者、独立备份和最终恢复仍明确为待部署验收，不生成虚假的通过状态。

认证文件与独立公共预算使用不同存储。已覆盖或已被其他权威登记的文件目录不能作为独立预算／请求存储，避免边界外写入破坏检查点；其他预算后端的物理独立性仍须按完整计划验证，不能把“未被 FileStore 来源覆盖”当作部署独立性的证明。

保护模式的单次授权需要独立的无参数请求守卫，不能把要求 action／scope 参数的 `StateRequests` 直接传入。宿主须在进入外层边界前完成公开请求检查，当前账号权限使用纯策略和准确动作／目标批准。

工厂中的注册、地址变更和两类恢复尚未接入整个业务入口，当前明确拒绝落入旧的无边界生命周期实现。旧密码重设、其他 API 凭据／重放／链接及租约工厂也不能从该保护模式静默落入独立的普通授权存储。它们仍是完整 G1 的未完成工作，未删除原需求；普通未保护组件仍保留。通用业务模块、宿主写入者及外部投递也不因这组认证接线而自动受保护。
