# G4 新凭据的持久准备与持有证明

日期：2026-10-21（Asia/Shanghai）。继续原 P1／G4，不新增阶段或预算。本组实现新密码和新 TOTP 的持久准备、真实持有证明及准确候选描述。**尚未安装到目标账号或因子目录，也未重新启用业务**；完整恢复和 R1—R6 仍开放。

## 独立持久准备

新增 `StateRecoveryCredentials` 和敏感结果 `StateCredentialEnrollment`。准备服务须使用独立 `StateBoundary` 覆盖的真实 `FileStore`、目标实际受管理的 `TotpFactors`、原 HMAC 密钥对象及具体 `PasswordHasher`。准备目录与目标 SQL／认证文件／独立见证／恢复审计必须物理分离；可以复用已声明完整来源的独立审批域中的单独 namespace。构造不会初始化根或放宽保护，原始存储也不能绕过既有边界直接操作。

目标必须是格式 3 的 quarantined，当前没有未决处置，且恢复审计覆盖本次关闭的起点。`LocalStateWitness::credentialSelection()` 核对签名历史中准确账号清单确已完成固定禁用，再确认所选行仍逐字节匹配其封存 after 摘要。候选绑定完整根摘要、来源观察摘要、隔离代际、原禁用计划／操作、scope／subject 及行摘要。伪造清单、错账号或变更后的行不能进入准备；源状态或根变化也不能把旧候选作为当前证明。

`prepare()` 生成 32 随机字节对应的 64 位十六进制新密码，通过配置的标准 hasher 保存哈希；不保存密码正文。TOTP 使用实际目标服务的加密器、发行方和算法配置，创建全新的随机因子 ID 和独立物理坐标，其秘密以绑定该坐标／ID 的密文保存。准备过程不访问或修改目标物理因子，也不复用旧密码、旧种子或恢复码。敏感结果只提供准备 selector、首次显示的新密码和 `Enrollment`；普通调试／导出不包含这些材料，序列化拒绝。

准备记录写入独立见证保护的文件，而不是依赖内存对象。记录还有独立签名域 `SoSecurity.Account.StateRecoveryCredentials.State.1`，保存 selector 的单向摘要、密码哈希、加密因子候选和准确绑定。销毁并重新创建服务后可以继续处理；本组通过真实文件重载验证，实际 PHP HTTP 请求接线和浏览器验收仍未执行，不能由对象重建测试替代。

## 真实证明与固定资源限制

每个目标权威最多四份活跃候选，固定存活 300 秒，每份最多五次确认尝试。候选集合有固定结构及 60,000 字节编码上限，底层 FileStore 仍保留原有 64 KiB 限制。到期清理只影响独立准备集合；容量满返回明确拒绝，独立域保持 current，目标仍保持 quarantined。取消、安装后的候选消费及完整维护接线尚未实现，不能据此关闭全部 R2.7 容量／维护要求。

`confirm()` 同时核验新密码和实际 TOTP 代码，使用真实认证加密和 TOTP 算法；没有布尔“已证明”参数，也不允许恢复码替代新因子的持有证明。加密、随机数、时钟调用和昂贵密码验证均在可重试原子回调之外；回调只校验固定数据、比较旧记录并提交确定的新状态。成功保存已确认因子及已消费时间步；重复确认拒绝，重新创建服务不能重置失败次数。

无效 selector 和超大／错误类型的证明输入在密码验证前拒绝；未知 selector 不消耗其他候选的尝试。独立准备文件回放为旧字节时，独立见证在处理前检测陈旧状态，不能重置尝试次数或已确认状态。目标根、SQL、文件和原可信摘要保持不变。

`describe()` 只返回当前仍有效的非秘密候选描述及材料摘要，不返回密码哈希或因子密文。候选生成与新因子持有证明**不证明申请人是原账号所有者，也不授予安装／登录权限**。宿主必须保护敏感材料交付和请求预算；之后仍需独立当前恢复管理员的强认证、审阅后重新认证、参数绑定的一次性安装批准，以及固定原生写入／未知结果处理。本组没有以准备成功代替这些步骤。
