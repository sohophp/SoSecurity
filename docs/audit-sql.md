# 独立 SQL 审计日志

`Audit\SqlSink` 是可选的真实 SQL 日志接收器，直接接到 `AuditLogger`、`BudgetedSink` 或 `MetricsSink` 的下游。它把固定字段记录提交到独立数据库，返回成功表示本次数据库 COMMIT 已确认；指标、近期索引和 PSR-3 回调成功本身不提供这一证明。

## 部署与接入

使用单独的审计数据库和 PDO，不能复用正处于业务事务中的连接。SQLite 使用持久文件、开启日志及 FULL／EXTRA 同步；MySQL 使用 InnoDB、异常模式、原生预处理和 `innodb_flush_log_at_trx_commit=1`。组件验证这些条件，不修改部署的耐久性设置。SQLite 不能使用 `:memory:`。是否能抵御实际掉电仍取决于数据库、磁盘和虚拟化环境，本地进程测试不证明真实断电恢复。

管理员先在可信部署阶段安装 [SQLite](../resources/sql/audit-sqlite.sql) 或 [MySQL](../resources/sql/audit-mysql.sql) 表结构，再显式初始化站点。请求写日志不会创建表或初始化缺失状态，不能从请求参数选择连接、站点、容量或表结构。实际应用需限制日志数据库访问、备份和数据库维护权限。

```php
$sink = new SoSecurity\Audit\SqlSink(
    $independentAuditPdo, 'example-site', 10000, 604800, null, 1000,
    $authorizeCurrentOperator, // 清理权限；省略则拒绝显式维护
    $authorizeAuditReader     // 独立读取权限；不能用清理权限代替
);
$sink->initialize(); // 仅可信 CLI／部署引导执行一次；普通请求不执行
$logger = new SoSecurity\Audit\AuditLogger($sink, $independentPseudonymKey);
$logger->record('login.failed', 'tenant', $subject, ['allowed' => false]);
```

[原生接入工厂](../examples/audit-sql.php)只返回可信构造闭包，加载本身不连接数据库或初始化表。可以把返回的 logger 注入现有审计接线；不会自动替换整个项目的日志接收器。连接、站点和至少32字节的独立假名化密钥由宿主配置注入，不放在公开请求或源码中。

## 容量、保留与错误

- 容量为每个受控站点 1—100000 条，默认10000；保留期为1—31536000秒，默认86400。多个进程在同一站点根锁下分配递增序号并核对容量；MySQL 计数与清理使用当前锁定读取，不能依赖建立于锁前的旧快照。
- 每条日志只接受 `time/event/scope/subject/context`，上下文只允许 `allowed/retry_after/status`；主体必须为空或64位十六进制假名。正文最多4096字节，解析、校验和编码发生在 SQL 效果前。事件正文、原始主体和秘密不会由本组件自动追加。
- 接收时间和到期时间取服务端可信时钟，不由事件 `time` 决定。每次写入最多清理128条到期记录；没有空位时拒绝 `audit.sql_capacity`，不覆盖未过期日志。清理也不会重置序号。多站点总容量、索引／数据库空间和备份保留由部署方管理。
- 可在运维任务调用 `$sink->prune(128)`，单批最多1000条；默认拒绝。授权在读取前及提交前复核，撤销或异常会回滚本批清理。写入时按可信保留策略自动过期清理不依赖运维授权；两者均不物理擦除数据库空闲页或备份。
- 初始化后改变容量或保留配置会拒绝 `audit.sql_policy`，不能用重新 initialize 隐式重置旧记录。需单独安排受控迁移或新站点标识，并保留旧站点的保留／维护安排。
- 同一连接已有业务事务会被拒绝，调用方原事务保持归属；应把审计数据与业务文件／表的锁关系分开设计。日志在自己的事务中提交，业务随后回滚也不会撤销审计尝试记录。它不提供业务与日志原子提交，也不证明事件所描述的业务已经成功。
- SQL 失败向外抛出，提交结果未知不自动重放。未知结果后需要检查记录／重建连接并由宿主决定是否补记；重新创建对象也不能证明此前没有提交。审计没有事件幂等键，手工补记可能重复，不能把它作为幂等告警接收器。

## 保留期内的有界历史查询

`records($afterSequence=0, $limit=100)`在当前站点内按序号升序返回最多100条未过期日志，每条包含`sequence/recorded_at/expires_at/record`。继续分页时传入上一页最后一个序号；空页只表示本次查询没有后续未过期记录，并非可验证的永久空档案。它可查询超过近期事件索引一天上限、仍在 SQL 保留期内的记录。页游标只定位，不授予访问权。

读取使用构造器最后一个独立回调`authorizeRead`，默认拒绝；它与清理回调互不替代。每次读取在访问数据库前、返回结果前都复核授权；回调异常或撤销不返回数据。当前实现使用受控服务连接及站点锁，不是数据库只读账号适配器；宿主须把回调绑定实际当前操作者及站点，不从请求中接受“已授权”布尔值。日志记录本身只读，读取不隐式清除过期行。

SQL侧先核验正文的实际 BLOB 类型和字节长度，再投影最多4096字节供解码；异常类型、8MiB字段、损坏元数据或不匹配固定协议均拒绝，不能先完整载入再判断上限。记录没有防数据库管理员篡改的签名，格式校验不等于完整性认证。宿主应对查询再加请求预算，并避免把跨页期间的并发写入／到期清理称为一致性快照。

此存储不是不可篡改档案、备份新鲜度权威、全站跨站点查询服务或账号恢复凭据。它不创建公开HTTP端点；宿主必须实施当前操作者授权、请求保护、站点边界和输出限制。保护日志数据库不受业务账号读写、长期归档、外部告警接收与生产部署仍需实际环境验收。

## 本地验收范围

[本轮验证记录](sql-audit-integration-2026-10-22.md)记录九版 SQLite 专项、PHP7.2／8.5 私有无 TCP MySQL、真实并发写入、提交故障、原生工厂及从 ZIP 全新安装的消费者。既有告警组件组合检查使用真实 SQL 日志和本机持久去重收件表，模拟接受后租约确认未知，再次投递仍只有一份收件记录；这是至少一次发送＋接收方去重，不是全链路 exactly-once。外部目标及暂缓的账号恢复链路未执行。
