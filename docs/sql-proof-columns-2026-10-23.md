# SQL 权限证明与列结构读取合并（2026-10-23）

本批继续处理默认MySQL签发预算缺口。先测量策略指纹计算，再依据实际SQL对照合并查询；没有提高预算、缓存权限或减少结构保护。

## 决策依据

用临时复制的策略类，在PHP8.5默认首次签发中测量指纹方法体：Account\Policy调用192次，CredentialPolicy和RolePolicy各1次，总计约0.930475毫秒。计时区域不包括观察计数写入和方法分派；该运行带测量开销并在首次签发超时，不能当作正常验收。成本不足以支持新增指纹缓存，因此未修改这些策略类。原源码摘要和结果保留于 [策略测量](issue-policy-profile-evidence-2026-10-23/analysis.json)，没有续办未知结果。

原SqlSchema先查询权限，再单独读取列结构。对两种SQL组合进行三轮交替对照，每轮40次、2／13／64列，所有权限字段和列元数据完全一致，40080项断言通过；每40次校验的相关SQL由80条降为40条。三个宽度的累计耗时分别下降约11.09%、16.76%、3.62%。计时包括结果比对，尤其候选需要逐行提取和核对额外权限字段，故只代表此探针，不是端到端性能承诺。见 [原始测量](sql-proof-columns-evidence-2026-10-23/performance.json)。回放探针显式加载保留的基线类，避免后续工作树变化影响基线。

## 实际变更

权限和有界账号标识通过单行派生结果进入同一条列结构查询，仍在PHP严格校验身份格式及直接授权；全局权限的partial_revokes限制保持。列结果最多65行，身份字段仍限制288字节。原有引擎、字段、主键、索引、外键、触发器判断全部保留，包括原列查询中的触发器检查。不存在跨查询／调用的权限缓存。

测试中的保护查询数量由2改为1，表示同一条SQL同时携带权限和结构检查，不是删除保护断言。DDL、格式、公开API277及默认预算不变，SQLite分支不变。精确补丁见 [runtime.patch](sql-proof-columns-evidence-2026-10-23/runtime.patch)。

候选实现曾将权限元数据数组传入私有校验函数，显式保留异常参数时可从异常栈取到账号标识。privacy-before.log 保留失败，最终将校验放回读取函数内，使元数据仅为局部变量。新增异常栈隐私断言没有删除原权限拒绝断言；这是本批候选中发现并修正的问题，不冒充旧版本已确认缺陷。
