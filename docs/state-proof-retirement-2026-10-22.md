# 恢复中的范围证明代际退役

日期：2026-10-22。继续既定 P1／G4、R3.4／R3.5 的旧授权处置；31 项／80 个有效工作小时上限不变。没有以某几个已知令牌的清空代替整个已启用范围的证明失效，也不以仍隔离的结果关闭完整恢复。

## 代际与实际存储

新增内部 ProofEpochStore，将明确退役后的新账本值放入 `proof_epoch / context / epoch / value` 封装；内部 Operation／Link 状态格式仍为原 v1，外部 oc1／og1、sl1 和重置令牌格式保持。没有退役标记时按既有原始值读取和签发，不隐式初始化标记。标记是原 FileStore 命名空间中的永久记录，必须与实际证明账本一起纳入完整来源；它不是替代独立见证的新信任根。

每次证明事务在回调外读取标记、在纯回调中处理捕获的代际，提交后再读取标记。期间变化或效果后的读取失败不返回结果，报告 completion_unknown，禁止自动重放；读取失败不降级为空。回调没有标记 I/O、随机值或隐藏外部副作用。底层每个证明账本事务增加两次 AtomicStore 标记读取；不能把跨请求缓存用于绕过退役检查。

| 组件 | 明确批准的失效范围 | 保持的内容 |
| --- | --- | --- |
| Grants | 指定原 FileStore 命名空间与 scope 的全部账号、待确认操作和已授权证明 | 新代际仍要求真实会话、准备后的重新认证、准确参数及一次性消费；原手工／原生调用契约保留 |
| Links | 指定命名空间、站点与资源 scope 的所有用途、资源、路径／版本及一次性／可重复链接 | 其他 scope 和命名空间不失效；新链接继续使用既有固定来源、目标／方法绑定与持久账本 |
| ResetTokens | 指定原 FileStore 命名空间的全部账号版本绑定，components.scope 必须显式为空串 | 不修改密码或普通 CSRF；其他 FileStore 命名空间不受影响 |

password-reset 的处理位于 CsrfTokens 对应用途，原始 CsrfTokens 入口也识别标记；不是只在 ResetTokens 外面加一个可绕过的包装。其他 CSRF 用途保持原路径。

退役后旧原始账本和旧封装代际不能验证；新证明只写入当前封装。损坏标记、非永久标记及新封装缺失其标记时拒绝。删除标记不是迁移：裸存储仍有“无标记支持旧格式”的兼容路径，完整备份回滚拒绝依赖独立见证、全部来源覆盖及旧写入者围栏，不能声称仅凭这个标记已经解决 F01。

Nonce 的已消费记录不能清空。本组没有改变 NonceStore、HMAC 验证器、收件箱或签名密钥；旧签名凭据和未见过的请求仍须按完整恢复清单另行处置。

## 准确审批与固定效果

StateProofRetirement.prepare／resume 只接受实际 Grants、Links、ResetTokens，准确的同一 FileStore／Clock、覆盖它的 FileStateSnapshot 和完整 CompositeStateSnapshot。每份计划一至四个不同标记；不同底层存储分别形成明确计划，不猜测 NamespacedStore 的私有转换或跳过不同 Clock。ResetTokens 的空 scope 明确代表整个该命名空间，不能把它写成单一账号的处置。

清单格式 1 固定组件／scope／原生策略上下文、标记键和实际文件引用、原字节摘要及新永久字节；代际绑定独立见证、后继代际、计划 nonce 和实际组件上下文。FileStateSnapshot.canStoreFiles 在消费批准前核对合计新增文件容量，不逐个假设都还有最后一个空位。重复文件、其他类型（含 nonce）、错命名空间／Clock／坐标和变动后的字节拒绝。

StateProofReview 使用独立 `state.proofs.retire / state.proofs.resolve` 用途，不能借用 API 密钥或凭据安装的批准。StateRetirementControl 仍使用独立当前账号／MFA／会话、近期强度、准备后的真实重新认证和准确一次性 Grants。LocalStateWitness 持久化 pending 后才逐个写入固定标记；每次写入／持久化及最终提交均复查当前批准、权限和截止时间。没有任意 SQL、文件负载或业务回调。

部分效果或确认丢失保留 pending／quarantined。新读取器只能重建同一原清单，接受每个文件的准确 before 或 after；第三种字节、旧批准、不同用途和借 resume 启动新计划均拒绝。新的 resolve 审批才可继续，不重新生成代际。恢复审计保存具体清单，16 KiB 根／64 KiB 审计及既有审计容量保持。完成后仍隔离，不修改账号字段或自动启用业务。

所有读取器必须协调升级并停止／围栏旧写入者。旧代码不识别新标记，不能混用两份 SDK 后声称恢复安全。本组新增 2 个公开恢复类型、2 个内部类型；既有公开参数顺序及令牌格式不变，新增只读原生效果描述方法、明确恢复入口和合计容量方法。

## 有限验证

[冻结执行清单](state-proof-retirement-evidence-2026-10-22/execution.json)固定八条命令：四个 PHP7.2／8.5 与 SQLite／自建 MySQL 组合，每组执行三个恢复专项、五个原生操作授权专项、既有 API 退役兼容以及三个真实 SIGKILL 点；SQLite 另执行低层代际、普通操作／SQLite 业务／链接／重置五个 8 MiB 专项。最后核对两端公开契约、PHP7.2 目标静态分析和 PHP7.2 语法。保护恢复图使用 16 MiB，没有启动九版本最终整轮。

故障点固定为首标记重命名前、第二标记重命名后、全部三标记重命名后。控制器等待真实停点后 SIGKILL，要求旧进程确实终止；新进程重新打开 PDO／服务图，以新强审批完成准确零／部分／全部效果。不能把确定性持久化失败当成真实进程死亡。

原生证明探针在复制的真实字节上，刻意保持旧身份、因子绑定和会话有效，验证失效来自证明代际；旧操作授权／待确认、多资源链接、多个重置绑定在退役前有效、退役后拒绝，新证明仍能一次性使用。保留其他 scope 的链接、其他命名空间的重置、普通 CSRF 和已消费 nonce。目标旧账本字节保持，只增加明确的代际标记，避免用旧会话失效或账号停用替代这一结论。

原生 Grants 另在测试用 current 权威中建立代际数据预设，使用真实密码／TOTP 验证新代际准入、旧授权在 pending 前拒绝、准确意图回执和一次 SQL 更新。这是读取路径检查，不是恢复启用接口或 SDK 完整恢复的验收。
