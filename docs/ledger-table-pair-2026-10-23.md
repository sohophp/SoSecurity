# 账号账本双表结构的同次有界读取

继续处理真实默认签发中的数据库往返，未修改默认预算或移除任何注册账本检查点。修前每次账号账本结构校验分别读取根表及记录表，新的初始化元数据预算断言复现2次而非1次，失败证据在[本地目录](ledger-table-pair-evidence-2026-10-23/before-query-budget.log)。

内部SqlSchema新增至多两个固定表契约的组合读取，Ledger使用它校验根表／记录表。每张表仍先取得实际表的元数据锁，再在一条SQL中分别取得有界列、首组索引、独立账号／权限／触发器／外键及唯一约束证明；分支使用独立参数和表标记，按表分别拒绝异常。后续索引组仍各自读取。SQLite按原顺序调用原单表校验。

每表列分支仍最多读取65行并拒绝超过64列，首组最多4个索引各65行，每个索引最多接受64行；两表初批最多650行。结果仅在当前校验调用中存在，不跨回调保留权限、结构或业务行。观察到的数据库账号元数据保留在局部变量，不作为校验辅助函数参数进入错误栈。

SqlTransaction的共享期限、见证、宿主事务所有权及原有结构证书失效边界保持；回调、写入、事务结束及提交后仍复核。HMAC、完整账本历史、来源、因子、会话与全部权限阶段没有减少。公开API277、DDL、存储格式和配置默认值保持。因为先取得两张真实表的元数据锁，当配置同时存在多处异常时，拒绝先后及具体错误原因可能变化；所有异常仍在业务效果前拒绝。

首轮新增测试只捕获SecurityException，配置拒绝实际仍继承InvalidArgumentException；产品正确拒绝异常列，测试因漏捕获而失败。修正为同时捕获原有ConfigurationException，保留原断言、初轮日志及测试源码。初次修后专项：SQLite162项，MySQL208项及账号格式／错误栈隐私20项通过；不是最终整仓验收。

结构复用测试现在记录本次成功创建的两张账号表，结束时只清理这些自建表，避免同一自建实例内后续测试的同名表失败。既有数据保护与测试断言保持。
