# Webhook 只读候选分页完成检查（2026-10-25）

本批在2026-10-24启动、跨日完成，原始证据目录保留原名。仅修改 `SqlProcessor::pendingRows()`：共享的普通只读候选扫描显式检查关闭结果、限制SQL返回字节、拒绝页内重复／不递增游标，以及不完整或矛盾的元数据。没有修改领取、执行、重试、未知回执续办、跨安全代际交接或最终恢复启用；测试均使用独立普通模式PDO和自建记录。

## 实际问题与修复

PHP7.2／8.5分别复现四类问题，修前八个样例均保留：

- 扫描未显式关闭游标，关闭故障没有触发，仍返回候选。
- 已有处理状态字段12MiB时，8MiB内存上限下退出255，不能返回受控错误。
- 两条收件记录使用相同回执ID时，返回页内重复候选。
- SQLite字节相同BLOB回执键按存储类型排在文本游标之后，返回未越过传入游标的候选。

修后八例均受控拒绝，超大字段峰值2MiB；关闭失败传播为 `webhook.processing_cleanup` 并禁止复用该实例，下一次调用在权限回调前拒绝。使用已有内部消费方法，读取错误不泄露驱动私有消息。

SQL投影对每行固定四字段限制：回执ID32、状态9、两个整数各19字节；最多50行，返回字段内容最多3950字节。WHERE、JOIN、ORDER BY和LIMIT保持原查询结构，不新增全表排序或索引迁移。缺失LEFT JOIN处理记录的NULL状态仍合法，现有超限状态返回非NULL拒绝哨兵，不能误当成缺失记录。非递增游标及页内重复ID拒绝整页，不静默丢弃候选；正常跳过未来到期项仍推进游标。扫描只校验本页排序和唯一性，不把惰性候选列表当作全库完整性审计或处理授权。
