# Webhook SQL锁策略与超时隐私（2026-10-24）

本批修复 `SqlInbox` 首次接收和 `SqlProcessor` 自有事务的元数据锁等待缺口。私有MySQL8.0.46中，1000ms预算下首次接收／只读待处理查询分别等待约4.013／4.003秒，均未写入收件箱。初轮修复的同一复现降至约1.016／1.004秒并失败退出事务；最终源码另由下述九版真实加锁场景覆盖。MySQL配置按每次加锁计时、最小1秒，不是严格整条语句截止时间，参见[官方说明](https://dev.mysql.com/doc/refman/8.0/en/server-system-variables.html#sysvar_lock_wait_timeout)。

两入口现在先完整读取并显式关闭锁策略游标，再按原策略与剩余预算收紧元数据锁等待，退出时恢复配置。共享的内部 `InboxSchema::lockTimeout` 只接受三个固定SQL查询，校验行列数与非负整数；执行、获取、超时均不能跳过游标清理，关闭或恢复不确定则使服务失效。SQLite原先把`busy_timeout=0`放宽为1ms，已独立复现并改为保持0。
