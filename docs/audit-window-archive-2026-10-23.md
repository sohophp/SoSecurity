# 闭合审计窗口的检查点与补入队

日期：2026-10-23。显式闭合窗口检查点及补入队的本地子关口已完成。当前 goal 仍为 active，默认签发缺口、完整 R4.6 及稳定版验收尚未完成。

原计划 R4.6 要求保留期外恢复。现有 SQL 日志没有原指标策略和窗口，指标又先计尝试再调用下游日志；日志行数不能准确还原原窗口计数。源码依据见[缺口核对](audit-window-recovery-gap-2026-10-23.md)，修前入口不存在的证据见[记录](audit-window-archive-evidence-2026-10-23/before-feature.log)。

本批只增加显式闭合窗口检查点：源窗口仍在 Metrics 保留范围时保存有界副本，后续按准确窗口起点恢复原告警入队。未保存、已丢失或已过期的数据不重建；不领取消息、不投递、不处理未知回执，也不恢复账号。

## 产品边界

- `MetricsSink::archiveProfile(Clock)` 提供固定策略摘要、阈值及容量，要求与源使用同一时钟（两个 `SystemClock` 等价）。现有指标 v1/v2 格式、构造参数及默认单窗口行为保持。
- 可选 `Audit\WindowArchive` 使用共享 `AtomicStore` 保存最多64个已闭合窗口，固定根最多32768字节，不支持 `MemoryStore`／`SessionStore`，不新增 SQL 表或隐式迁移。使用已有 `MySqlStore` 时仍须按原要求先显式安装。
- `checkpointClosedWindows()` 只读取源中仍保留的历史窗口，排除当前窗口；返回本次确认保存的窗口起点。重复保存必须内容一致；有效容量满时拒绝，不覆盖。原窗口结束时间加保留秒数决定固定到期，重复调用不续期。
- `window(start)` 只返回一个准确窗口，缺失或到期抛错。保存内容严格绑定站点、原指标策略、容量和保留策略，校验类别、计数、总数与阈值。检查点只有固定类别聚合，不保存事件正文、主体或凭据。
- 读写权限分别以 `read`／`write` 调用当前授权回调，必须严格返回 `true`，并在操作前后复核。时钟、权限和外部调用均在原子存储回调外；回调可以安全重放。写入后撤权或期限耗尽会拒绝返回，但不声称已提交检查点被回滚。
- `AlertOutboxPublisher::publishArchived()` 要求同一个 Metrics 实例，保留原 ID、正文、创建时间及原 `message_age`。每条入队前和最后返回前重新核对档案权限及内容。调用方拥有 Outbox SQL 事务，任何异常均须回滚；本方法不提交事务。

各调用有固定时间预算；共享发布期限不会在每次档案读取时重新开始。原子存储仍需要自身短锁预算，Outbox 仍遵守其 SQL 预算；结束后超时拒绝不能中止已经进入的外部依赖，也不表示跨存储原子提交。

## 兼容与实际范围

[API审查](audit-window-archive-evidence-2026-10-23/api-review.json)以当前实际277类型为基线：新增一个公开 `WindowArchive` 类型，MetricsSink与Publisher分别增加一个方法；原有277类型的既有签名全部保持，内部62类型保持。候选现为278，未用最初268类型的历史记录覆盖当前清单。

没有修改现有DDL、指标v1/v2、Outbox格式或默认预算。新档案格式仅显式配置后使用，读写权限必须当前有效；MySqlStore必须使用独立连接，不加入宿主Outbox事务。旧站点切换指标或档案策略仍会拒绝混读，不能自动迁移或清空数据。接入与运维见[审计指南](audit-budget.md#显式保存闭合窗口)及[中英文兼容说明](current-compatibility-2026-10-23.md)。

本批新增功能止于准确闭合窗口的有界保存及原消息补入队，不恢复已消失且从未保存的历史、不重新投递、也不提供长期防篡改档案。未提交、推送、部署或发布，保留现有数据及未提交改动。
