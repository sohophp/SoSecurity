## 归属与事务

宿主继续拥有账号、邮箱唯一性、密码哈希、因子、角色、当前凭据版本及发送服务。组件负责用途隔离的挑战、期限／尝试／发送预算、状态转换和明确的通知意图，不自动登录、建表、联网或清除 MFA。账号适配必须明确绑定当前 PDO；业务修改、挑战消费和 Outbox 通知意图在同一实际数据库事务提交。组件不在可重试存储回调或 SQL 事务内发送邮件。

公开请求与确认操作使用各自明确的方法和结果，不能提供调用方任意命名、任意对象写入的通用流程执行器。通知请求对未知、已存在、禁用或不适用账号采用相同公开响应；内部审计也不记录原始地址、口令或挑战秘密。成功请求只说明请求已受理，不说明邮件已到达或账号已变更。

## 数据、秘密与资源边界

挑战使用不可猜测秘密及公开选择器；持久挑战记录仅保存验证所需摘要，并封存用途、主体、地址／凭据版本、期限、状态及计数。所有变更重新读取当前状态，不能使用签发时缓存的身份代替当前授权。恢复备份或切换代际时，旧挑战不能重新生效；缺失／损坏历史、未知格式及容量耗尽拒绝操作，不能清空后重建以恢复可用性。

延迟通知需要的地址和挑战秘密放入有用途及对象绑定的认证加密信封，保存到同 PDO 的私有通知账本；Outbox 正文只引用稳定通知编号。Outbox 绑定原正文指纹，不能为了轮换通知加密密钥而改写已入队正文；应原子更新通知账本信封并保留原编号、用途、接收地址和期限。工作进程只为固定服务器模板解密，不接受客户指定的发件人、回复地址、邮件头或回调 URL。密钥版本、轮换及不可用处理沿用密码学组件；缺少所需能力时明确拒绝，不把纯 HMAC 封存当作保密。调试、JSON、序列化、日志和异常不能导出挑战秘密或完整通知正文。

邮箱的显示值与唯一性键分开，明确地址规范化、域名大小写及国际化能力；不能擅自应用特定提供器的忽略点号／加号规则，也不能将不同本地部分合并。兼容已有账号时由宿主明确迁移和冲突处理，不能在用户确认后悄悄采用另一个地址。

全部输入、数据库字段、挑战／通知正文、在线记录数、重发次数、有效期、尝试次数和 I/O 都有显式预算。拒绝必须发生在相关账号写入、通知入队或昂贵口令计算之前；确认期间重新检查预算和当前权限。Cookie 写入口有 CSRF，敏感确认响应禁止缓存；统一公开错误不以数据库异常内容泄露账号存在性。

## 事务账本隔离候选进度（2026-10-17）

同一隔离目录后续增加 `AccountRecord`、宿主 `Repository` 契约及内部 `Ledger`，并提供两张私有表的显式 SQLite／MySQL DDL。账本只参加调用方已经开启的 `SqlTransaction`，没有网络、自动建表、账号变更或权限决策；账号适配接口还没有宿主实现，不能因接口存在而认定已完成账号事务。待验证账号的创建接口不接收密码，激活时须由条件更新安装所有者确认的密码并推进凭据版本。

根记录绑定外部 epoch、策略和成员历史；每条记录封存主体索引、用途、版本、期限、正文长度及摘要。元数据在 SQL 端按字节／类型限制，正文最多 16KiB，实际类型／长度通过后才读取正文并验证摘要；合法空 BLOB、NUL 和非 UTF-8 字节保持。历史按物理主键每页最多 64 条，默认最多 1000 条；缺失／篡改、版本冲突和满额均拒绝，不自动清空、采用孤立记录或覆盖损坏正文。历史扫描验证封存元数据和实际正文长度；正文内容摘要在读取／改写该记录时校验，不声称每次扫描都读取所有正文。

该阶段尚无清理、封存密钥轮换、备份恢复编排或挑战状态机。后续注册实现见下节。外部 epoch 的保留与恢复时换代仍是部署责任，不能把同一备份内的根摘要当作独立恢复锚点；全部状态和锚点一并回滚的情况没有在本阶段解决。

`ledger-validation/report.json`：九版 PHP 各 76 项私有 SQLite 检查、七个账号源文件的 PHPStan 及 81 次 PHP 语法检查通过，11 个被测文件哈希保持。`ledger-mysql-validation/report.json`：九版各 53 项自建、禁用 TCP 的 MySQL 检查通过，另一个 11 文件清单哈希保持；两者均限制 PHP 内存为 8MiB。验证包括 16MiB 异常 SQLite 字段、NUL 类型混淆、MySQL 大二进制正文、CAS／容量／损坏历史及宿主事务局部回滚；没有运行生产数据库。首轮 MySQL 因测试将超限参数异常类型写错而退出 255，原日志保留在 `ledger-mysql-first-failure/`，修正测试断言后重跑通过，账本实现没有为此修改。

上述证据只验证内部账本基础行为；没有注册、双地址确认、恢复、重发／取消、并发挑战消费、SMTP 或浏览器流程验收。完整交付范围仍按本页前述矩阵执行。

## 注册与确认隔离候选进度（2026-10-17）

候选新增 `Registration`、私有投递数据 `Delivery`、实际 PDO 账号适配示例及其两后端 DDL。待验证申请不保存密码；通知正文只引用稳定通知编号，邮件证明秘密保存在认证加密信封中。申请、当前申请指针、挑战及通知意图同 PDO 提交；确认先持久扣减尝试次数，在事务外检查密码策略和计算哈希，再重新核对账号、版本、地址、指针、用途、期限及当前权限，条件激活、消费挑战和新增激活通知同事务完成。没有自动登录或清除 MFA。

重复申请在冷却期内不追加通知，有限重发更换秘密而不延长原期限；旧通知停止提供给读取方，旧秘密不能兑换。实际测试预算回调复用 SDK 的组合限流和独立主体限流，覆盖站点、来源、目标地址假名及已知主体；这是测试宿主实现，尚无正式工厂／诊断和生产预算接入契约。通知读取要求当前工作进程权限，但该方法不验证 Outbox 租约，也不发送邮件，不能直接当作完整投递工作进程。

## 取消、清理与轮换隔离候选进度（2026-10-17）

`Registration.cancel()` 消费当前注册证明，不改密码／账号状态，也不创建会话。取消后旧证明不能激活；允许在冷却后重新申请，但须换用新的随机选择器和秘密，沿用原截止时间并继续累计有限重发次数。错误、旧版本、旧选择器、其他作用域、过期或已消费证明不能取消当前申请；取消前后仍检查当前权限及期限，提交后状态未知与提交前回滚分开处理。

`maintain()` 只处理私有账本：按物理主键选择最多50条页头，额外包含当前指针／挑战伙伴，最多删除两倍页头数；对全部待删除正文先认证，之后同事务删除并封存成员历史。到期的当前指针与其挑战成对删除，旧申请清理不会误删较新的当前指针；旧格式、损坏正文、未知结构及悬空指针拒绝，不通过清理自动修复。宿主账号和 Outbox 记录保持，宿主仍须定义账号数据保留与累计业务配额，队列维护使用其独立接口。

`rotate()` 有界重封存账本根／记录，并按需重新加密私有通知信封；原收件地址、秘密、编号、用途与期限不变。通知维护只返回已认证的密钥编号／时间元数据，不返回收件地址或秘密。Outbox 的稳定通知编号、正文指纹及根保持原样。空账本也能换根密钥，当前密钥记录不重复改写；已过期历史可认证／重加密，但不会重新变为可投递证明。退役旧密钥前仍须停止旧写进程并核验所有命名空间及保留副本；分页 `done` 仅表示当前扫描已无更大编号，不能当作全局备份／密钥退役证明。备份恢复／代际管理仍待实现。
