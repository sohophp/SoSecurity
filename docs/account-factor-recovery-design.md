## 认证与持久化边界

受管理目录为每个账号保存一个签名指针。认证读取该指针并核对实际因子代际；缺失、损坏、代际不一致或读取权限失效时拒绝，不自动采用原始 TOTP 存储中的其他因子。显式首次接入要求账号当前有效，启用 MFA 并推进凭据版本，保留密码、地址及其版本、角色和状态。

替换前，新因子位于随机作用域和随机主体的独立槽位。对新因子的设备验证码确认只证明持有该新因子，不切换账号身份，不允许用该槽位登录。开始准备时先在业务 PDO 上持久化流程、当前流程指针及安全通知意图，再创建外部因子状态；因此外部状态创建失败或 SQL 后续失败均有对应的准备记录。

独立审批上下文绑定用途 `replace_factor`、站点、作用域、外部 epoch、流程标识、账号快照、有效密码身份、旧因子绑定、新槽位和已证明的新因子标识、原始期限。审批预览是数据，不是授权；不能用邮箱恢复审批、普通登录会话或其他目标的操作授权替代。审批验证在 SQL 事务外消费一次性授权，当前／提交／完成阶段检查原审批及当前操作员；SQL 失败不退还审批或证明尝试。

最终切换在同一业务 PDO 事务内完成账号凭据版本推进、永久目录指针变更、流程消费和安全通知意图写入。失败回滚时继续使用旧因子；成功后旧会话、旧 MFA 挑战及旧恢复码不再被受管理认证路径接受。已提交而完成复核失败时报告结果未知，不再自动替换或再次发通知。密码、地址及其版本、角色保持。

外部因子存储与业务 PDO 不承诺分布式原子性。外部 TOTP 确认成功但 SQL 保存失败时，原账号指针仍保持；下一次用新时间步验证码重新证明，不能再次导出此前生成的恢复码。共享存储错误、权限错误和旧代际均拒绝操作，不能降级到内存或 Session。
