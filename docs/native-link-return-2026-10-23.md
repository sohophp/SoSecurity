# 原生签名链接最终返回及时间源异常清理

全新自建账号与初始因子环境复现七个返回反例：issue／verify／execute在最终撤权或到期后仍返回，all在最终撤权后仍交付元数据；正常issue对照通过。另两个普通模式反例证明，签发／验证写入后时钟抛错，异常清理再次直接读时钟，会泄露私有RuntimeException。原始日志和修前源码见[native-link-return-evidence-2026-10-23](native-link-return-evidence-2026-10-23/)。未使用恢复环境或暂缓链路。

`Links` 现为已准入且完成的原生请求增加只读返回复核：管理入口重新捕获准确当前会话，检查相同会话身份、对象与字段权限；所有入口重新调用原请求守卫，最终检查时间及适用的链接期限。业务执行使用原准入Target，避免把合法业务版本更新误当作原链接的新授权；宿主守卫仍负责当前请求权限。all返回的是读取时元数据，不把它升级为后续授权。无匹配证明的拒绝路径不新增写入。

准入、SQL事务和最终复核共享原30秒事务上限内的整体Deadline；单次见证的预算保持。超时或后置拒绝不撤回已提交SQL，也不恢复已消费／撤销链接。普通异常清理改为捕获时间源异常，使用已知时间下限，仅移除本次准确id／digest，保留固定link.clock错误及无原异常链。

公开API和277类型清单保持。宿主边界需支持相应 `links.issue_check`、`links.verify_check`、`links.execute_check`、`links.all_check`、`links.revoke_check`、`links.revoke_all_check`。请求守卫仍接收原入口动作（execute使用verify），需支持有界重复只读调用。结果只在整个入口成功返回后使用，不自动重放。

首轮PHP8.5原生16个场景通过，两个普通时钟异常反例修后通过。最终九版本定向矩阵64项中63项通过，涵盖原生返回、普通时钟异常、公开契约及两端普通链接套件；失败为PHP7.2 revoke-guard的明确持续时间时钟倒退，未重跑。业务20秒＋最终守卫11秒的整体预算检查通过，已提交状态保留。最终静态分析通过，既有可选turbo扩展GLIBC告警保留。

私有MySQL8/8通过（PHP7.2显式单调时钟包装与PHP8.5）。离线归档／全新消费者14项中13通过、1失败：默认PHP7.2 issue-normal在SQL来源读取阶段触发明确墙钟倒退。其余消费者检查通过、安装源码摘要匹配，临时消费者已清理。详细逐项结果见[汇总](native-link-return-evidence-2026-10-23/summary.json)。普通时钟异常修复后的最终运行时与归档摘要一致；Links.phase1.php保存该修复之前的原生返回版本。

这不是完整候选验收。默认PHP7.2环境失败、MySQL默认预算可用性和其余非暂缓收口核对未关闭；暂缓与外部验收未执行。未提交、推送、部署或外部投递。
