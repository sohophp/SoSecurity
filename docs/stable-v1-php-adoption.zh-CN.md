# 现有PHP项目接入说明：S稳定范围与E实验功能

2026-10-25。限定S范围的首个本地稳定交付1.0.0已完成最终管理验收。运行时基线为`fedc471`。本次将最新中文说明纳入交付ZIP，不新增组件、接口或稳定承诺；最终准确提交、包摘要及新包最小安装验证结果由包外交付清单记录，避免自引用。

## S和E到底是什么意思

**S是可以按已验证方式接入现有PHP项目的普通组件。**稳定承诺有前提：指定方法、普通配置、依赖和部署条件都符合[准确范围表](stable-v1-api-scope.md)。它不是“整个SDK的所有功能都稳定”，也不是“自动保护整个网站”。

**E是源码里已经存在，但首版不承诺稳定的实验功能。**本次接入不启用它们、不开放对应路由或后台任务。E不全是已知坏功能，但有的仍有超时、结果未知、未解释历史失败或缺少完整外部验证。

**同一个类可以同时有S和E方法。**例如普通`ApiKeys`与高级`CredentialRegistry`不同；`HmacVerifier::verify`属于S，`verifyFor/withVerification`及状态边界组合属于E。不能仅凭类出现在S清单里就使用它的全部方法。完整类型表保留全部既有签名，准入以其前面的“混合类型的方法与启用条件”为准。

## 现在可以接入的S组件

| 现有项目的需求 | 本版可以接入的组件 | 必须保留的边界 |
| --- | --- | --- |
| 表单防伪造请求 | CSRF令牌、普通签名CSRF | 绑定服务端会话和具体操作；不替代登录和权限检查 |
| 本地验证码 | 算术、图片、滑动/点选验证码 | 图片/交互类型按需GD；不包含外部验证码提供商的稳定承诺 |
| 登录/接口限流、封禁 | 请求次数限制、共享预算、组合预算 | 跨用户/会话必须使用共享原子存储；验证码不能代替限流 |
| 密码处理 | 密码策略、本地弱密码清单、bcrypt哈希和校验、受控渐进升级 | Argon2id仅运行时编译支持时使用；不自动降级已有强算法 |
| 普通登录和会话登记 | 宿主身份提供者、普通密码会话、登记/校验/撤销、原生会话轮换 | 不配置StateBoundary；用户库、当前禁用/权限事实仍由宿主提供；不关闭已有MFA |
| 输入和输出处理 | 输入规则验证、按上下文输出编码 | HTML正文、属性、URL、JS等按文档使用；输出编码不等于富文本HTML净化 |
| HTTP入口保护 | 可信代理/IP、CORS、安全响应头、Cookie、跳转策略 | 代理名单显式配置；CORS不代替认证或CSRF |
| 普通文件上传 | 来源/MIME/大小/图片资源限制、私有保存及既有Scanner接口 | fileinfo，图片按需GD；自定义扫描器须满足契约；不包含隔离队列或ClamAV服务验收 |
| 服务器出站请求 | 有边界的目标地址策略、DNS/地址校验、TLS、请求/响应/耗时限制 | 明确允许的目标；原生传输需要curl和CA；不能把它当任意URL代理 |
| 普通API认证 | 普通Bearer API密钥、HMAC签名与验签、防重放 | 普通共享存储、当前密钥/作用域；不配置受保护状态连接；业务授权仍由宿主完成 |
| 普通Webhook入口 | 已有协议的请求验签 | 仅验签；不提供持久收件、持久去重或处理完成保证 |
| 普通权限与审计 | 当前身份/策略提供者、角色策略、本地脱敏审计 | 不含状态快照授权、SQL审计委托或远程投递保证 |
| 组件基础设施 | 按需工厂、普通FileStore/RedisStore/MySqlStore、只读诊断 | 后端和依赖按用途选；诊断不是安全认证，不在故障请求中自动安装/恢复 |

这是范围表S01—S14的中文归并，没有增加S项目。无需把全部组件一次接入；保留项目原有可靠实现，只替换一个明确入口即可。

“密码哈希稳定”不表示“账号恢复稳定”，“Webhook验签稳定”不表示“持久收件处理稳定”，“普通上传稳定”不表示“隔离扫描工作进程稳定”。已有项目正在使用MFA或受保护流程时，继续保留原保障，不能删配置、删标记或清空状态降级成S。

## 怎么最小接入

### 1. 安装已验收包

核对交付目录的`SHA256SUMS`，将`sosecurity-1.0.0.zip`解压到新的私有目录。它是本地交付，没有公开标签或Packagist发行。新建独立消费者的最小`composer.json`：

```json
{
  "require": {"sohophp/sosecurity": "1.0.0"},
  "repositories": [
    {"type": "path", "url": "/absolute/path/to/unpacked-sosecurity", "options": {"symlink": false, "versions": {"sohophp/sosecurity": "1.0.0"}}},
    {"packagist.org": false}
  ],
  "config": {"allow-plugins": false}
}
```

用目标PHP运行Composer：`php /path/to/composer.phar install --no-plugins --no-scripts --no-interaction --no-progress`，离线安装设置`COMPOSER_DISABLE_NETWORK=1`，保留生成的锁文件。已有项目须合并所需配置并审阅锁文件差异，不能覆盖原composer.json，不能关闭宿主已有依赖源来强行套用这份独立示例，也不能忽略平台要求。

### 2. 在宿主启动处加载，只选择普通组件

以下沿用已验收接入指南的普通工厂配置。先由部署步骤创建Web根之外、PHP进程可读写的应用独占0700目录；不能复用受保护账号目录。

```php
<?php
require __DIR__ . '/vendor/autoload.php';
$security = SoSecurity\Security::fromArray([
    'site' => 'example-site',
    'storage' => ['driver' => 'file', 'directory' => '/private/example/security'],
    'session' => ['secure' => true],
    'rate_limits' => ['login' => ['limit' => 5, 'window' => 300]],
]);
```

这一步不会自动启动会话、拦截路由或完成登录保护。若只用密码哈希/输入验证/输出编码，不必创建共享存储；工厂按实际调用启用模块。

### 3. 先接一个现有入口

- **表单**：沿用宿主已启动且可靠加锁的Session，保持锁至CSRF操作结束。将服务器随机生成的绑定值保存在Session，GET时用`$security->csrf()->issue($scope, $binding)`签发并做HTML属性编码；POST时用`verify($scope, $binding, $submittedToken)`验证，失败拒绝，再检查登录/权限后执行业务。不要接受客户端自选binding。已有框架会话不要重复启动或重新配置。
- **登录**：复用已验证的`examples/legacy-login.php`接线顺序：共享账号/IP预算、CSRF/验证码、宿主密码查询与验证、成功后轮换会话。样例不是真实用户库；实际身份禁用/权限/MFA仍用项目原流程。详见[完整最小接入指南](stable-v1-integration.md)。
- **普通API**：Bearer用`apiKeys()->fromAuthorization($header, $requiredScope)`；签发入口必须由现有认证/权限保护。HMAC按`examples/api-request.php`处理原始正文和签名头，使用共享nonce存储；验签通过后再做业务资源授权。不复制测试用公开签发/撤销路由。

示例复制到消费者根下的examples目录后使用其vendor自动加载路径；不要直接把vendor目录作为Web根。完整本地表单运行步骤、HMAC参数、依赖与回滚均沿用[接入指南](stable-v1-integration.md)，本说明不创建另一套接入框架。

## 仍然存在的限制

1. **验证环境有边界。**声明PHP7.2—8.5，已验证九个具体运行时版本；基础依赖json/hash，Session、GD、fileinfo、redis、pdo_mysql、curl/CA、sodium按用途要求。实际服务器为Redis5.0.3/MySQL8.0.46；不据此宣称任意系统、第三方适配器或真实业务站都已验收。完整固定门禁已通过，先前7ad825c交付ZIP在PHP7.2/8.5完成11项安装/来源/核心/真实本地HTTP烟测。本次仅更新文档后的新ZIP另做最小安装、加载来源和普通S组件验证，以新交付清单为准；不把旧ZIP烟测记成新ZIP执行结果。
2. **PHP7.2时钟回拨会拒绝当前操作，可能让合法请求返回503。**该版没有hrtime，真实耗时用microtime；这是已接受且未消除的可用性条件。不能通过增大预算、平滑时钟或关闭检查掩盖；本版不承诺不间断服务。
3. **共享状态必须真正共享、原子且隔离。**MemoryStore和单会话SessionStore不能承担全站登录预算/API防重放。多主机选择经过部署验证的共享后端；MySQL使用专用连接，不加入宿主已有业务事务。S与E不混用目录、连接和运行进程。这里没有新增运行时沙箱，包内E代码仍可被宿主误调用。
4. **错误不能放行，结果未知不能自动重试。**输入/认证失败拒绝，超限按策略429，依赖/存储/时钟故障拒绝并脱敏503。普通ApiKeys也可能出现`api.issuance_unknown`；不能当作必然没写入而再次签发。旧高级管理3000ms超时、`account.completion_unknown`、旧SqlInbox未解释失败仍未修复，不用新测试通过改写历史。
5. **宿主仍负责业务安全。**路由、HTTPS、代理信任、用户库、当前身份/权限、会话锁、私密配置和业务事务都需项目接线；不接管MFA，不提供业务恰好一次执行或持久Webhook收件保证，不把示例密码/测试入口当正式配置。
6. **迁移与回滚不能清空安全状态。**先在测试环境验证成功/拒绝/重放/超限/依赖故障，再接实际项目。回滚先恢复可靠旧保护，保留封禁、nonce、密钥和审计，不倒退安全账本、不降级密码哈希、不重试未知结果。旧保护不可用时关闭敏感入口，不能匿名放行。
