# G4 独立见证引用的耐久恢复审计

日期：2026-10-21（Asia/Shanghai）。继续原 P1／G4，不新增需求、阶段或预算。此前隔离根只保存最新处置及前序摘要，多次续办后无法回放全部审批／处置状态。本组补充显式耐久审计；账号仍 disabled、业务仍 quarantined，完整 F01／R1—R6 尚未完成。

## 显式依赖与状态约束

新增 `StateRecoveryAudit($directory, $keys, $persist)`，目录须独立、规范化、0700，与见证目录分开，并且不能落入受保护 SQL、认证文件或采集目录。构造只验证配置，不创建审计状态。`$keys` 必须与准确见证复用同一 HMAC 密钥对象；`$persist` 是同步确认准确文件及目录稳定持久化的可信平台适配器，不能以普通成功日志或布尔权限代替。可使用已有 `LocalStatePersistence`，测试使用 WSL 内原有 Linux／Python 文件描述符 fsync 适配，不修改系统 PHP。

`LocalStateWitness` 构造函数末尾追加可选 `?StateRecoveryAudit $recoveryAudit = null`，原有参数顺序与默认值保持。现有认证工厂仍注入该准确见证所构造的 `StateBoundary`，没有自动创建审计或从当前 SQL 初始化的配置捷径。例如，在已准备来源及独立目录后：

```php
$audit = new SoSecurity\Account\StateRecoveryAudit(
    $auditDirectory,
    $keys,
    new SoSecurity\Account\LocalStatePersistence($auditDirectory, 5000)
);
$witness = new SoSecurity\Account\LocalStateWitness(
    $pdo, $witnessDirectory, $site, $scope, $epoch, $keys, $source,
    $witnessPersist, 30000, 2, null, $audit
);
```

独立恢复管理员的物理域复查现在包含审计目录。继任读者继承同一准确审计对象，不能在建立新隔离代际时移除或替换它。根一旦包含 `recovery_audit`，未配置准确审计的读者会拒绝。已存在恢复审计时，丢失见证不能通过 `initialize()` 创建一个新 current 来绕过历史。

运维必须让见证和审计不随业务备份回滚；代码中的物理域检查不能证明备份流程独立。下文的审计回退检查，以当前独立见证没有同时回退为前提。

这是显式可选依赖，普通 SDK 和未配置的历史接入仍可独立运行；它们不能因此宣称具备完整恢复审计。最终恢复提交尚未实现，未来提交必须将这项证据与其他恢复条件一起检查，而不是仅凭存在审计对象放行。

## 先持久审计，再发布状态

关闭旧权威，以及已配置审计的新隔离代际内每次 pending／complete 写入，均先追加签名记录并确认其持久化，再把引用该记录的签名根写入原见证 inode。记录包含准确签名前序根、后继状态提案、前序审计摘要、序号与独立签名域；根引用审计目录身份、记录 SHA-256、序号及历史起点标志。审批回执、准确处置清单、各次续办的序号与尝试号随记录保留，不会因最新 remediation 被替换而丢失。

使用独立的 `SoSecurity.Account.StateRecoveryAudit.Context.1`／`Record.1` 签名域。内容寻址文件不能覆盖已有内容；原始密码、会话令牌、一次性批准令牌及因子秘密不进入这些根／记录。现有根保存的只是操作摘要、批准编号以及不含原材料的固定处置清单。

每次读取被引用的根都会重新验证所引用的完整链、前后状态与根引用，不用先前成功读取的缓存掩盖替换。删除、篡改、回退、错误权限、硬链接、超大记录、错误目录或缺少准确配置时拒绝。记录在发布前已写入但确认失败时，可以留下未引用记录；它不成为可信根，也不会自动重放或自动采用。只有新的准确审批／原生持锁写入作用域才可能发布后续状态。部分文件损坏或持久化不明仍需要保留隔离和受控处理。

格式 2／3 增加可选 `recovery_audit` 根字段，审计记录格式单独为 1。旧读者可能拒绝新根，禁止混用部署，不能把“原构造调用仍可运行”当作旧读者理解新状态格式。没有审计的历史 closed／quarantined 可以从当前根开始登记后续记录，但 `complete=false` 永久保留，不事后虚构已丢失的历史。`complete=true` 只表示链起点覆盖了本次关闭旧权威的前序 current／pending；它不表示恢复业务、孤立记录对账或完整安全验收已经完成。

## 固定容量和分页

每个审计目录只服务一个见证上下文。最多 256 个记录文件，未引用记录也计入；另有一个不超过 1 KiB 的上下文标记。单记录在解析前限制 64 KiB，记录内前／后根各不超过 16 KiB，根自身仍遵守原有 4／16 KiB 限制。达到容量或出现不合规条目时保持隔离，不自动删历史、跳过或扩大上限。满容量后的独立归档／维护尚未实现；大型恢复可能因此无法继续，仍是完整容量维护验收的开放项。

`LocalStateWitness::recoveryHistory($requestBudget, $cursor = null)` 每页最多返回四个从新到旧的准确事件。游标绑定当前完整根摘要，根改变后旧游标拒绝；游标在请求预算回调前脱离调用者引用，防止校验后修改。读取不授予处置／启用权限；宿主继续负责管理接口访问控制和响应日志处理。审计追加只接受当前准确持锁、相同 PID／Fiber 的原生见证写入作用域，不能通过公共类方法提交任意提案。
