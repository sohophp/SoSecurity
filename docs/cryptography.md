# 密码学用途清单与迁移边界

本清单描述组件代码中的用途、算法和宿主责任，不收集或展示在用密钥、密码、证书或个人数据。更新于2026-10-17；它不是使用方生产环境的完整密码资产清单，也不代表独立密码学审查通过。

## 当前组件用途

| 用途与实现 | 算法／材料 | 范围与边界 |
| --- | --- | --- |
| [Cipher](../src/Crypto/Cipher.php)敏感数据加密 | sodium XChaCha20-Poly1305；32字节随机密钥、24字节随机nonce | sosc1信封绑定格式、密钥ID、用途和对象；认证失败不返回明文；不接收密码并自动派生密钥 |
| [HmacKeys](../src/Support/HmacKeys.php)消息认证 | HMAC-SHA256；32—128字节宿主私有材料 | 供明确协议／业务用途注入；应为每个用途提供独立材料，类实例不同不证明材料已隔离 |
| [TOTP](../src/Mfa/Totp.php) | RFC6238的HMAC-SHA1／SHA256／SHA512，因子秘密分别20／32／64字节随机生成 | 默认SHA1为既有验证器兼容策略；每个绑定保存自身参数。验证码不是128位Bearer秘密，依赖期限、防重放和在线错误预算 |
| [TotpFactors](../src/Mfa/TotpFactors.php)因子与恢复码 | 因子秘密用Cipher认证加密；每个恢复码含16字节随机材料，状态保存摘要 | 因子秘密与加密主密钥分别管理；恢复码仅一次展示并原子消费，不能当作无需近期认证的永久设备身份 |
| [PasswordHasher](../src/Password/PasswordHasher.php) | PHP原生bcrypt默认cost12，显式可用时Argon2id | 新哈希受最低参数约束，验证受资源预算约束；旧哈希仅经宿主已知验证器迁移，不自动猜测旧格式或降成本 |
| [PasswordBlocklist](../src/Password/PasswordBlocklist.php)与[PwnedPasswords](../src/Password/PwnedPasswords.php) | 本地SHA256拒绝表；外部范围查询按服务协议使用SHA1前缀 | 只用于匹配拒绝集合，不能将这些快速摘要用作账号密码保存、认证令牌或数字签名 |
| [SessionRegistry](../src/Auth/SessionRegistry.php) | 随机定位编号和256位随机秘密，秘密保存SHA256摘要 | 凭据绑定当前身份／期限／代际并可撤销；PHP原生Session ID的生成配置仍由宿主和运行时负责 |
| [RememberedLogin](../src/Auth/RememberedLogin.php) | HmacKeys签名、随机定位编号与256位随机秘密、共享摘要状态 | 固定协议与站点／主体／代际绑定，旧代际重放撤销；密钥变化与账本恢复须共同制定失效规则 |
| [CsrfTokens](../src/Csrf/CsrfTokens.php)与[SignedTokens](../src/Csrf/SignedTokens.php) | 随机令牌／摘要状态；签名方案使用HMAC-SHA256 | 绑定当前服务器会话或已验证身份、用途和期限；签名方案不提供逐令牌撤销或自动单次消费 |
| [ResetTokens](../src/Password/ResetTokens.php) | 256位随机秘密与SHA256摘要 | 绑定主体和当前密码版本，原子消费；最终改密由业务版本条件和事务控制 |
| [API凭据](../src/Api/CredentialRegistry.php)与[SigningKey](../src/Api/SigningKey.php) | Bearer随机秘密／摘要、HMAC-SHA256声明与RFC9421固定签名配置档 | 消息签名密钥与账号凭据封存密钥分开；有效签名不代替当前账号状态、scope或对象权限 |
| [Links](../src/Link/Links.php)与[Grants](../src/Operation/Grants.php) | 签名链接使用HMAC-SHA256；操作凭据使用随机秘密及摘要账本 | 绑定用途、资源／参数／当前身份及期限；普通SHA256指纹只标识绑定内容，本身不是来源认证 |
| [Webhook验签](../src/Webhook/Verifier.php) | 固定HMAC-SHA256协议与可选sodium Ed25519 | 提供器登记／撤销由宿主；不接受客户端选择算法或将未签名字段提升为可信来源 |
| [Webhook接收](../src/Webhook/SqlInbox.php)与[处理](../src/Webhook/SqlProcessor.php) | 独立HMAC-SHA256状态封存、SHA256正文摘要、256位随机领取秘密 | 封存证明完整性和已接受来源，不加密正文；私有数据库的访问控制、备份与历史撤销政策仍须部署落实 |
| [下载](../src/Download/Downloads.php)与[租约](../src/Concurrency/LeaseManager.php) | 内容SHA256与当前授权绑定；租约使用随机持有秘密和摘要 | 内容摘要不保密，租约不停止已暂停的进程；私有文件、条件写入、期限及隔离序号分别执行 |
| [AuditLogger](../src/Audit/AuditLogger.php)主体假名 | 独立私有材料上的HMAC-SHA256 | 假名可关联且仍需访问／保留控制；不能复用生产签名密钥或声称日志已不可篡改 |
| [受限外部请求](outbound.md) | TLS由cURL及其TLS库执行 | 证书、固定目标、地址／实际连接和预算分别核验；组件没有实现自己的TLS或应用层密钥交换协议 |

CAPTCHA短答案用于受限交互挑战，不是一般用途的高熵授权秘密。随机凭据使用PHP的random_bytes／random_int，不使用时间、顺序编号或UUID代替秘密；生成失败不得切换到较弱随机源。原子存储回调可能重试，随机材料在回调外生成。

## 已知标准对照与兼容范围

ASVS5.0.0附录C将HMAC-SHA1列为仅适合历史兼容的机制，当前TOTP默认值因此必须保留明确的兼容例外及迁移评估，不能描述为全部采用附录认可的新设计算法。SHA256／SHA512已有RFC向量与显式配置，但实际认证器对参数的支持须验证后再选择默认值；修改默认参数不能静默改写已绑定因子。此项继续R1.2／R5复核。

HIBP的SHA1范围查询属于固定外部检索协议，不为新密码、令牌或签名提供安全性。不得因为该协议使用SHA1就将账号哈希改成SHA1，也不在未验证兼容性的情况下自行改造远端查询协议。

Cipher使用受维护的原生AEAD实现及固定版本格式；不开放客户端算法协商，不把任意算法名称作为配置传给底层。密钥轮换与重新加密已有接口，但更换算法或信封版本需要显式兼容解析、受控迁移和旧版本退役，当前未提供可任意替换的算法插件。

hash_equals用于秘密摘要／MAC比较，sodium和PHP原生密码函数负责对应原语。长度和格式检查可以提前拒绝无效输入；这不能作为全部请求路径恒定时间或已完成计时侧信道审查的证据。

## 宿主资产与生命周期

宿主应在受控资产清单中记录用途、所有者、环境、密钥ID、允许算法／数据类别、存放和授权方式、创建与轮换计划、依赖服务、恢复和退役条件；清单不包含实际秘密。还须盘点库以外的TLS证书、邮件／对象存储凭据、旧入口和第三方SDK。

新密钥由受信任的密码学随机源生成，按生产／测试、站点和用途隔离。字符串长度检查不能证明熵、独立性或秘密未泄露；部署不得使用文档中的重复字符测试材料。签名、加密、提供器验签和审计假名密钥应分别管理，避免共享权限扩大。

轮换先部署包含旧／新材料的受控版本，再把新ID设为当前；读取旧记录时仍需认证来源和绑定。重新加密／签名保存使用业务事务或比较更新，记录完成情况，并确认备份及仍在有效期内的令牌如何恢复或失效后再移除旧材料。状态数据库与密钥恢复到不同时间点时，先停止相关工作并核实，不能自动清空账本恢复服务。

密钥泄露后的撤销须覆盖现行凭据及受影响历史记录，不能仅生成一把新密钥就认为旧数据安全。日志不得记录材料、完整令牌、恢复码或明文因子。PHP调试脱敏和禁止序列化只保护相应接口；不保证进程内存、崩溃转储、同UID进程或宿主管理员无法读取秘密，也不承诺PHP字符串已可靠清零。

## 后续算法迁移

发现底层算法、协议或依赖不再满足要求时，先按此清单定位受影响用途和数据，再评估维护方支持的替代实现与运行时要求；新增受限版本、独立对照与互操作测试，保留迁移／停止接受旧格式的明确边界。后量子协议遵循适用标准及成熟实现的实际可用性评估，不在PHP7.2核心中自行实现原语，也不将未来迁移计划写成当前已部署能力。
