## 范围与停止条件

本轮处理[候选审查](candidate-review-2026-10-20.md)的 F02：幂等 SQL 元数据在安全校验前返回 PHP，异常字段可以使进程内存耗尽。验收仅限 PHP 7.2／8.5 的 SQLite、控制器自建禁 TCP MySQL、相关幂等正常／拒绝／事务回归、公开 API 和受影响源码静态检查。通过即停止，不执行九版本完整门禁、Outbox 大矩阵或下游／生产验收。

同时更正 F03 的 OIDC 文档版本范围，实际依赖保持 `1.0.2`。F01 完整旧备份风险继续未关闭，本轮不启动其 SDK 实现。

## 实现

- `Idempotency/Schema.php` 集中定义原有根与记录字段类型；DDL 验证与投影共用，字段类型及数据库结构不变。
- `SqlExecutor` 对根、执行记录、历史的键／执行编号、维护分页统一使用现有 `SqlSchema::boundedProjection()`。SQLite 同时检查实际存储类型及完整字节数，NUL 后的内容也计入；MySQL 检查字节数及整数范围。
- 异常字段成为 SQL NULL，再由原有严格状态校验拒绝；不将异常数据截断成可接受内容。正文仍按准确 BLOB 长度选择，投影也只返回声明长度一致的正文，然后验证 SHA-256。
- 历史及维护分页明确使用原表的 `key_hash` 排序，避免投影别名使 SQLite 放弃索引顺序而增加临时排序。新增测试读取实际服务查询的 `EXPLAIN QUERY PLAN`，要求两条分页查询均不使用临时排序表。
- 不调整共享投影实现、公开执行器接口、策略默认值或业务事务所有权。拒绝前不执行新的业务回调，拒绝操作不推进根版本或创建执行记录。
- 新测试接入 `bin/check.sh` 的两种数据库路径及 `tests/mysql_check.py --idempotency`，后续适用门禁会运行，不能把接入配置当作远端已通过。

固定检查：两版运行新增输入边界及既有 `idempotency.php`、`idempotency-safety.php`、`idempotency-body-budget.php`、`idempotency-factory.php`；两版公开 API 检查；私有 MySQL 控制器仅运行幂等组件及新增边界／既有并发；PHP 7.2 目标的受影响源码静态检查；文档链接、语法及补丁空白核对。

测试数据仅来自自建本地数据库。SQLite 在 SQL 引擎内生成 16 MiB 超长字段，不在 PHP 中先分配大字符串；覆盖根与执行元数据、历史索引字段、NUL 前缀／中缀 TEXT、BLOB 类型错配和错误整数。合法空正文、NUL、全 256 字节值均需保持原样，重复请求只调用一次处理器。

MySQL 的准确 CHAR／VARBINARY 表结构在写入阶段拒绝超长元数据；测试区分引擎的 1406 拒绝与读取器对范围内非法元数据的拒绝，不宣称复现 MySQL 中无法按该 DDL 存入的 16 MiB CHAR 字段。

首次修改测试控制器时出现缩进错误，已在启动 MySQL 前修正。首次 PHP 7.2 SQLite 边界实际通过 125 项，其后仅修正 MySQL 测试中正常重放会推进根版本的预期，不影响 SQLite 分支；该历史与本轮最终输入摘要分别保存。

初版边界和回归通过后，实际 SQLite 执行计划显示 `USE TEMP B-TREE FOR ORDER BY`。将两条分页的排序列限定为原表列并加入上述查询计划检查后，才对变化后的准确源码复验受影响幂等专项；不是在无代码变化时反复扩测。静态工具曾报告可选 turbo 扩展因本机 GLIBC 不匹配而无法加载；保留启动警告，以分析器的实际退出码及结果判断，不将扩展加载失败隐藏为无警告环境。
