# SoSecurity 总体规划

规划日期：2026-10-13。原始产品要求见 [requirements.md](requirements.md)。本地目录和公开 GitHub 仓库开始时均为空；没有可复用的历史实现。

## 交付策略

先完成可接入旧 PHP 登录和表单的 0.1 基础里程碑，再扩展涉及网络、文件、数据库和认证协议的功能。各版本必须独立通过验收。路线表中的后续版本是规划，不能当作已实现 API；本次目标是交付 **0.1.0-dev 本地候选版本**，不包含发布、Packagist 登记或生产网站改造。

不按需求清单机械创建十三个独立包。当前用一个 Composer 包 `sohophp/sosecurity`，按职责划分命名空间；共有原子存储、时间源、令牌生命周期，不创建重复的 AutoBan 库。允许以后成为 monorepo，但有明确的独立依赖和发布需求时才拆包。

## 需求覆盖边界

- CAPTCHA：0.1 有算术、图片、Turnstile、过期/次数/单次使用/场景绑定/主动撤销；风险触发由宿主结合 RateLimiter 决定；不能证明具备抵抗 OCR 或自动解题的能力。
- CSRF：0.1 有 Session 和共享存储、按绑定/作用域、并行表单、可选单次消费；无状态验证、框架自动豁免规则在后续。宿主须保护全部状态变更入口，不能全局关闭验证。
- 限流：0.1 任意 IP/账号/组合键、阶梯及人工封禁、inspect/reset、Retry-After 数值；没有全站封禁列表扫描。账号单独封禁应谨慎；默认示例组合 IP+账号并用宽松 IP 桶控制总量。
- Session：辅助配置、更新 ID、空闲/绝对超时、显式失效；宿主控制启动、登录和注销，PHP 7.2 需显式发送 SameSite Cookie。
- 密码：原生 bcrypt/可选 Argon2id、验证/升级、宿主旧哈希验证回调、基本长度/编码策略、泄露检查回调和一次性重置令牌；没有内置联网泄露数据库。
- HTTP/XSS：0.1 Cookie、基础响应头、CSP Report-Only/可选 HSTS、可信代理/CIDR、上下文输出编码。CSP 策略由站点审核；没有 HTML 清理器或通用输入消毒。
- Input/Upload/SSRF/API：后续里程碑；不得用通用字符串过滤或 URL 格式检查替代这些防护。
- Audit：0.1 结构化回调和白名单脱敏上下文；查询存储和诊断后续实现。事件由宿主显式接入，业务语义留在业务层。
- 数据库：不是 0.1 存储实现；不把无锁数据库示例包装成安全适配器。

## 发布门槛

没有执行的 PHP 环境、浏览器、第三方验证码服务和独立审计必须逐项标记“未执行”。通过单元测试不代表全库安全审计通过。基础候选完成后暂停功能扩张；发布前验收见 [verification.md](verification.md)。
