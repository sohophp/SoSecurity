# SoSecurity 总体规划

更新时间：2026-10-13。需求依据是用户重新提供的规划对话最终共识及[产品需求](requirements.md)；早期助手建议的系统Fail2ban、独立AutoBan、固定目录/类设计不属于约束。

## 定位与范围

一个可用Composer安装、支持PHP7.2–8.5、框架无关的安全工具包，优先让验证码、CSRF、限流与应用层封禁、密码和会话能力易于正确使用。网络、上传、API等能力按需启用。完全公开源代码，安全依赖正确机制、秘密和部署边界。

本次处理SoSecurity核心、独立使用/迁移示例、文档、自动测试及`72.rocky.wsl/SoSecurity/`演示。已有项目接入、公开推送/发布、额外系统或Windows环境操作需明确指令；不自行选择其他项目试点。Docker只在当前环境确有验证需要时使用。

## 架构安排

保留单个核心Composer包和PSR-4命名空间，各组件可以直接实例化，也可通过PHP数组工厂按需创建。限流和自动封禁复用同一套计数、策略、存储；不按功能数量机械拆包。现有原子存储、Clock、错误分类和日志契约继续共用。

开发工具与可选HTML依赖有独立Composer清单并排除核心发行包。没有独立发布需求前不扩展monorepo，不引入完整框架、认证平台、ORM或大型依赖。具体设计依据见[architecture.md](architecture.md)。

## 验收原则

每项交付有可调用API、最小示例、正确配置、正常/拒绝/故障路径、演示、对应测试和限制。组件导入不造成自动会话、网络或宿主业务改动。存储异常、依赖故障和无效配置不能静默放行。

测试结果分已执行并通过、已执行但失败、未执行。PHP版本兼容、后端原子性、浏览器行为、生产部署和独立审查分别取证；不能互相替代。当前环境已有证据继续利用，不因重整文档重复安装运行时或额外改造系统。
