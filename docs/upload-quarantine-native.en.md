# Native PHP quarantine example

The [HTTP entry](../examples/upload-quarantine-http.php), [inert host composition](../examples/upload-quarantine-business.php), [CLI worker](../examples/upload-quarantine-worker.php) and [host-owned SQLite DDL](../resources/sql/upload-quarantine-example-sqlite.sql) compose actual password authentication, registered sessions, the quarantine factory and a local ClamAV service. They do not provision accounts, directories, tables, routes or services automatically. The SDK remains independent of this SQLite example.

Provision canonical private 0700 state, spool and native session directories outside the web root; protect ancestors and server aliases. Configuration JSON and SQLite must be 0600 regular files without links. This adapter requires native `files` session locking and a private flat `session.save_path`; other handlers need a host-specific verified integration. Apply DDL explicitly through the host's migration process. Populate accounts with actual bcrypt cost-12 hashes and a separate dummy hash; no test account is a deployment credential. Accounts requiring MFA cannot fall back to password-only access; connect the host's full authentication flow instead of clearing that requirement.

Set `SOSECURITY_QUARANTINE_EXAMPLE_CONFIG` to private JSON containing exactly `site`, `origin`, `database`, `state`, `spool`, `document_root`, `socket`, and `dummy_hash`. Site is a fixed ASCII identifier of at most 64 bytes. Origin is an exact HTTPS origin without a path, query or trailing slash. The actual web root and HTTPS environment are checked, not inferred from untrusted forwarded headers. Only an explicit `SOSECURITY_QUARANTINE_EXAMPLE_ALLOW_HTTP=1` permits localhost/127.0.0.1 loopback HTTP tests.

The `uploader` role may upload and download its own files. `upload-admin` may inspect site metadata and rescan, reject or remove files; it does not grant access to another owner's content. Current enabled status, roles, credential version and actual saved password hash are reloaded. Every mutation requires POST, exact Origin and single-use CSRF. Administrative actions additionally require recent authentication within five minutes, with remembered sessions excluded. Login, reauthentication and logout rotate the native session ID. Cookies are HttpOnly, SameSite=Lax and Secure for HTTPS.

Successful HTML POSTs redirect with 303 to GET; JSON clients receive direct results. `Referrer-Policy: same-origin` preserves ordinary same-origin form behavior while null/missing/foreign Origin is still rejected. See [MDN's Origin interaction](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header). No CSRF check is removed.

Private downloads accept only canonical `?download=<32-hex-id>` GET/HEAD requests. Ownership and availability are checked before reading, and current identity/ownership are rechecked before returning a digest-checked immutable snapshot. Responses use safe fixed attachment names, application/octet-stream, nosniff and no-store. Paths and credentials are never returned. Range and public sharing are outside this example. Inputs, authentication, authority, pending content, quotas and dependency failures map to fixed 400/401/403/409/429/503 categories without raw exceptions.

Web requests enqueue only. A trusted scheduler explicitly invokes `php examples/upload-quarantine-worker.php /private/config.json 16`, with a batch size of 1–64. Output contains only processed IDs/states; failures use fixed errors and nonzero exit. Scanning outages leave content unavailable for bounded retries. The example permits txt/png/pdf up to 1MiB each, 64 queue entries/16MiB total, eight indexed files per subject, and 240 requests per direct source IP per minute. Owner quota and index writes are serialized with an owned SQLite transaction and bounded queries. Uploaded images retain the SDK's decoding/reencoding limits. Engine configuration, signatures, process supervision and disk quotas remain host responsibilities.

The host index and filesystem/metadata store are not one physical transaction. Failed index writes attempt rejection and cleanup; crashes or lost confirmation can retain unavailable orphaned records requiring explicit reconciliation. Deletion handles quarantine first, then the site index. Never remove permanent lock files or restore only one store while workers can run. This example does not prove complete host authorization coverage, concurrent revocation, rollback protection or production recovery.

Local commands are `python3 tests/upload_quarantine_http.py /path/to/php`, the same command with `--tls`, and with `--browser --tls` plus `SOSECURITY_PLAYWRIGHT_MODULE=/path/to/playwright`. `SOSECURITY_TEST_NATIVE_QUARANTINE=1 python3 tests/install.py /path/to/php` additionally exercises actual installed native endpoints. Tests own their SQLite/PHP/no-TCP clamd resources and use synthetic signatures, not downloaded malware or system signature updates. Browser certificate exceptions are confined to private test contexts. See the [verification record](verification.md) for actual results, initial failures and remaining full R4.4 scope.
