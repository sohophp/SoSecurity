# 受保护持久登录返回检查（2026-10-23）

## 反例与实现

自有新账号、初始因子和正常登录环境复现七个原始反例：持久凭据签发／登录轮换后撤权或过期仍返回，设备查询／撤销／忘记后撤权仍返回。两个正常对照通过。随后单独复现提交后风险策略变为 `deny`、`step_up` 或抛异常的三个反例；这三项是在第一阶段返回检查修复后运行，不混称原始源码测试。

原生五个入口现在共享30秒操作时限，返回前执行只读当前请求检查。签发凭据、记住登录产生的会话和下一代持久凭据必须在返回时仍未过期。成功记住登录还重复读取当前设备风险策略，只允许 `allow`；请求、风险及时间源异常均脱敏，回调重入拒绝。已完成轮换不回滚，不退还旧令牌，不重复消费证明。

宿主新增只读动作 `remember.issue_check`、`remember.resume_check`、`remember.all_check`、`remember.revoke_check`、`remember.forget_check`；请求／风险回调须支持重复、无业务副作用的调用。普通模式不增加原生状态检查，但风险及时间源异常也使用固定安全错误码。API签名与277个公开类型保持。
