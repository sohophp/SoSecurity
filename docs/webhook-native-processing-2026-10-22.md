# Webhook 原生处理入口

本批补齐已声明保护模式下的领取、执行、失败登记、人工重试、状态及待处理查询。原先工厂返回的处理服务只能在手工 boundary.run 内使用，缺少原生准入；`before.log` 保留直接领取的真实失败。这是新增缺失能力，不把历史完成记录当作当前候选证据。

## 实现

- SqlProcessor 增加末尾可选 StateWebhookConnection，由 Security 工厂传入并核对同PDO、完整处理来源、端点、回执封存密钥和策略；普通构造器十个原参数保持。声明增加 processingLimit 与 process，接收和处理共用非嵌套保护上下文。
- 原生处理先在当前见证锁内使用只读观察事务读取封存处理行、接收来源、受长度约束的正文及必要容量计数。观察事务结束后才调用宿主映射／关联回调；不在观察单元调用任意宿主代码。准入后由见证再次核对完整来源。
- 无效领取状态、无消息、租约无效、当前工作者或管理权限拒绝、业务关联拒绝、处理容量不足在 pending 前结束。查询 status／pending 使用完整状态复核后返回的数据，不创建处理意图或更改见证。查询过程中撤权返回原有空结果形式。
- 写入意图仅开放 webhook.processing.claim／execute／fail／retry 四个确定动作，绑定作用域、工作者摘要、回执摘要、输入摘要、完整来源摘要及声明。原始领取令牌不写入意图，处理身份不冒充账号登录身份。
- 准入后使用原处理事务，保留处理行与业务SQL同事务、映射与来源复核、当前权限复核、租约检查、事务所有权和清理保护；全阶段共享一个 I/O 预算并检查业务时钟倒退。效果阶段失败仍保留 pending 和 account.completion_unknown，不重置见证、不续办未知效果。

## 测试与实际结果

证据目录：[webhook-native-processing-evidence-2026-10-22](webhook-native-processing-evidence-2026-10-22/)。

- `matrix.json`：PHP7.2、7.3、7.4、8.0—8.5九版54条全部退出0。每版原生工厂129断言、事务失败127断言、提交后撤权127断言、既有普通处理287断言、既有工厂／诊断120断言、270类型公开API检查。
- 原生正常检查覆盖：接收／处理容量、满容量重复接收、只读查询不改变见证、缺消息、工作者与业务拒绝、查询途中撤权、重复领取、错误工作者令牌、映射后租约过期、失败登记、独立管理权限与人工重试、最终业务SQL成功及来源变更拒绝。绑定前和绑定后构造的原始服务仍拒绝边界外调用，未删除其保护断言。
- 两种失败模式分别证明：handler返回失败后业务SQL回滚但见证保持pending；提交后工作者撤权时业务行保留且返回未知结果，不伪称回滚。均确认无活动SQL事务，不尝试续办。
- `race.json`：九版各四个独立进程／连接竞争同一回执，113断言全部通过，只有一个领取者、一次成功执行、一条业务行，最终见证为current且摘要一致。仅使用同一当前状态，不涉及代际交接、工作者恢复或未知结果续办。
- `mysql.log`：私有无TCP MySQL，PHP7.2原生单调时钟运行时／PHP8.5共22条检查通过，包括新原生失败模式、既有处理，以及受影响的原生接收／共享账号／原接收专项。`mysql-race.log` 两端四进程竞争分别通过。控制器退出0，并清理自己的实例。
- `archive.json`：实际ZIP、离线全新Composer安装，反射确认组件来自vendor副本，两端原生成功／失败／晚撤权／普通处理／工厂共14条命令全部退出0。`archive-race.json` 再在同一已安装组件上验证两端四进程竞争，两条通过；仅更新消费者测试辅助文件，运行时代码摘要保持一致。
- `static.log` 初轮失败：分析器缓存了权限回调的返回值，认为查询后的再次检查恒真。给现有 guard 方法补充准确的 `@phpstan-impure` 注释后 `static-final.log` 退出0，未更改权限判断。原可选turbo扩展GLIBC警告保留。
- `api-before.json`、独立提案、成员差异与 `api-review.json`：270个原有类型保持，新增三个方法及 SqlProcessor 最末可选状态参数，断言其他既有签名完整保留后才更新候选。
- `completion.json`：相关shell／Python语法和空白差异检查通过，归档运行时摘要与当前源码一致。新模式接入定向测试入口；未运行含暂缓能力的全项目脚本。

## 兼容与剩余范围

配置 state_connection 的 SqlProcessor 现在直接调用，不再套 boundary.run，嵌套进入会拒绝。未配置声明的普通用法、已有封存处理格式及领取令牌格式保持。宿主工作者／管理权限、映射和关联回调必须只读、可重复并覆盖其可变依赖；处理handler只允许当前PDO上的受控业务SQL，不能自行结束事务、DDL、网络或其他外部副作用。任意宿主代码不会因本功能自动变成只读或原子。

本批是本地原生处理接入与专项验证，不是完整R4.3、所有宿主HTTP部署、全写入者清单或稳定版发行验收。此前PHP7.2共享账号及普通维护的未解释超时证据仍保留，本批通过不抵消历史失败。在线提供器、旧ApiKeys、维护等剩余接入须继续逐项核对；暂缓的安全代际交接、未知回执续办、最终恢复及依赖F01仍未实施或验收。goal保持active；没有提交、推送、部署、生产访问、删除用户数据或撤销已有改动。
