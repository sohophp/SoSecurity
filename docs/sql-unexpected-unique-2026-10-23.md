# 私有 SQL 表额外唯一约束的默认拒绝

本批修复通用 `SqlSchema` 的独立结构缺口，覆盖账号账本、SQL审计、Outbox及幂等执行器使用的私有表。规范允许多条记录的字段被额外唯一约束限制后，原检查仍接受该表，可能在后续合法写入中发生意外冲突。

修前SQLite及MySQL都记录到额外唯一索引未被拒绝，校验后的测试操作标志为1；真实账号账本对象复用期间增加约束也未被拒绝。保留修前类的隔离写入对照进一步确认：根表增加epoch唯一约束后，结构校验仍通过，第二个合法站点命名空间初始化却返回sql.unavailable，第一条根记录保持。修后以配置异常前置拒绝；规范表的两个命名空间均可正常初始化。证据在[本地目录](sql-unexpected-unique-evidence-2026-10-23/)，包括`before-sqlite.log`、`before-mysql.log`、`before-ledger-sqlite.log`、`before-write.json`和`after-write.log`。这是结构准入缺口；本批没有据此宣称已造成跨键数据混用。

## 修复及兼容变化

- SQLite继续最多读取129行索引元数据，超过128项拒绝；额外读取经固定值限制的`origin`，区分主键索引与其他唯一约束。未声明的显式、隐式、表达式及部分唯一索引均拒绝。主键、全部所需索引和原有类型／列顺序／部分索引限制保持。
- MySQL在原有有界列／索引组合查询内读取唯一索引数量，严格等于主键及声明的唯一索引数量；随后仍逐组核验每个已声明索引的准确名称、列顺序、唯一性、前缀和类型。缺少一个所需索引并增加另一个约束不能靠相同总数通过。
- MySQL仅增加一个计数及固定参数，不额外加载未知索引行；SQLite字段最多为两个字符。原有元数据条数、内存、SQL输入和时间预算保持，额外非唯一索引仍允许。
- 每次需要重新校验结构时都重新读取当前元数据。已有预备语句只复用已关闭语句，不复用结果；原有回调、写入、事务及提交后边界仍令结构证书失效。
- 当前部署若给这些私有表增加了未声明的唯一约束，现在抛出`configuration.sql_schema`。需要宿主部署流程核对规范DDL；SDK不会自动删除索引、改表或改数据。规范DDL、数据格式、默认期限及277个公开类／接口签名保持。

TRIGGER可见权限、全局部分撤权、双向外键、触发器、存储引擎、列类型及字段预算校验保留。MySqlStore原有索引专项源码未由本批重写；本次修改的是通用SqlSchema。
