# Outbox 独立权限源与业务备份恢复

原生示例可通过私有配置中的 `authority_database`，将当前账号、角色、发布路由和业务拥有者放到独立 SQLite 权限库。业务订单、队列、审计和接收检查点仍保留各自的事务与恢复协议。恢复旧业务库不会改写独立权限库，已撤销的权限继续拒绝操作。

省略该配置时保持原来的业务库权限查询；这种模式不能防止旧业务备份带回旧权限。需要恢复隔离的部署必须显式接入当前权威来源，不能仅复制一份旧业务库后改配置。

## 显式部署

1. 停止发送、接收及管理进程，排空在途操作并保留当前可信恢复基线与完整备份。
2. 宿主显式创建独立权限库并执行[权限库 DDL](../resources/sql/outbox-example-authority-sqlite.sql)。从当前身份／权限权威来源填充账号版本、启用状态、角色、路由和拥有者；示例不自动导入业务库中的历史权限。
3. 权限库使用规范绝对路径，文件 0600、父目录 0700，位于真实 Web 根之外，与业务库、检查点、锁、配置和密钥文件不能是同一文件或硬链接别名。发送端与接收端分别配置自己的权限源。
4. 在私有发送／接收 JSON 中加入 `"authority_database": "/private/current-authority.sqlite"`，然后启动全部使用新配置的进程。旧代码会拒绝未知配置项，不能混跑旧进程。

该可选示例需要 `ext-sqlite3`，普通原生业务库继续使用 `pdo_sqlite`。缺少扩展、路径错误、未创建的库或无效配置均拒绝启用，不自动创建库、不改用业务库。只读打开使用 PHP 7.2 已支持的 [SQLite3 OPEN_READONLY](https://www.php.net/manual/en/sqlite3.construct.php)，不依赖较新版 PDO 的打开标志或本机 SQLite 恰好启用了 URI 文件名。

权限记录使用原示例表名：`outbox_example_actors`、`outbox_example_routes`、`outbox_example_owners`。发送者需要当前 `orders_writer`／`outbox_worker`，管理需要 `outbox_admin`；对账还需要 `outbox_reconciler`。接收管理、处理和终态签名分别检查原来的 `receiver_admin`、`receiver_worker`、`receiver_reconciler`。服务账号版本仍与私有配置绑定，不从请求指定权限库或操作者。

## 当前读取与拒绝

每次权限决定重新打开原生只读连接，查询完成立即关闭，不复用业务事务中的权限快照。宿主使用独立写连接按自己的权限管理流程提交变更；业务事务不会锁住权限库，当前撤权在后续权限检查中可见。

一项决定要求的全部角色、服务账号版本、当前路由和拥有者关联放在同一查询中读取，不能分别查询后拼接结论。并发变更时，该决定只能采用某个真实已提交的完整权限状态；多个检查阶段之间仍会重新读取当前状态。已经返回空结果的 SQLite3 查询不再继续读取，避免驱动重置后在另一个状态重新执行。

查询按实际类型和字节长度限制版本、角色及启用值，最多返回两条以拒绝重复身份。锁等待最多 1000 毫秒；数据库不可读、结构缺失、重复记录或查询异常按 `outbox_example.authority` 拒绝。无匹配账号／角色／关联也不允许业务操作。异常不会改查本地权限表。

每次读取前后重新核对私有配置及权限文件设备／inode。删除配置、切换路径或替换文件会拒绝旧设置对象；权限内容在同一库内正常事务更新无需替换文件。更换文件须停止进程并加载新配置，不能用这个检查授权运行中替换 SQLite 文件。

终态对账保留既有历史关联规则：当前管理员和对账角色仍有效时，可以为已禁用但关联仍存在的拥有者／路由完成历史关闭；普通新业务仍拒绝。删除关联则不能以旧业务库中的记录补回授权。

## 恢复顺序与边界

恢复业务库时保持独立权限库当前，不将它随业务备份一起恢复。确认当前服务账号版本和授权，再按[接收恢复](outbox-recovery.md)处理已封存的最后一个转换；当前撤权时拒绝重放，宿主只有在权威来源明确重新授权后才能重试。发送端查询、原证据导入、归档和管理命令同样使用该来源。

该接入不创建分布式原子事务。权限提交与业务提交之间仍有并发窗口，后续检查能拒绝确认，不能声称撤销已提交的业务副作用。独立权限库本身的可信性、同步时效、耐久提交、灾备和外部身份提供器由宿主管理；若它也被恢复为旧版本，单靠文件权限和 inode 无法证明其内容最新。全部业务、权限、检查点与外部配置共同回退仍需独立权威恢复记录。

## 本地验证

`php -d memory_limit=8M tests/outbox-authority.php` 使用自有临时库验证真实业务备份恢复后的撤权、当前身份版本／角色／路由／拥有者、已知转换恢复、只读拒绝写入、锁等待、文件替换、旧设置拒绝及 16MiB NUL 字段限额。包含当前权限源下的实际签名终态和管理 CLI；缺少可选扩展时明确报告未执行。

专项另启动真实权限写进程，每次提交都故意缺少一项必需权限；发送双角色、接收双角色、处理角色与对象关联各执行 1000 次决定，必须全部拒绝。停止写进程并提交完整授权后须恢复允许，不能用始终拒绝来通过测试。

`python3 tests/outbox_native.py --authority <PHP运行时>` 使用独立网络命名空间和本地 TLS，删除业务库权限行后实际执行生产、投递、接收、管理、撤权和恢复。它只验证测试权威来源与原生适配，不等于实际身份发行方、生产备份或完整 R4.3 验收。执行结果见[验证记录](verification.md)。
