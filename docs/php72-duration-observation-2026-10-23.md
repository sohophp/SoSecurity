# PHP7.2 默认持续时间时钟观测

为诊断之前多次被依赖边界脱敏的失败，本批只在三个全新隔离测试进程中通过 auto_prepend_file 定义 `SoSecurity\Support\microtime` 观测函数。它直接调用全局 `microtime` 并原样返回结果，只计数并记录最多32个倒退事件的时间差和不含参数的调用栈；不修改运行时源码、全局系统时间、预算或错误处理，也不平滑时间、不重试。工具及原始日志见[证据目录](php72-duration-observation-evidence-2026-10-23/)。

三个不同路径各观察一次：自定义业务拒绝通过，操作授权消费后撤权路径失败，操作业务过期路径通过。失败进程记录13376次读数，其中一次真实墙钟倒退约2591微秒，发生于 `Deadline::remaining` → `Deadline::check` → `LocalStatePersistence` → 见证写入。随即触发固定的持续时间时钟倒退错误。PHP版本为7.2.34，全局 `hrtime` 不存在，使用此前已有sodium包装，没有启用专用单调时钟扩展。

该证据证明当前默认PHP7.2环境的墙钟确实会倒退，默认拒绝是保护按设计生效，不应以忽略小幅倒退或延长预算换取通过。不能据此把所有历史依赖失败都归因于时钟：之前日志的底层异常已被脱敏，本次三个进程也不是那些历史进程。两次通过不覆盖旧失败，这批不是候选验收。

代码与时限策略保持不变。具备原生单调时钟的显式PHP7.2测试环境仍单独列示，不替代默认环境通过。现有环境／数据没有更改，未访问生产库，测试只使用自建账号和临时资源，未涉及暂缓链路。
