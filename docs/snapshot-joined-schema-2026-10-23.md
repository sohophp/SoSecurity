# 默认签发优化调查：SQL快照元数据合并

本轮在临时类副本中比较两种只读元数据查询：将列结构与主键元数据关联查询，或将两份结果在同一请求中返回。未修改src/Account/SqlStateSnapshot.php。两种候选都保留每组最多四表、列／主键各自的原有行数上限、读取前后两次完整结构复核，以及引擎、类型、空值、主键列／次序／前缀和唯一性检查。

实际加载候选后，两种写法均将五表快照的调用计数从28减为24，三个数据状态的完整摘要保持一致。每种候选的7项现有边界程序通过，覆盖宽表内存预算、读取中DDL变化、行及字段限量、捕获值、独立并发写入、提交后隔离和完整组合来源；该结果仍只属于PHP8.5／私有MySQL的候选实验。

性能未改善：每种数据状态执行20次完整digest，JOIN候选合计1.685秒、对应现行1.499秒，约慢12.4%；合并结果候选1.679秒、对应现行1.501秒，约慢11.9%。两种候选的三个状态都更慢，因此均不采用，也不扩大到九版／消费者验收或再次运行默认签发。

保留两轮无效实验：首轮自动加载优先级使候选类未加载，调用计数没有变化；随后加入ReflectionClass文件路径断言并直接加载临时候选。另一轮以括号开头的联合查询被现有观察单元的SELECT开头限制拒绝；未修改限制，后续仅将候选改写为外层SELECT。无效实验不作为性能或候选通过证据。

准确时间、摘要比较和采纳决定见[结构化记录](snapshot-joined-schema-evidence-2026-10-23/decision.json)。候选源码、驱动与所有原始日志均在同一证据目录保留；临时包装器、私有MySQL及测试资源由运行器清理。没有产品/API/兼容性变化，没有暂缓流程、未知结果续办或外部投递。默认签发超时及其他缺口继续开放，goal为active。
