# 上传隔离的完整文件来源与写入保护

## 已确认缺口与本批实现

源码核对确认 `Security::quarantine()` 在认证保护模式仍拒绝，现有 FileStateSnapshot 只覆盖状态 JSON，不能充当真实隔离文件的完整来源。本批新增 `QuarantineStateSnapshot`，先落实必需的文件来源与底层写入保护；没有把元数据接入等同于完整文件保护，也没有提前启用公开工厂。

快照绑定准确 PDO、规范化私有目录、目录设备／inode／所有者、上传策略、文件数和总字节上限。目录须为 0700 且在 Web 根外；只接受规范文件编号及策略允许的规范扩展名，拒绝符号链接、硬链接、目录、未知文件、异常权限和越界数据。每个内容文件须为同所有者的 0600 普通文件，按不超过 8192 字节的块计算完整摘要；单文件及累计大小先于读取检查，全部扫描受时限约束。两次完整观察须一致，不能只依赖 mtime、文件名或账本中的旧内容摘要。

永久 `.quarantine.lock` 只允许空的受保护普通文件，其存在和设备／inode 纳入摘要。构造和观察不创建锁、不扫描恶意内容、不分配业务状态、不执行恢复。私有目录、文件数、单文件大小、总大小和时限均有独立边界。

`CompositeStateSnapshot` 显式接受该具体来源，并在其他组件的只读捕获中同时观察它。`protect(boundary, witness, source, name)` 核对完整准确声明后，使用现有 FileStateBoundary 登记同一个物理目录。QuarantineFiles 的锁定、读、写、删除在打开文件或创建锁前检查当前边界；较早构造的实例、新实例及误指向该目录的 FileStore 都不能绕过。登记是进程内保护：所有 SDK 写入进程仍须使用同一准确权威，未声明的外部写入只由来源不一致检测拒绝，不宣称操作系统级写入隔离或跨安全代际交接。

目录校验与实际打开之间仍可能发生替换。专用测试在这两个步骤间只移动自己创建的目录，复现 DirectoryIterator 暴露私有路径；现已转换为固定 `account.quarantine_snapshot_corrupt`，不携带原异常链。首次日志保留。

## 本地测试范围

真实本地隔离队列在显式授权边界内完成文本入队、模拟扫描、内容读取、拒绝及清理；绑定前的原文件写入和已有实例绑定后的拒绝分别验证。只修改文件内容而不改元数据时，下一次见证操作拒绝，扫描器不再执行。本批没有真实病毒引擎／HTTP／外部投递，也没有未知扫描结果续办。

资源测试在 8 MiB PHP 进程预算下观察 16 MiB 自建稀疏文件，并修改最后一个字节验证完整摘要变化。这证明快照读取不要求一次装入完整文件，不代表上传解析或扫描 16 MiB 文件也能在 8 MiB 下运行。

初轮测试把 FileStateSnapshot 的状态目录与 scratch 目录误算成一个物理域，断言失败后修正为实际三个域；运行时声明没有放宽。首次静态分析指出读取结果的冗余类型判断，改用有明确失败返回值的有界 stream_get_contents，仍保留空读及读取失败拒绝。初轮矩阵脚本还误将 API 反射工具设为 8 MiB，九版均内存失败；原标准是 32 MiB，因此仅按既有标准补跑 API 工具，原失败不覆盖，功能与大文件快照测试保持 8 MiB。

准确输入、初轮／后续结果和消费者摘要见 [证据目录](quarantine-source-evidence-2026-10-22/)。公开类型新增一个至 274，既有类型签名保持。

## 仍需完成

公开工厂尚未有原生隔离连接；当前测试显式提供外层边界和测试权限，不能代替业务入口的当前账号／对象权限、输入与元数据只读准入，以及入队、扫描、读取、管理的最终返回检查。下一步在该完整来源上接入这些入口。未知结果续办、最终账号恢复和跨代交接继续暂缓；旧 PHP 7.2 超时、其他入口核对与外部验收保持开放，goal 不标记完成。

最终本批结果：首份快照 36/36 功能命令通过，9 条 API 命令因驱动误用 8 MiB 失败；两端 MySQL 4/4、消费者 10/10 通过。目录竞态异常脱敏后，最终快照的九版 API／竞态及两端普通／篡改定向检查 22/22、两端 MySQL 4/4、归档与全新消费者 12/12、两端语法 10/10 均通过，最终完整 PHPStan 无错误。API 补验使用原定 32 MiB；功能、目录竞态和原九版 16 MiB 内容观察保持 8 MiB。三份运行时源码与最终消费者一致，两份快照仅 QuarantineStateSnapshot 的目录打开异常处理不同。PHP 7.2 MySQL 使用既有单调时钟／sodium 包装，旧默认时钟失败未关闭；可选 turbo 扩展 GLIBC 警告保留。临时消费者及两轮私有 MySQL 已按控制器清理自身资源。准确命令、首次失败、源码差异和结果见 [result.json](quarantine-source-evidence-2026-10-22/result.json)。
