# 受保护凭据委托与 SQL 审计接入（2026-10-22）

## 实际修改

在完整 SQL 审计来源和单次写入准备接口基础上，`Authorizer::stateAuditedPolicy()` 识别准确身份提供器、具体 RolePolicy 和直接 SqlSink。`AuditLogger::prepareState()` 与 `StateAccountPolicy::prepareCredentialAudit()` 绑定同一 PDO、站点、时钟及完整表声明；配置、脱敏密钥及容量参与准确策略绑定。任意授权策略或包装审计回调仍默认拒绝，未假定其无副作用。

`CredentialRegistry` 原生委托入口接入允许及明确角色拒绝事件。允许流程核对操作者、目标、会话、近期认证、角色、范围、请求权限和完整来源，再执行准备的单次审计写入与凭据操作。角色拒绝只提交审计，边界完成后抛 `authorization.denied`，不执行凭据修改。成功路径在返回秘密前通过另一次只读准入复核当前权限，并再次检查时间。无效输入、初始会话、范围或容量等早期拒绝不保证产生日志。

宿主请求保护新增 `audit_current` 动作，阶段为 admission、before、return，附原管理动作元数据；它必须只读且可重复，不能重新消费原请求的 CSRF 或预算。允许流程重复读取当前范围提供器。审计事件表示授权决定，不保证业务完成；SQL 审计与凭据存储不是跨存储原子事务，后续未知失败保留已有记录及 pending，不清除限制、不恢复、不续办。

另外先用独立临时测试副本复现最终复核泄露 `private-permission-clock-detail`，再修改私有 `CredentialRegistry::now()`：捕获时钟异常，抛不带 previous 的 `api_credentials.clock`。添加 return-clock 用例，保留原始失败日志；只清理自己创建的两个测试副本。

公开清单仍为275类／接口；新增上述三个方法，旧公开签名未变。没有把用户初始268数量强制写回候选；见 api-review.json。普通凭据、无审计原生策略及原有拒绝保护保留。bin/check.sh 登记新增用例但未整轮执行，因为其中包含暂缓链路。

## 失败与剩余事项

最初 first.log 在PHP8.5来源快照遇到 `Security clock is invalid or moved backwards`。首轮PHP7.2 return-expiry发生被见证包装的身份依赖失败，未达到预期最终拒绝断言。脱敏补丁后PHP7.2源码与新消费者正常流程均在replace的管理认证处失败。公开异常已脱敏，未获得底层原因，不把这些失败归因于时钟，也不重复运行覆盖旧证据。

两端MySQL默认预算拒绝是当前明确的本地可用性缺口。较大预算10秒审计／30秒凭据下的通过不关闭它；未提高产品默认预算、放宽校验或清除pending。下一步可独立核对审计准备期限与写入前边界的衔接，以及完整来源快照的实际开销，不能进行未知操作续办。

当前只完成带审计原生委托的实现和上述定向验证，不代表稳定版验收。自定义授权／身份来源的原生覆盖、默认预算失败、此前未解释失败及全范围最终核对仍未关闭。OIDC未定义关联迁移按用户许可跳过；跨代际工作进程交接、未知回执续办、最终账号恢复启用及依赖它们的完整F01继续暂缓，真实外部验收未执行。

没有提交、推送、部署、访问生产数据库或删除既有数据。已有goal保持active，不另建重复goal，也未标记完成或blocked。
