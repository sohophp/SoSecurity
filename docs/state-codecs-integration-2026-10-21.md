## 改动及边界

未来锁内权限判断必须与真实业务读取器使用同一组格式校验，避免只看部分字段就把损坏或失效状态解释成当前权限。本次将四类校验提取为内部类型，并让现有真实读取路径调用它们：

| 内部类型 | 实际调用者及约束 |
| --- | --- |
| `LedgerState` | `Ledger` 共用形状、整数、HMAC、修订、期限、正文及集合校验；额外限制 `bytes:N` 字段。保留先认证元数据、再观察真实时钟的顺序 |
| `FactorDirectoryState` | `FactorRegistry` 共用准确目录字段、格式、主体／记录号／owner、因子坐标、迁移／撤销／恢复字段及绑定摘要；载荷上限 16 KiB |
| `TotpFactorState` | `TotpFactors` 共用 TOTP 状态／配置校验；过期归一化只改返回数组，不写回原始输入 |
| `ManagedFactorFrame` | `ManagedFactorStore` 共用 v2／v3 封装、上下文、迁移回执、HMAC 及有界树编码；原物理权限检查仍在真实存储操作处 |

四个类型登记在 `resources/api/internal.json`，原 232 类／接口的公开签名没有变化。没有修改数据库结构、状态封存格式或依赖。原事务、工作进程栅栏、权限回调和物理迁移过程保持在原调用链中；本次没有引入独立见证或全入口保护，旧备份风险仍然存在。

新增 `tests/account-state-codecs.php` 使用真实已登记因子、SQL 目录账本和物理 FileStore 封装，不以自行拼装的简单数组冒充完整集成。损坏目录数据会重新正确封存后再安装，验证拒绝不是仅来自错误外层 HMAC；纯读取阶段检查 SQL 调用数及物理字节保持不变，且拒绝对象时不调用其 `jsonSerialize()`。测试加入常规 SQLite／MySQL 入口；私有 MySQL 控制器新增有限的 `--state-codecs` 模式。
