# 原生操作授权的最终返回复核

本批在全新自建账号、初始TOTP绑定与普通业务授权中复现五个反例：begin 后请求守卫撤权、begin 后证明到期、confirm 后撤权、consume 后证明到期、execute 的SQL提交后撤权，原实现仍返回结果。正常begin对照通过。原始日志保存在[native-operation-return-evidence-2026-10-23](native-operation-return-evidence-2026-10-23/)。没有执行恢复审批、最终账号恢复、未知回执续办或跨代际交接。

修复 `Operation\Grants` 的原生返回路径：仅对新确认凭据、已确认授权、消费许可及已取得消费许可的业务执行增加只读复核。核对当前请求守卫、准确会话及身份、原Intent的对象／字段权限、会话和强认证期限，并在全部读取完成后检查证明期限。复核不重新消费、写回或恢复证明，业务回调仍只执行一次；后置拒绝不撤回已提交SQL，也不退款。没有产生权限结果的原有null路径及取消入口不增加权限结果复核。

准入、SQL事务及最终复核共享原有30秒SQL上限内的整体Deadline，见证自身的更短预算继续生效，没有提高预算。完成后的读取不会重启整体预算。私有时间检查复用同一次读数判定证明与会话期限，避免判定之间多读时钟。原公开API及277个类／接口清单保持。

宿主边界预算守卫需显式支持 `operations.begin_check`、`operations.confirm_check`、`operations.consume_check`、`operations.execute_check`。请求守卫必须允许重复只读调用；抛出的私有异常转换为固定依赖错误，不串联原异常。源码中的角色策略约束保持；这次没有增加任意自定义操作策略或审计接入。

首轮PHP8.5的四入口×正常／撤权／过期／守卫异常共16个场景通过。最终静态分析通过（保留现有可选turbo扩展GLIBC告警），默认PHP7.2与PHP8.5普通模式 `tests/operations.php` 均通过。该普通测试使用模拟存储及认证证明，不做账号恢复启用。

最终九版本定向矩阵40项中39项通过、1项失败；私有MySQL6/6通过（PHP7.2使用显式单调时钟环境，另有PHP8.5）。两项非法来源变更故障注入确认拒绝并保留pending，但不计为正常角色撤权场景。实验中的错误预期、诊断与模式改名时误改测试规则键的失败均保留，详见[分阶段说明](native-operation-return-evidence-2026-10-23/phase-notes.md)；没有改变运行时保护来通过测试。归档／全新消费者12项中11通过、1失败：默认PHP7.2的execute-expiry在因子权限读取中失败，目标断言未完成，根因未确定。没有重跑覆盖。安装运行时源码摘要一致，消费者已清理。汇总以逐项退出码为准，驱动脚本的退出0不代表全部子检查通过；见[最终汇总](native-operation-return-evidence-2026-10-23/summary.json)。默认PHP7.2消费后撤权场景已在前置begin的会话读取阶段失败，原异常被依赖边界脱敏，根因尚未确认；不能把目标断言未执行算作通过，也不以其他运行环境的通过覆盖该失败。
