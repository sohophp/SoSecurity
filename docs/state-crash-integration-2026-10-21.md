# G3 凭据安装的真实进程中断与有界暂存

日期：2026-10-21（Asia/Shanghai）。继续原 P1／G3 和 G4，不增加需求、阶段或预算。上一组完成固定凭据安装，但当时只有异常注入和对象重载，未证明强制终止后可恢复。本组处理认证目录内随机临时文件阻断续办的问题，实际终止写入进程，再在另一个 PHP 进程中重建连接和对象图。

## 修复和安全边界

原恢复写入使用 `.contain-*`／`.contain-lock-*` 随机临时文件。重命名前进程被强制终止会留下未提交文件，原完整文件来源扫描正确地拒绝未知名称，导致固定原效果也无法续办。保留原 FileStore／FileStateSnapshot 两个生产类，其余 SDK 使用本轮依赖；该对照的实际失败见[复现日志](state-crash-evidence-2026-10-21/before-repair-source-refusal.log)，旧源码副本保留在同目录 `before/`；不将拒绝误称为旧权限已复活。

恢复写入改用每条永久锁条带对应的 `stage-0` 至 `stage-63`，最多 64 个暂存槽，每个最多 65,536 字节。持有原锁条带和准确见证授权后才覆盖暂存槽，仍先落盘、核验目标 before 和暂存 after，再原子重命名并确认持久化。锁文件直接以排他创建和私有权限生成，不再创建随机锁种子；临时 umask 在同一同步调用中恢复，没有用户回调或 Fiber 切换点。

受保护的普通 FileStore 写入也使用相同条带暂存槽；未保护普通存储保留原有写入路径。暂存字节永不由 FileStore 解码、查找或采用为认证状态，实际读取仍只接受 `SHA256(namespace + NUL + key).json`。未知结果的续办依旧需要原封存清单和新的独立强批准，不能把残留暂存作为批准或数据来源。已知名称的暂存可以在下一次授权写入中覆盖；没有无界孤立文件累积或不经批准恢复账号。

`FileStateSnapshot` 只对这 64 个准确名称接受私有普通文件、同属主、单硬链接和 64 KiB 上限。符号链接、硬链接、错误权限、超长内容、`stage-64`、前导零名称、旧随机临时名称及其他未知节点仍拒绝。正式认证文件的字节摘要和最大文件数量保持独立；暂存内容的变化不成为可信业务变化。

## 真正的进程终止

`tests/state_crash.py` 创建私有目录，独立启动写入 PHP 进程。写入进程在指定持久化点输出就绪并暂停，控制器向其发送 `SIGKILL`，核验退出状态为信号 9，然后独立启动恢复 PHP 进程。没有 `fork()` 继承数据库连接，也没有序列化／传递活服务对象。

恢复端使用测试宿主的只读启动路径重新打开两个 PDO、实际 FileStore、受管 TOTP、账本／目录、完整 SQL／文件来源、独立见证、审计和独立恢复审批域。不运行建表、初始化、重新迁移或 `activate()`。私有传输文件只包含准确测试配置和验证材料，不进入日志；进程退出后连同全部测试数据库和认证文件删除。

三个中断点是：新因子文件持久化后、重命名前；重命名和第二次持久化后；三行 SQL 提交后、最终完成确认前。恢复端验证原 pending 清单、真实目标行／文件位置、原可信摘要、旧批准拒绝，以及重新强认证后的同一原效果完成。完成仍 quarantined、账号仍 disabled；实际新密码哈希和新因子 ID 正确，不采用旧授权。
