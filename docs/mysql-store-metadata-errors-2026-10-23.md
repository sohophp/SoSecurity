# MySqlStore元数据预算与错误详情（2026-10-23）

## 已复现并修复

1. **无界列元数据读取**：在自有MySQL8.0.46中创建64个额外列、每列带60000字节默认值的合法表结构。8MiB读取进程在 `fetchAll()` 耗尽内存，未能正常拒绝不兼容结构。修复将列读取限制为五行，在SQL侧限制类型声明长度，仅取需要验证的 `expires_at` 默认值；规范结构仍正常读写，错误结构抛出配置异常。
2. **PDO异常链泄露**：构造、安装、写入、清理四个入口均复现原始内部错误经 `getPrevious()` 暴露。修复保留既有错误类别、原因码及事务处理，移除PDO异常引用。写入和清理用例使用真实MySQL `SIGNAL` 错误；构造／安装使用真实PDO连接上的明确故障注入。没有以吞掉错误或继续执行来通过测试。

第一种尝试使用单列4MiB默认值，MySQL在建表时拒绝（3507），不算产品缺陷证据。该记录保留；随后多列结构成功创建，才确认运行时内存问题。DDL准备进程使用64MiB，实际构造与读写检查进程使用8MiB，不宣称整个建表过程也在8MiB内完成。

## 范围与兼容

规范DDL、数据格式、公开方法签名保持。PDO包装异常的 `getPrevious()` 现在为null；依赖原始数据库异常链的诊断逻辑需改用已有原因码，不向应用异常输出内部详情。本模块仅支持MySQL，未将SQLite测试算作本模块验收。

本批没有验证或宣称所有SQL部署结构和触发器权限边界均已闭合，没有执行暂缓链路、生产数据库操作、外部投递、提交、推送或部署。默认凭据预算失败、既有PHP7.2默认时钟问题及剩余非暂缓候选核对继续开放；goal保持active，非完整稳定版验收。
