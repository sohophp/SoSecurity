# G1 账号 API 凭证公开工厂与写入前准入

日期：2026-10-21（Asia/Shanghai）。继续原 P1／G1，不增加阶段和预算。`Security::apiCredentials($stateAccountPolicy)` 现在可以构造具有原生准入的受保护 `CredentialRegistry`，完成账号凭证的八个公开入口；不是开放旧版 `apiKeys()` 或其他授权工厂，也不关闭完整 G1／G4／F01／R1—R6。

## 配置与两种明确模式

在已配置的 `authentication.state_boundary`、实际 FileStore、密码身份提供方、受管 TOTP 和工作进程围栏上，先用同一 `Security::stateAccountPolicy()` 创建纯策略，再传给 `apiCredentials()`。策略必须匹配这个工厂缓存的实际会话／因子图、来源、边界和时钟。缺策略、其他图的策略或在未保护模式传策略均拒绝，不猜测或初始化来源。构造和诊断不读取状态、不调用宿主或身份提供方。

`Security::apiCredentials()` 只追加可选策略参数；`CredentialRegistry` 在原可选边界之后追加可选策略参数。原参数保留。无策略的普通模式保持原语义；此前手工传入边界、显式 `run()` 的直接服务模式继续要求准确活跃边界。新的原生模式直接调用公开方法，禁止外套 `run()`、递归请求和借用其他 Fiber 的进行中上下文。

## 准入、权限与拒绝

`issue`、`rotate`、`replace`、`all`、`revoke`、`revokeAll`、`authenticate`、`fromAuthorization` 均进入同一原生处理路径。输入标签、作用域、名称、列表、期限和代次先有界验证并复制，输入数组中的引用不会在宿主回调后改变已选参数。

独立预算与见证先核对 current 和完整来源。锁内准入通过原生 `SqlStateSnapshot`／`FileStateSnapshot` 重建实际账号、密码版本、签名因子目录、实际因子绑定、会话及 API 账本；每份完整捕获都必须匹配锁内已确认摘要。它不调用身份提供方、第二因子证明、会话事务或可重试存储回调，不更新 seen、不裁剪过期记录、不创建账本。

管理流程在第一次 pending 前确认当前会话、强度、近期认证、对象权限、范围、容量和已选代次，并执行宿主请求保护。Bearer 流程校验实际签名、账本记录、代次／代际、期限、当前身份及有效范围；无效请求返回 null。宿主回调期间跨越期限／近期认证上限也在 pending 前再次拒绝。独立公共预算可以被消耗，不能把本组“无认证状态效果”解释为所有外部系统均无变化。

`LocalStateWitness::work()` 的准入现在接收已确认完整摘要；显式返回 false 表示不执行业务并返回 null，原有 void 准入保留。即便返回 false，仍须确认完整来源及根没有改变；回调暗中写入原始 SQL 会被检测，后续来源保持陈旧拒绝，不被采用为新基线。这不是原始外部写入的回滚证明。

请求保护及范围回调在准入时执行，必须只读，不消费受保护证明或进行业务写入。该次请求的当前范围与对象权限在锁内固定，效果阶段使用已封存判定，不再次运行宿主授权回调。原生服务仍复查真实身份、会话、令牌及最终来源；进入效果后发生真实 I/O 失败、提交不确定或最终预算拒绝，保留 pending，不伪装成无效果拒绝。这里没有时间与文件系统的跨系统原子事务保证。

委托管理复用同一提供方的原生 `RolePolicy`，按实际操作者会话和目标身份运行纯对象规则，撤权会使旧会话失效。`Authorizer::stateRolePolicy()` 只提取配置，不授予认证。含效果审计或自定义 PolicyProvider 的委托 Authorizer 明确拒绝这个原生模式；这些扩展的 SDK 集成缺口仍登记为未完成，不转称宿主已负责或视为全部授权入口通过。
