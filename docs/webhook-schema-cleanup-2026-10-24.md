# Webhook 共享表结构读取清理（2026-10-24）

本批只修复共享结构／耐久性／权限／索引查询、两条零行结构锁的完成检查，以及失败语句的清理。处理器仅验证空表状态读取；未执行领取、重试、未知回执续办或跨安全代际交接。

## 问题与修复

四个隔离 SQLite 修前样例在 PHP7.2／8.5 重现：外键查询关闭失败仍返回回执，另外耐久性／列查询未显式关闭；执行后异常也未清理。修后四例均返回 `webhook.inbox_cleanup`，无新记录，实例不可复用。原始日志保存在[证据目录](webhook-schema-cleanup-evidence-2026-10-24/before72.log)。

共享 `InboxSchema` 保持原来的固定 SQL、行数／字段字节预算、读取方式和回调顺序，集中检查显式关闭；准备成功后若绑定、执行或截止时间检查失败，也会清理。驱动私有异常不会带入 SDK 异常链。`ProcessingSchema` 的引擎读取同样接入。另以四个空表状态查询样例确认 MySQL 两条零行表结构锁查询忽略关闭结果；现复用同一关闭检查。接收器和普通处理器事务会记录共享清理失败，后续入口在调用权限依赖前拒绝。

变更仅涉及四个 SDK 源文件，无 SQL 结构、持久格式、默认时间预算或公开契约调整。公开 API 及兼容检查以最终记录为准。

## 验证及失败保留

共享检查候选的九版 PHP7.2—8.5 新增专项共 522 场景、7380 次断言通过；SQLite／API 18/18、MySQL 9/9。此前候选的九版收件箱 DDL 检查 18/18 通过；之后只删除静态分析证明冗余的类型判断，并补齐处理器零行锁的关闭检查，未改 SQL。

准确候选的 PHP7.2／8.5 全新离线 Composer 消费者安装完成：7/7 外层步骤及 8/8 功能程序通过，367 个运行时文件逐一核对摘要。两端两后端原生共享状态 4/4 通过；45 次语法检查和静态分析通过，API278。静态工具的可选 turbo 扩展因系统 GLIBC 版本无法加载，常规分析正常完成。

后续[普通处理读取修复](webhook-processing-read-2026-10-24.md)继续修改 SqlProcessor；本页记录的共享检查结果对应 `final-inputs.json` 的阶段候选，最终源码复验以后一批证据为准。

首个测试版本没有在清理临时表前释放故障注入保留的实际游标，PHP7.2 报表锁错误，见 `first72.log`。测试随后增加仅用于自身资源回收的明确关闭，不改变操作期间的关闭失败。因首轮没有输出准确临时目录，按时间筛选的一个候选目录不能确定归属，保留未删除，见 `initial-cleanup-candidates.json`；不清理其他任务资源。

首轮 MySQL 外键注入误选 `KEY_COLUMN_USAGE`，实际固定查询为 `REFERENTIAL_CONSTRAINTS`。未触发故障的断言失败保留，不计为产品通过。首次静态命令使用不存在的 `vendor/bin/phpstan`，实际工具在 `tools/vendor/bin/phpstan`；实际分析发现一处重复类型判断，最终处理见后续结果。
