# 原生业务事务的捕获事实策略

本批复现了独立缺口：已有 `SnapshotPolicy` 能接入凭据委托，但业务事务只接受固定 `RolePolicy`，无法通过受保护的业务入口使用捕获事实策略。新增测试在修改运行时前因 `withSnapshotAuthorization` 不存在失败，见[原始证据](native-business-policy-evidence-2026-10-23/before.log)。没有执行旧账号恢复、跨安全代际交接或未知回执续办。

新增 `CredentialRegistry::withSnapshotAuthorization`，参数顺序沿用 `withAuthorization`，策略参数为 `SnapshotPolicy`。旧入口签名及行为保持，底层共享 SQL 事务、Bearer 返回核验和整体预算。公开类／接口仍为277；对候选清单逐项比较，只增加这一个方法，旧类型、方法、常量和属性完全相同，见[契约审查](native-business-policy-evidence-2026-10-23/api-review.json)。没有放宽普通 `PolicyProvider` 的接入条件。

策略必须使用账号图中同一个 `SqlStateSnapshot` 实例，等价配置的另一个实例也拒绝。准入时捕获对象事实并判定对象及字段权限；效果开始前使用相同已准入快照再次判定；SQL 完成后，在只读 Bearer 核验中用当前快照重新判定原 Intent。整个流程不延长原请求预算。评估器必须是可信、有界、无 I/O 的纯计算，外部服务和任意查询不能声明为原生事实。

业务准备回调只读加载服务端 Intent；事务回调必须自行比较版本，全部写入者遵守同一见证和围栏。最终策略看到已提交的数据，因此业务策略应明确合法的提交后状态。若提交后失去对象权限，结果拒绝交付，但已提交 SQL 不撤回，也不自动重放。效果开始前策略异常保留 pending 并禁止执行事务回调；本批测试只断言失败与隔离，不解除或续办 pending。

专项测试覆盖正常修改、实际行归属拒绝、字段拒绝、错误来源、效果前异常、返回异常及提交后归属变化；后者确认 SQL 已提交但没有成功结果。另回归原 `withAuthorization` 和独立 Bearer。首轮 PHP8.5 七种场景通过。初次静态分析的闭包引用类型推断及共同策略接口诊断已修正，未加抑制；最终静态分析通过，保留原可选 turbo 扩展 GLIBC 警告。

最终[汇总](native-business-policy-evidence-2026-10-23/summary.json)：九版本定向矩阵48项中46项通过、2项失败；私有MySQL8/8通过（PHP7.2使用显式单调时钟运行环境，另有PHP8.5）；离线归档／全新消费者12/12通过（默认PHP7.2与PHP8.5），安装源码摘要一致，临时消费者已清理。该归档早于后续操作授权修复，只证明本批对应快照。默认 PHP7.2 已出现两项失败：权限拒绝场景在前置凭据发行期间遇到认证依赖失败，根因未确定；旧业务正常场景进入明确的持续时间时钟倒退拒绝。两者均保留，不通过重跑覆盖，不以单调时钟专用运行环境替代默认环境验收。

本批不代表完整候选或稳定版通过。原 MySQL 默认预算、PHP7.2 默认时钟与未解释失败、其余非暂缓产品缺口及最终范围核对仍开放。暂缓功能和外部宿主／平台验收没有执行。未提交、推送、部署或外部投递。
