# 密码恢复核心与强恢复审批契约

当前核心、显式工厂和可移植测试已写入SDK工作树，候选及当前SDK整合专项均已通过。此模块以当前已验证邮箱的所有权证明替换密码，保留地址、角色、状态和MFA，推进凭据版本，不自动登录。它不执行地址迁移或重置因子。旧邮箱丢失时使用独立的[强审批邮箱恢复核心](account-mailbox-recovery.md)；因子替换和完整R2.7仍待后续交付。

`Recovery` 与注册／地址变更使用不同的账本命名空间和Outbox生产者。宿主需实现 `IdentityRepository`，从同一PDO返回当前业务版本与绑定实际凭据的有效身份。私有表沿用显式账号／Outbox DDL，不自动安装或清空历史。构造需要独立公开恢复、管理和通知读取权限，正式四维共享请求预算、密码哈希／策略、通知加密及外部可信epoch。

`request(address, source)` 统一返回受理，不创建账号，不改账号状态，不返回选择器／秘密。仅活跃且已验证的当前账号产生加密恢复通知意图。重发有冷却和累计次数，更新秘密不会延长原窗口。所有者以明确POST调用 `confirm(selector, token, password, source, proof)`；取消仅消耗邮箱挑战，不产生改密权限。原生方法／CSRF／缓存和统一错误映射由后续入口实现。

挑战绑定用途、账号完整快照、有效密码身份、当前因子代际、邮箱证明及期限。证明尝试在独立短SQL事务提交；验证因子、强恢复审批、密码策略和哈希在SQL事务外完成，全部共享原I/O预算。最终事务重新核对当前身份与最新挑战，条件替换密码、消费挑战和创建安全通知在同PDO原子提交。最终请求预算检查放在提交权限及审批复核之后，晚返回／超时／时钟回退拒绝并回滚。SQL失败不退还已消耗的恢复码、外部审批或共享预算。

未启用MFA且没有额外因子／审批策略时，当前邮箱证明允许密码替换。MFA或已绑定因子要求额外证明：`['type'=>'recovery','code'=>原一次性恢复码]` 通过注入的 `Auth\SecondFactor` 以原代际原子验证，且可信返回方法须恰为 `recovery`，普通TOTP不自动成为此恢复入口的替代证明。MFA账号缺少因子适配时拒绝。成功后因子代际、启用标志和其他未消耗恢复码保留，下一次登录仍需MFA。

宿主可显式注入强恢复审批回调，使用 `['type'=>'approved','code'=>宿主审批凭据]`。回调收到 `(phase, scope, subject, context, proof)`：

- `verify` 在SQL外调用，必须验证并原子消费独立的一次性审批。审批由宿主强认证／人工核验流程创建，不能信任客户端自报已批准、管理员标志或邮件证明本身。
- `current`、`commit`、`complete` 复核同一审批的当前授权、撤销和期限，不能再次消费或执行联网。回调只可严格返回布尔 `true` 才通过。
- `context` 由服务器绑定站点／epoch、作用域、选择器、当前账号／有效身份、因子代际、原邮箱证明、此次新密码及原期限。审批不能转给其他密码、账号或挑战；宿主只能在私有流程中处理它，不记录原始证明或密码。
- 默认没有审批回调就不启用该替代路径。回调权限与公开申请权限独立，不能把一个宽松回调同时当作强身份验证。已启用MFA的当前代际仍须由因子适配提供。

`initialize()` 需要当前管理权限；`notification(id)` 需要独立工作进程权限，但不是实际Outbox租约或SMTP发送器。恢复秘密只在私有加密通知中，队列正文保存稳定通知编号。密码成功变更通知不含秘密，保留原收件地址；后续凭据／邮箱变化不抹去已提交安全通知。`maintain()`／`rotate()` 有界、用途隔离并复核检查点与选中正文，不删除宿主账号、因子或Outbox记录。

工厂增加 `accounts.recovery_authority`，可选 `recovery_factor`／`strong_recovery` 服务名称；调用 `Security::recovery()`。只启用恢复不要求配置普通登录／操作授权，但必须有明确的恢复权限及当前身份适配。诊断只核对类型与结构，实际因子持久性、审批强度／期限／消费、独立恢复锚点和邮件传输由宿主验证。

改密会让读取当前凭据版本的旧会话／持久登录拒绝；不承诺把跨存储登记物理删除在同一SQL事务提交。提交前失败保留原密码与队列，已消耗外部证明不退款；已提交但返回复核失败报告 `account.completion_unknown`，必须重新查询当前账号事实，不能直接认定未改密或重复执行。

实现参考 [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) 和 [MFA Recovery](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)。测试仅使用本地私有SQLite和自建无TCP MySQL，不能据此声称邮件送达、生产灾备或完整账号恢复验收。

验证边界见[最新记录](verification.md)：当前SDK两版SQLite／一版自建MySQL各267项、219源码静态、180类API和两版实际安装消费者通过，完整SDK门禁、实际邮件和原生页面仍未执行。

密码恢复与邮箱恢复的过期请求也可通过maintainFor／rotateFor执行原生管理维护，须绑定准确账号来源、当前管理会话／角色和页参数。普通维护的管理回调新增complete阶段；提交后拒绝报告完成未知，不自动重试。该能力不确认恢复、不启用账号、不执行未知回执续办，详见[过期请求维护](expired-request-maintenance-2026-10-22.md)。
