# 依赖与来源清单

本清单记录当前仓库各Composer清单及锁文件的**本地快照**，供发行复核和漏洞响应定位。它不描述任何使用方实际安装的依赖集，也不等于经验证的软件物料清单（SBOM）或来源可信认证。版本、引用和来源以相应`composer.lock`为准；可选包没有锁文件时，以使用方的实际锁文件为准。

`bin/lock-inventory.php`现可对**一份实际存在的**`composer.json`／`composer.lock`配对生成稳定JSON：输出根包要求、锁定的运行时／开发包、版本、许可证、来源／归档引用及两份输入的SHA-256。例如先执行`composer validate --strict --working-dir=tools`，再执行`php72 bin/lock-inventory.php tools > /tmp/sosecurity-tools-inventory.json`。根包、`tools`和HTML Purifier验证项目已按当前本地锁文件定向验证；`tests/lock_inventory.py`检查相同输入的输出一致、锁文件缺失拒绝、带认证信息的来源URL拒绝及超大输入在解析前拒绝。生成器不联网、不安装依赖、不读取宿主数据库；它不验证远端来源是否可信，也不代替Composer自身的锁文件一致性检查或安全公告审计。独立可选包没有锁文件时必须在真实消费者安装后对其锁文件生成清单；当前不能把版本范围写成已锁定物料，完整消费者SBOM仍是开放项。

PSR-3、PSR-15和OIDC的全新本地路径消费者现于Composer安装及`audit --locked`后生成并核对各自的准确锁定清单；本地path仓库URL在清单中标为`[local-path]`，不会把工作区绝对路径当作发布来源。PHP7.2三个消费者已通过，包括OIDC私有MySQL／Redis及本机TLS；这只证明该次临时消费者安装的依赖集，清单随临时目录删除。要保留正式证据，发行流程应对准确候选和实际部署消费者保存生成JSON及对应锁文件，并另行审查来源、许可证、安全公告与目标PHP／扩展版本。其他可选包和真实下游仍未覆盖。

WebAuthn独立消费者现用PHP8.2—8.5四版本地全新安装`web-auth/webauthn-lib`精确5.3.9及其间接依赖，核对同一清单中的`web-auth/cose-lib`、核心与适配包，并运行十组本地组件测试；四次锁定审计均退出0。它同样只代表临时本地依赖集，生成的清单不覆盖目标站点、实体安全密钥、真实宿主或可选包其他依赖组合。

PHP版本和原生扩展也在供应链范围内：当前核心声明PHP`>=7.2 <8.6`，扩展用途见[配置指南](configuration.md)及Composer清单。代码兼容PHP7.2不代表该运行时仍有上游安全维护；实际部署须选用受维护的PHP与扩展，并记录其来源及补丁状态。

发行或漏洞复核时按准确候选提交重复以下步骤：

1. 对根包和每个可选包分别核对`composer.json`、锁文件有无、允许版本范围及归档清单；不得把`tools`或验证项目误记为核心运行时依赖。
2. 在实际目标消费者保存完整`composer.lock`，列出直接和间接包的名称、版本、来源仓库、提交或发行引用、许可证及启用的PHP／扩展版本；版本范围不能替代安装快照。
3. 对每份真实锁定依赖集运行适用的安全公告检查，并核对来源是否属于维护者批准的仓库；无可审计第三方包时记录“不适用”，不把命令的无对象退出码当成通过。
4. 登记第三方组件的支持状态、已知漏洞、风险定级和处理时限，并与[漏洞响应流程](security-response.md)及具体使用方版本关联。2026-10-22 已在漏洞响应流程中定义统一内部风险分级期限及延期规则；实际履约记录、生产来源白名单和所有消费者的 SBOM 仍未完成，因此 ASVS 15.1.1、15.1.2 和 15.2.4 仍是开放项。

当前本地可选包临时消费者与锁定依赖审计结果及其验证范围见[验证记录](verification.md)，不能外推到其他项目或未来解析结果。
