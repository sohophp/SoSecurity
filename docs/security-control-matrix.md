| ASVS 5.0.0 条款 | 当前实现／证据位置 | 宿主责任／未完成范围 |
| --- | --- | --- |
| v5.0.0-7.1.1 | [认证指南](authentication.md)记录 `idle=1800`／`absolute=28800` 秒及范围；`SessionRegistry::policy()`提供实际值 | 宿主须记录其业务风险依据及重新认证规则，默认值不能证明符合特定身份保证级别；NIST 偏离说明不能由组件代写 |
| v5.0.0-7.1.2 | `SessionRegistry::issue()`达到容量拒绝新登记，文档记录默认 16、范围 1—32；`tests/auth.php`含容量与主动撤销 | 所有接入入口必须使用同一权威登记和策略，产品须展示达到上限后的实际操作 |
| v5.0.0-7.1.3 | [身份认证](authentication.md)区分当前发行方与本地会话，`IdentityProvider`每次重取当前身份 | R6.2 发行方适配和真实 SSO 协同尚待完成；宿主须列出实际 RP／IdP、撤销传播和重新认证关系 |
| v5.0.0-7.2.1 | `SessionRegistry::verify()`检查当前身份、因子、服务端记录、秘密摘要、指纹及期限；`tests/auth.php` | 所有业务入口均须服务端核验，不能信任浏览器传回的已验证对象；全宿主写入者与备份新鲜度仍在 R2.7 推进 |
| v5.0.0-7.2.2 | 登记令牌由 `SessionRegistry::issue()`每次动态产生；API 凭据在独立组件管理 | 宿主不能把固定 API 密钥用作会话凭据，混合身份／旧入口仍按 R1.3 复核 |
| v5.0.0-7.2.3 | 登记令牌秘密为 `random_bytes(32)`，编号另用 `random_bytes(16)`；服务端保存完整令牌 SHA-256 摘要 | 随机源故障、运行时与秘密传递通道由部署验证；会话编号不是认证秘密 |
| v5.0.0-7.2.4 | `AuthenticationFlow`的明确 `currentToken`重新认证路径调用 `SessionRegistry::replace()`，保留管理编号并更换秘密；旧秘密在专项中拒绝 | 宿主必须把真实重新认证关联到当前会话，不能误调用独立登录创建第二个会话；PHP 宿主 Session ID 轮换仍须接入方负责 |
| v5.0.0-7.3.1 | `RegistryState`／`SessionRegistry::verify()`执行空闲期限，核验时刷新 `seen`且不放宽原策略；`tests/auth.php` | 实际会话时钟、应用间一致性和风险决定必须另行验证 |
| v5.0.0-7.3.2 | 绝对期限从登记起固定，替换会话保留原绝对期限，核验取更严格的策略期限；`tests/auth.php` | 不能用自动续期、重新存储旧对象或另一套 Session 绕过绝对期限 |
| v5.0.0-7.4.1 | `revoke()`撤销指定登记，`revokeAll()`推进随机代际；旧令牌和原等待 MFA 的挑战在专项中拒绝 | 产品退出须清理浏览器凭据并核验旧凭据重放；远端退出与本地退出分别验收，不能仅隐藏导航 |
| v5.0.0-7.4.2 | `verify()`重取当前账号，明确失去权威且令牌真实时撤销该主体登记；账号指纹变化阻止旧会话 | 禁用／删除入口、缓存、API 凭据及其他节点撤权需完整覆盖；不能把提供器故障当正常不存在 |
| v5.0.0-7.4.3 | `revokeAll()`为组件能力；[账号因子管理](account-factors.md)及恢复专项覆盖已实现管理流程的旧会话拒绝 | R2.7 所有密码／因子／恢复入口的统一撤销与用户选择仍须逐项核对，不能凭一个 API 证明完整覆盖 |
| v5.0.0-7.4.4 | 原生认证示例提供退出操作，[认证演示](demo.md)记录接入要求 | 实际受保护页面的可见退出入口、所有身份导航、CSRF 与完整跳转链属于宿主逐页验收；组件无权保证宿主布局 |
| v5.0.0-7.4.5 | 提供指定主体的 `revoke()`／`revokeAll()`，没有无界扫描全部用户的后台接口 | 宿主须实现并验证管理员权限、租户范围、审计及有界全局撤销；不能把调用方法本身当管理授权 |
| v5.0.0-7.5.1 | [高风险操作](operations.md)绑定准确意图、准备后重新认证和一次性 Grants；账号变更的已实现流程有对应专项 | 邮箱／密码／因子／恢复入口须全部接入实际完整认证，正在推进的独立见证与安全代际不能由近期时间戳替代 |
| v5.0.0-7.5.2 | `all()`只返回管理元数据，`revoke()`／`revokeAll()`提供实际撤销；原生认证示例已对指定／全部撤销增加近期认证，PHP7.2／8.5 Chromium覆盖恢复后拒绝、真实第二会话保持与重新认证后撤销 | 会话管理页面仍须核验当前身份、近期认证和 CSRF；这些低层方法不自行检查操作人的授权，宿主必须补齐 |
| v5.0.0-7.5.3 | Grants 检查近期强度／认证方法及确认后的当前身份；`tests/operations.php`覆盖意图、过期及重放 | 业务须识别全部敏感操作并绑定实际 SQL 版本／权限／副作用；示例不覆盖未登记业务 |
| v5.0.0-7.6.1 | 通用身份提供器能在本地验证时重载权威身份，不代表真实发行方会话协同 | R6.2 待完成实际 IdP／RP 期限、退出及重新认证协议与跨系统验收 |
| v5.0.0-7.6.2 | 本地认证由明确密码／第二因素入口发起；记住登录单独要求主动选择，见[持久登录](remembered-login.md) | 不据此豁免联合登录的用户交互要求；真实协议回调、静默登录和同意记录继续 R6.2 |

本表核对源码、现有专项位置与公开接入契约；本次文档映射未额外执行浏览器、真实发行方或生产验证。统一原生会话管理 UI 与全局管理员撤销没有因表格完成而自动交付。
