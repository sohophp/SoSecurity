# 会话验证返回前的当前身份复核

## 问题与修复

普通 `SessionRegistry::verify()` 先读取账号／因子，再访问存储，原实现返回此前的身份。独立模拟存储在此次访问完成时停用账号，实际观察到 `current_enabled=false`、`returned_authenticated=true`。反例与原始失败见 [before85.log](session-current-authority-evidence-2026-10-23/before85.log)，不是仅凭代码推测。

修复在存储操作成功后重新读取当前账号和因子绑定；完整身份指纹改变、账号消失／停用、返回前已过期或时钟倒退时返回 null。成功结果使用最新身份对象。保留现有存储操作及已提交状态，不恢复旧会话、不退款、不重试。没有放宽任何期限或策略。

兼容性：身份提供器与因子绑定在验证时会多一次读取，应允许重复只读查询；过去可能返回旧身份的并发变化现在拒绝。原公开签名不变。受保护流程同样使用此校验，因此需相应受保护回归；不能仅凭普通模拟对象证明原生集成。

## 证据

[证据目录](session-current-authority-evidence-2026-10-23/)包含本批修改前源码、runtime.patch、固定输入、矩阵、HTTP／SQL／消费者结果。新增 `tests/session-current-authority.php` 并接入 `bin/check.sh` 普通认证分支；没有执行包含暂缓项的完整脚本。

第一版身份复核后，原生 HTTP 登录与凭据 HTTPS 两端4/4通过（登录各192断言、HTTPS凭据各600项）。SQLite原生4/4；MySQL PHP7.2合并读取场景通过，但normal场景因明确的时钟倒退失败，其后4场景未执行。单独执行此前未运行的PHP8.5六场景全部通过。见 `http.json`、`native.json`、`mysql-native.log`、`mysql-native85.log`。这些结果属于补入空闲期限检查前的实现，不能混写成最终版本通过。

随后进一步复现：100秒空闲期限的会话在存储返回前过去101秒，虽未超过绝对期限，仍被接受（`idle-before85.log`）。最终修复同时检查 `seen + idle` 对应的空闲期限，新增存储期间／最终身份读取期间的两个到期场景。没有提高期限或删除测试。

最终源码验证结果另列，固定输入见 `final-inputs.json`；补充前的摘要与结果保留在 initial-* 文件。
