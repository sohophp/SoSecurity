# 原生SQL审计只读准入与单次写入（2026-10-22）

## 实际实现

在准确审计来源绑定基础上，新增 `SqlSink::prepareState(record, maximumRows, deadline)`。它只在已登记的受保护PDO上使用，最大物理记录数为1—1000000且不得小于审计策略容量；调用者仍须通过上一批准确来源声明取得正确容量。这是可信接线辅助接口，不是凭该参数授予授权。

准备阶段先严格编码固定结构且最多4096字节的记录，然后用只读SQL单元核对持久化结构、准确根、顺序余量、本站点策略容量和整个记录表的物理容量。只计算最多128条已过期记录可释放的容量，不在准备时删除或写入。原始审计I/O期限从准备开始，与调用者已经开始的期限取交集；不为提交重新分配预算。

返回的闭包保存准确根及已编码正文，最多调用一次。提交仍需真实受保护状态边界；重新核对根，按原上限清理到期行，再核对全表及本站点容量、插入一条记录并更新根。沿用原SQL事务提交、错误处理与正文限制；普通 `__invoke()` 仍走原默认行为。已使用写入器重复调用拒绝，失败后也不重试。跨准备／提交的业务时钟倒退及原I/O期限耗尽均拒绝。

本批公开类型保持275个，仅新增一个方法，旧签名保持，见api-review.json。没有修改Authorizer或CredentialRegistry的默认拒绝，也尚未把允许／拒绝授权决定接入业务入口。

## 本地验证

新测试仅使用新建账号、SQLite或私有禁TCP MySQL：准备后普通拒绝不写入／不推进见证；成功写入、一次性调用、策略容量拒绝、到期清理保留永久序号；其他站点占满物理来源时拒绝；准备后根变化或时钟倒退时保留pending并停止；共享预算耗尽拒绝。根变化场景明确保留已发生的第一笔审计写入，不清除pending、不续办。

九版另运行原独立SqlSink测试与API核对。两端实际ZIP消费者覆盖普通审计、成功写入、根变化及预算拒绝，核对vendor来源和摘要。源码／测试摘要、准确命令、父进程单调耗时及日志位于[证据目录](native-audit-write-evidence-2026-10-22/)。

## 本次PHP7.2失败的新证据

PHP7.2默认运行时normal场景约2.828秒失败，异常明确为 `Security duration clock moved backwards; the operation budget is expired.`，发生于 `LocalStatePersistence` 见证持久化。该处创建自己的Deadline，没有期限交集调用；只读运行时查询确认PHP7.2.34没有hrtime，使用内部microtime。可确认本次拒绝来自墙钟读数倒退分支，不能解释为普通预算耗尽；尚不能确定底层倒退来源或幅度，也不能据此认定所有历史超时原因相同。

该失败不重跑覆盖、不提高预算、不关闭倒退拒绝，不改变机器时钟。消费者本次通过不能抵销源码目录失败；MySQL PHP7.2继续使用已有真实单调时钟包装，单独记录。
