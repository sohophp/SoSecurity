# Webhook 普通处理元数据字节预算（2026-10-24）

本批修复普通处理记录与已确认接收来源的元数据在 PHP 校验前整体载入的问题。SDK 仅修改 `src/Webhook/SqlProcessor.php` 的两处固定 SQL 投影，新增私有限长方法；不调整 SQL 结构、写入、权限、公开接口或默认时间预算。

## 问题及修复

PHP7.2／8.5 各以一个处理记录、一个已确认接收来源的12MiB损坏字段复现，四个子进程均在8MiB内存上限下退出255，无法返回SDK受控错误。父进程仅清理自己创建的临时目录。修后相同四个样例均受控拒绝、退出0、峰值2MiB，分别为 `webhook.processing_corrupt`／`webhook.inbox_corrupt`。

处理元数据20字段、来源14字段在SQL侧按现有校验上限返回：整数最多19字节、摘要最多64字节、状态9字节、密钥标识32字节，来源事件及资源沿用原上限。超限的非空字段返回拒绝哨兵，不截断后当作有效值。来源时间的合法NULL保持，非法非NULL超限值返回负数，不能归一化成合法NULL。SQLite按BLOB字节长度、MySQL按OCTET_LENGTH限制，保留既有文本／二进制表示和整数规范化。

正文读取已有来源长度上限和SQL精确长度匹配，本批没有扩大正文预算。此前[普通处理读取完成检查](webhook-processing-read-2026-10-24.md)继续负责显式关闭及异常隐私。
