# soSecurity 首个稳定版收口管理（2026-10-25）

本文件落实用户在管理会话中的最新要求：面向现有 PHP 项目按需接入安全组件，控制范围，整理积累的改动，推进首个稳定版本。历史 R1—R6 是产品愿景及后续需求库，不再作为无限追加实现的执行队列。本文件不把任何既有失败、暂缓功能或未完成验收改写为通过。

## 产品与版本边界

- 产品保持框架无关的组件库：Composer 接入、组件可独立使用，不接管宿主路由、账号、权限、数据库或会话。
- 首版优先验收既有基础能力：CSRF、验证码、限流/封禁、密码与会话安全、输入验证/输出编码、HTTP策略、安全上传、受限出站请求、普通API鉴权与Webhook验签，以及这些能力依赖的存储和故障拒绝行为。最终稳定清单必须逐项绑定公开API、运行时、依赖、测试与接入说明。
- 完整受保护账号管理、跨代际恢复、未知结果续办、复杂工作进程交接与事务编排不得因基础测试通过获得稳定承诺。先评估与基础路径的耦合：若会影响基础路径，必须修复或阻止该版本发布；若确实隔离，明确实验状态、显式启用条件和文档限制。不能仅靠改文档掩盖缺陷，也不擅自删除已有接口或降低保护。
- 保留 PHP7.2—8.5 当前兼容声明。若客观无法满足，提交具体兼容性方案给用户决定，不静默缩小版本范围。
- 不新增功能、公开类型、框架集成或平台式管理能力。新发现只在存在具体复现、影响稳定清单或共用底层时进入首版阻塞队列，其余登记后续。

## 当前审查发现与阻塞

1. 未提交变更规模失控：2026-10-25 初查185个已跟踪文件变化、约3.3万新增文件；约3.24万为本地证据。生成API清单占大量行数，不能把行数当成功能工作量。
2. 默认受保护管理流程的3000ms总预算仍缺少跨声明运行时的稳定通过证据，并出现 completion_unknown。禁止重试或续办未知结果，不能提高预算、缓存权限事实或删掉复核来变绿。
3. PHP7.2 Deadline 在无 hrtime 时使用 microtime，时钟倒退选择拒绝，这是现有保护；需要区分环境时钟问题、可用性限制和未解释断言失败，不能将所有失败归因于环境。暂不修改系统时间设置或新增长驻服务。
4. 历史专项及普通828程序证明限定路径，不能拼接为当前唯一候选的最终整轮门禁。
5. 原生复杂路径已渗入共享 SqlTransaction、FileStore、Security 工厂等。基础组件稳定性必须用消费者实际安装和共享后端验证，不能假定“未使用高级功能”就无影响。

## 固定阶段与停止条件

A. 候选整理：在安全停止点核对活动文件；保留所有原始证据和失败。将证据日志留在本地并生成路径/摘要清单，排除出源码提交；保留可维护的源码、回归测试、必要文档和API清单。按依赖形成少量可解释的本地提交，不推送、不打标签、不部署。

B. 验收清单：仅制定一份固定清单，包含基础接入场景、支持的存储组合、成功/拒绝/故障、默认行为及安装/归档验证。每个用例有明确命令、输入身份、退出码和通过判据。禁止通过不断追加新专项取代最终收口。将实验功能与稳定API的具体隔离方案写入报告，列出最多五项真实发布阻塞。

C. 有限修复：一次只修一个已登记阻塞，修前复现、最小修复、相关回归；同一阻塞连续两批没有实质改善，停止原型扩张，提交简化架构/隔离发布/运行环境限制的明确选项。不可把未知结果流程作为优化试验。遇安全拦截时记录原始原因，将工作转向明确的本地防御维护任务；不得伪装意图、绕过审查或降低权限保护。

D. 唯一候选：源码稳定后固定提交和API清单，一次执行该范围适用的PHP7.2—8.5、真实隔离后端、消费者及发行包检查；失败保留，修复后重验受影响项并重新绑定候选。不需要因无关文档修改重复昂贵矩阵。

E. 交付：给出可运行的最小接入指南、迁移/回滚说明、准确限制、测试结果及剩余阻塞。第一版候选和正式发布分别标识；未通过不得标稳定。公开发布、远端推送、真实业务站点修改待用户明确指令。

## 执行协调

管理会话负责候选清点、代码审查与Git整理；VS Code 会话负责当前活动任务安全收尾、阻塞分析和限定修复。收到本指令先回报活动文件/未完成写入/安全停止点；整理期间不要并行改动同一文件或操作索引。后续由管理会话明确交接可写范围。

本次允许阶段性本地Git提交，替代旧记录中“用户未授权提交”的历史限制。禁止改写旧提交、强推、清理用户数据或删除证据。goal只在上述明确承诺范围全部达到时完成；遇能力/环境/安全阻塞应如实报告，不以维持active为目的不断找新任务。
