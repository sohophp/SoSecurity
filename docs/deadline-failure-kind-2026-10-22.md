# 期限失败原因区分（2026-10-22）

本轮复核此前有界诊断：三项观测均未复现PHP7.2提前超时，不能认定墙钟倒退或普通执行耗时是根因。本轮不重复同类探测，不调整机器时钟、不提高期限，也不把后续绿色结果覆盖原失败。

确认并修复的诊断缺口是：`Deadline` 对正常预算耗尽和时钟倒退使用相同异常消息，原始日志无法区分。现在记录本对象曾观察到倒退这一布尔事实；倒退仍立即使期限失效，后续检查及 `restrictTo()` 交集保留该原因。正常耗时的消息保持，倒退使用固定消息 `Security duration clock moved backwards; the operation budget is expired.`。错误类型、调用方传入的reason、默认storage.timeout及公开签名不变；不输出时间戳、调用栈参数或底层异常链。

新增测试先确认原实现不能区分，再验证正常超时、倒退后再次检查及期限交集；同时运行原时钟故障和交集测试。九版PHP共27/27通过，证据见 [matrix.json](deadline-failure-kind-evidence-2026-10-22/matrix.json)。测试加入现有检查脚本，但本次不运行含暂缓链路的完整脚本。两端语法、API和基础套件结果见checks.json，全量PHPStan日志保留原可选扩展加载警告。

这只是提高以后真实失败的可诊断性，不是PHP7.2提前超时根因修复，不证明历史失败当前已消失。未重新执行已经通过的SQL／归档矩阵；没有修改SQL及发行包行为。完整稳定版仍不能宣称通过。
