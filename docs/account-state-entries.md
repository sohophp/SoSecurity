## 当前行为

`StateBoundary` 持有同一独立见证及请求预算，最外层操作完成当前状态复核、持久化pending、业务执行、最终预算与新检查点。认证流程内部的会话登记、验证与替换加入同一活动上下文，不提前发布检查点；退出、拒绝及异常均解除进程内活动标记。进程内标记本身不授予身份或对象权限。

`WitnessedStore` 在任何实际transact之前要求准确活动上下文。读取也可能处理过期数据或重写状态，因此不能绕过；它不改写原始值、有效期或64KiB编码契约。FileStore只新增目录身份摘要，来源与实际存储必须匹配准确目录身份；普通元数据不导出目录路径。组合来源显式确认覆盖，未声明的存储拒绝构造，不能靠一个任意摘要回调宣称覆盖。当前仅实现FileStore的具体存储覆盖；其他后端不是自动适用。

认证、会话与持久登录的原有接口在未启用此候选时保持；新构造参数可选追加。启用时认证／持久登录与会话必须使用准确同一 `StateBoundary`，受保护存储不能交给未声明该边界的服务。所有既有211类公开成员保持，新增成员及新类型仍须在正式SDK接入时分类、复核与冻结。

## 请求检查与结果

### 只读权限视图的同次 SQL 采集候选

后续候选 `/tmp/sosecurity-state-capture-_6rot5gs` 为 `SqlStateSnapshot` 增加 `capture()`：完整摘要仍覆盖全部声明的表、字段和行；在同一次事务及哈希读取中，额外复制固定主键对应的指定字段。不得在摘要计算结束后再次查询权限字段，再将新值与旧摘要组合使用。选择器在查询前验证，最多8条、每条16列，按声明的最坏长度每条最多64KiB、合计256KiB；选择不存在或被来源筛选排除的行明确返回null。所有未选中的数据仍须通过完整结构、类型、长度与容量检查。

`SqlStateCapture` 仅保存采集结果，不授予权限，不是独立见证批准的能力对象。值与来源身份封装为不可变数据，普通导出不包含字段内容，序列化／反序列化拒绝；显式访问器可返回调用方要求的字段。后续权限评估必须由锁内见证自行采集、核对准确完整摘要，并使用固定无副作用的评估器，不能接受外部构造的结果冒充批准，也不能将SQL采集阶段等同于完整会话／因子权限验证。

九版SQLite新增每版77项检查通过，其中提交后竞态测试在快照COMMIT后立即由独立连接改写字段，结果仍为旧摘要对应的原始字节。分页中途并发修改、复合主键、缺失／筛选行、NULL／空BLOB／NUL、精确容量、选择器超限前置拒绝与未选中大字段拒绝同时覆盖。四个“完整摘要之后重新查询字段”的隔离反例在PHP7.2／8.5的SQLite／私有MySQL准确失败。九版378条关联／语法命令通过，382份冻结程序保持，九次共享SQL摘要与前版完全一致；静态分析通过。原私有MySQL控制器已退出0，34组关联测试、每版401项通过；补充提交后竞态每版5项通过，实例已停止并清理。源码及测试382份哈希保持，终态记录在候选acceptance.json。

本阶段未改动主SDK运行时代码。FileStore会话与因子的同次采集、组合来源两轮一致性、锁内只读权限评估、pending前明确拒绝及未知结果强审批恢复继续；当前运行时仍保留本节下方所述的pending后回调行为。

### 物理文件与组合来源的同次采集

后续候选 `FileStateSnapshot.capture()` 在原始完整扫描中保留指定文件实际参与哈希的字节，不在摘要完成后再次打开文件。最多选择4个固定SHA-256文件名，每个仍受64KiB文件契约约束；缺失文件返回null，合法零字节文件返回空字符串。未选中的文件继续参与完整摘要及类型、权限、链接、容量检查；无效选择器在目录读取和临时排序文件创建前拒绝。`FileStateCapture` 显式返回原始字节，保持导出隐藏、序列化／反序列化拒绝及不可变性；它不解析或消费会话、TOTP或恢复码证明。

`CompositeStateSnapshot.capture()` 先规范化所有选择器，并仅允许固定的具体SQL／File来源；任一来源是任意插件摘要回调时，连未选中的回调也不执行。当前采集配置是扁平来源，原有普通digest接口仍保留既有扩展行为。随后执行两轮完整来源读取，同时比较所有摘要与选定值；两轮不一致直接拒绝，返回的 `CompositeStateCapture` 保留第一轮对应的不可变子结果。最多选择4个来源，按子来源契约合计最多1MiB；所有未选中来源仍被完整覆盖。内部排序会使用私有临时目录，清理失败拒绝结果；这里的只读是对账号、会话及因子等受保护状态不写入，不代表完全没有临时文件I/O。

最新九版432条关联／语法全部通过，392份冻结程序保持；新增物理／组合／容量检查每版130项，包含精确1MiB选定值的两轮同时驻留、实际8MiB PHP限制、选择器引用被外部修改、跨轮物理状态变化和不支持的回调。九次SQL摘要与前版相同，旧版／新版在相同路径和inode上的18次物理摘要也相同。两版私有无TCP MySQL18组、每版227项及四个MySQL反例通过；另有四个SQLite反例，分别证明省略跨轮复核会返回已改变状态的旧视图，放开回调则会实际写入测试数据。控制器退出0，实例清理，静态通过，终态见候选acceptance.json。

下一步须让独立见证在锁内自行采集、先核对签名当前摘要，再由固定评估器检查准确账号、角色、会话及因子绑定；不能把外部构造的采集对象当成批准。正常拒绝才可安全发生在pending前。该阶段及未知结果的强审批、安全代际、所有宿主写入者仍未完成，完整旧备份风险继续按原规划跟踪。

`StateRequests` 分别提供宿主公开请求检查与当前权限复核的接入点。格式、字节数、无效令牌及公开请求防护／独立预算回调拒绝发生在源状态、身份提供器或存储读取前，不发布pending。合法请求在独立见证保护下再次调用当前权限复核，避免将公开检查的旧结论直接用于写入；即使调用方已在活动上下文中调用公开认证入口，公开门槛仍执行。测试通过可切换回调验证执行次序、拒绝和实际活动状态，不代表原生HTTP的CSRF令牌、浏览器或完整宿主权限接入已验收。

当前权限在锁内失效、提供器异常、最终预算撤销或持久化回执不确定时，仍保守报告未知结果。最终文件可能仍是pending，也可能已经写成current但回执未知；调用方应检查准确状态，不能据异常自动重放或重新初始化。锁内权限阶段目前仍在pending之后，不把本候选称为“任意拒绝均不封闭作用域”；要解决该可用性缺口，仍需有明确无副作用保证的当前权限阶段与独立强审批恢复。

会话管理仍要求调用方授权准确目标，见证不替代对象权限、CSRF、近期重新认证或一次性批准。

## 准确作用域

基础入口复核发现，若SQL来源只选择本租户账号，但服务允许其他租户请求，则其他租户恢复的旧凭据可能借用此见证完成实际认证。PHP7.2／8.5的准确旧实现均取得危险认证标记；测试中另一租户数据不属于本租户声明，不能用本租户检查点担保其新鲜度。

后续候选从独立见证保留不可变作用域，认证、会话及持久登录在请求防护、提供器或源状态读取之前拒绝不匹配的目标；同租户正常登录保持。最新九版360条及两版私有MySQL32组已通过，详细边界见下方。多租户应用须为各作用域建立准确的权威和来源映射；不能把一个已配置租户的边界复用于全部租户。物理存储目录或私有账本也须与声明的覆盖匹配；按当前全目录摘要模型，不同独立作用域共用同一数据目录会相互改变所观察状态，不能作为已支持的分区配置。完整多租户写入与并发接入尚未完成。

## 工作进程权威

绑定见证的 `LocalEpochFence` 使用格式2上下文，签名绑定独立见证身份，与原格式1权威不同。其初始化、工作、关闭及闭合上下文都要求活动见证；注册权威读取同样先检查，常见因子目录、物理因子、恢复、管理与维护路径从此公共边界进入。

旧权威到新绑定权威的交接继续使用既有准确根快照和独立审批，先永久关闭旧权威，再同PDO更新登记、审计并核对结果。它不自动初始化或采用缺失的权威；成为绑定模式后，工作进程交接不能丢弃或替换所需见证。真实部署的旧进程及所有宿主写入者仍须显式停止／迁移，测试中的合成审批与自有进程证据不能证明部署已完成。
