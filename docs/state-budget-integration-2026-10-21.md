# F01 已确认无状态变更的预算拒绝

日期：2026-10-21（Asia/Shanghai）。本组继续原 P1，目标是让能够证明已完整回滚、来源没有变化的普通预算拒绝正常收口；不把已经提交的尝试、已消费证明或不确定结果认定为无变更。固定 28 条初次检查、修正底层重放边界后的 8 条检查、最终相同 SDK 源码的两端普通预算 8MiB 检查均已执行并通过；准确差异和清理见文末。完整 G1、最终恢复及 R1—R6 仍开放。

## 实际行为

显式原生生命周期入口已经持有准确 `StateAccountConnection`。本组让它将该声明传入 `StateBoundary::run()` 和 `LocalStateWitness::work()` 的新增末尾可空 `lifecycle` 参数；旧调用保持原来对异常的隔离行为。声明必须绑定准确边界、见证、PDO 和完整来源，动作限定为注册、密码找回、邮箱丢失恢复的 `request`／`confirm`／`cancel`，不能用一个动作字符串代替声明或权限。

三个服务在账号／最终预算明确返回 false 时，可以由内部 `StateBudgetRefusal` 携带回滚凭据。凭据不接受调用者传入的“已回滚”布尔值，只从真实 `SqlTransaction` 获取当前拥有的事务状态和注册连接的执行上下文。普通未保护组件仍抛出既有 `account.budget`；客户端继续按稳定原因码和 `SecurityException` 分类，不依赖内部异常类型。

只有同时满足以下条件才结束本次 pending，并重新抛出普通预算拒绝：

- 预算拒绝从业务操作直接传出，不来自见证写入、快照、业务已经返回后的回调或最终见证预算。
- 精确 PDO 的事务确认执行了完整回滚，且提交没有开始、没有事务归属丢失、清理失败或不确定提交；加入宿主事务的保存点回滚不提供该凭据。
- 凭据属于本次已结束的边界执行，进程／Fiber 归属一致；本次 pending 前捕获的执行上下文必须发生更新，旧执行的凭据不能重复使用，包括直接调用底层 `work()` 的情况。
- 两次完整 SQL／文件来源摘要都与操作前的已核验 current 摘要相同，独立见证仍是本次准确 pending；最终状态写入和持久化成功。

结束的是已经预留预算的本次拒绝，不再增加一次业务最终预算收费；核对和清理仍受原见证 I/O 期限及有界来源限制。保留相同数据摘要，使用本次新的操作编号和递增修订号完成 current。独立公共预算费用不退款，真实 SQL 中新建的账号、账本和通知队列必须已回滚。没有采纳一个新摘要，也没有自动恢复旧密码、会话或恢复码。

权限／预算／仓库回调仍须遵守既有的同 PDO、无外部不可逆业务副作用契约；SDK 不会把任意直接 PDO、其他进程或外部投递自动变成可回滚状态。三个公开生命周期方法本身只入队，不在这些请求内发送 SMTP。该机制不能当作隔离恢复接口。

## 保持未知结果的情形

确认流程可以先提交一次证明尝试，再进行密码策略、恢复码及后续事务。后续预算拒绝虽然可以回滚账号修改，但整个操作已经改变来源，不能认定为无变更。测试确认注册尝试次数保留为 1，账号仍待验证，独立见证继续 pending。恢复码或其他因子文件已经改变也采用同样的保守规则。

预算回调写入覆盖文件、普通回调伪造相同公开原因码、SQL 回滚失败、旧凭据重放、持久化或来源核对失败均不被本机制自动转成 current。原生公开输入与公共预算的提前拒绝保留前一组实现；本组没有放宽密码／因子审批、预算期限或异常处理。

## 固定验收和反例

第一组 [28 条检查](state-budget-evidence-2026-10-21/execution.json)通过，覆盖两端 SQLite、独立禁 TCP MySQL、受影响的原始存储／授权／纯权限／上下文／生命周期／SQL 回归、接口及静态检查。随后审查低层入口，实际复现了一个边界遗漏：[原始反例日志](state-budget-evidence-2026-10-21/counterexample-low-level-work.log)表明直接 `work()` 可在未更新边界上下文时重复使用旧回滚凭据；当时完整来源仍必须不变，但不满足“本次真实回滚”的要求。

修正通过在 pending 前捕获执行更新条件，补充底层与普通边界两种重放拒绝检查，8 条[有限复验](state-budget-evidence-2026-10-21/followup-execution.json)核对预算、上下文、接口、两端 MySQL 和静态。首次与后续源码身份分开保留，不把初次绿色结果当作未修正边界已通过。早期静态检查发现未定义变量和外部读取被误判为纯函数，初始化准确状态变量并标注真实 I/O 方法后复验，没有压制诊断。

公开类型数量保持 252。两项原方法只追加可空参数，原顺序、名称及默认值保留；新增准确见证核对和执行更新检查，见[初次接口差异](state-budget-evidence-2026-10-21/api-compatibility.json)和[后续接口差异](state-budget-evidence-2026-10-21/followup-api-compatibility.json)。不改变数据库 DDL、凭据或见证封存格式。

PHP 7.2 生命周期使用已记录的私有 sodium／原生单调时钟，Fiber 子项未执行（该运行时没有 Fiber）；PHP 8.5 的 Fiber 和两端实际子进程归属检查分别记录，不把 PHP 7.2 写成 Fiber 已验证。工具可选 turbo 扩展的 GLIBC 警告保留，静态分析结果单独记录。

本组停止条件已经达到：上述正常拒绝、反向故障、准确接口／来源核对和资源回收完成，停止扩测。两次私有 MySQL 实例均已关闭删除，诊断反例的四份原源码已按原始哈希保留。完整交付核对见[证据核对](state-budget-evidence-2026-10-21/delivery-check.json)。
