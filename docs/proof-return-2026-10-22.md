# 原生请求证明的最终返回复核

## 已复现的缺口

原生 CSRF／验证码的共享 StateProofConnection 在效果回调内检查权限和期限，但独立见证随后仍会检查完整来源、执行最终请求预算并持久化 current。此前入口直接返回，没有重新核对这段时间内的权限、时钟及证明期限。

独立测试复现四项失败：最终检查推进时钟后仍发出过期 CSRF；最终撤权后仍发出验证码；一次性 CSRF 已消费但撤权后仍返回验证成功；只读 CSRF 准入期间撤权仍返回成功。准确失败日志见 [before.json](proof-return-evidence-2026-10-22/before.json)。这不是此前普通验证的期限缺陷：CsrfTokens／Captcha 已有完成时间复核，本批保留其行为并补齐共享原生权限和签发返回检查。

## 修复与兼容

唯一修改的运行时文件是 StateProofConnection。它保存实际准入调用者，见证操作结束后再次调用同一只读权限守卫，核对同一调用者、时钟不回退、证明仍有效及完整操作未超时。时限对象也传给 StateBoundary，使见证写 pending 前遵守同一已经开始的时限。

验证在最终失权或到期时返回 false；签发／撤销最终失权抛固定 proof.denied，签发到期抛 proof.expired；时钟回退或总时限耗尽分别保留 proof.clock／proof.timeout。守卫可能多执行一次，必须可重复且无业务副作用。原有中途失权／效果失败仍保持 completion_unknown 与 pending。

如果最终见证已经完成，返回复核拒绝不会撤销已提交账本，不恢复被消费的证明，也不重置见证。测试明确核对 current 对应实际来源：失败签发保留已写记录，失败验证／撤销保持消费后的状态，只读验证保持原见证不变。没有未知结果续办、恢复启用或跨代交接。

没有增加类型、方法或参数，公开清单仍为 273。未修改普通 CSRF／验证码算法、输入限制、尝试次数和原有测试断言。新增测试使用自己的 SQLite／隔离 MySQL、FileStore 和模拟当前权限，不包含真实 HTTP、外部投递或生产数据。

## 验证范围

新增测试对 CSRF 和验证码覆盖签发过期、时钟回退、最终总时限耗尽、签发／验证／撤销失权及验证到期；另覆盖只读 CSRF 失权。既有原生套件覆盖权限、来源、容量、旧已消费证明备份重放拒绝、中途失权、准入和效果阶段过期，以及公开工厂。两端四进程测试验证单次消费只产生一个成功者。

准确矩阵、MySQL、归档消费者、源码摘要及失败记录保存在 [证据目录](proof-return-evidence-2026-10-22/)。这是当前源码的定向验证，不是整个项目或完整 F01 验收。旧 PHP 7.2 时限失败、上传隔离完整保护图、其余入口核对、暂缓及外部验收仍开放。

最终本批结果：九版定向矩阵 81/81、两端隔离 MySQL 14/14 条命令（42 条场景通过记录）、归档／离线全新消费者 10/10、两端四进程单次消费 2/2、语法 4/4 全部通过，PHPStan 无错误。PHP 7.2 MySQL 使用既有原生单调时钟／sodium 包装；旧默认时钟失败并未因此关闭。唯一运行时文件与消费者安装内容摘要一致，公开清单仍为 273、签名不变；临时消费者已清理，MySQL 控制器正常退出并清理自身资源。可选 turbo 扩展 GLIBC 警告保留。准确命令、摘要及结果见 [result.json](proof-return-evidence-2026-10-22/result.json)。
