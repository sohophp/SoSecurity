# 原生操作者与目标身份合并捕获（2026-10-23）

## 实际修改与证据

继续核对原生委托默认预算时，源码显示 `nativeAdmission` 和每个审计权限复核阶段分别调用 `credentialView` 读取操作者和目标，每次都会捕获完整声明来源。对测试 PDOStatement::execute 计数确认：一个带首次注册TOTP的操作者与无因子的全新目标，分开读取需要SQLite732次、MySQL420次预备语句执行。计数不包含PDO直接执行的其他SQL，也不等同于生产耗时。

新增 `StateAccountPolicy::credentialPair()`，合并两者的首次SQL／会话选择与完整来源捕获；内部从同一捕获拆出准确选中行，复用原身份、目录、因子和会话重建逻辑。因子引用仍从已核对的目录发现，再执行完整来源捕获及准确摘要校验；没有跨调用缓存、接受调用者提供的捕获、取消校验或扩大预算。同账号只重建一次。缺失目标或无效操作者仍返回相应空结果，业务入口继续默认拒绝。

`CredentialRegistry` 的原生准入及审计当前权限复核使用该入口。实测对应读取阶段降至SQLite488次、MySQL280次，均减少三分之一。完整SQL／文件扫描、原选择数量／字节上限、因子一致性、会话有效性、来源摘要、当前权限及最终返回检查保留；这不是减少全部流程三分之一耗时的承诺。

公开类／接口仍275，仅新增credentialPair方法，旧签名保持；见api-review.json。该方法只返回受保护来源的读取结果，不授予权限，调用者仍需准确见证边界。原credentialView的公开接口保留。
