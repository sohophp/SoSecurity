# 结构证明复用的事务锁前置验证

2026-10-23。本轮只增加私有MySQL专项测试及独立控制器入口，未改产品运行时、公开API278、原有预算或DDL。上一轮减少一次解析仍未解决默认签发超时，因此核对跨回调结构证明能否安全复用的必要条件，不缓存授权结果。

MySQL官方说明，事务中的表元数据锁会阻止其他连接DDL，普通自动提交的锁只覆盖语句；保存点相关命令另有生命周期规则。依据：[元数据锁](https://dev.mysql.com/doc/refman/8.0/en/metadata-locking.html)、[保存点](https://dev.mysql.com/doc/refman/8.0/en/savepoint.html)。文档不能替代准确SQL路径的实际验证。

在控制器自建、禁TCP的MySQL8.0.46上，PHP7.2.34和8.5.9各验证四种情况，共8项通过：

1. 原生PDO执行当前零行双引用解析并关闭游标后，另一连接DDL因1205锁等待超时拒绝；事务提交后同一DDL成功。
2. 执行普通宿主回调及SDK保存点见证探测后，上述阻止仍成立；提交后DDL成功。
3. 反例：在原始零行读取之前建立保存点，读取后回滚到该点，另一连接DDL实际成功。因此不能仅凭“曾取得元数据锁”跨保存点继续使用结构证明。
4. 当前SDK证书路径：进入真实宿主事务前置保存点之后建立证书，再回滚到该前置点；复用触发内部configuration.sql_transaction_lost，外层以sql.cleanup拒绝，后续工作计数0且不提交。只有测试自己创建的空宿主事务由测试显式清理。

初轮误把第三种原始读取也视为锁始终保留，断言失败；独立观察实际DDL被允许，修正为明确反例。证书测试初版也未匹配加入宿主事务后的外层cleanup异常，后来同时断言具体内部见证错误及外层清理拒绝。原始失败与错误栈全部保留，不记为产品通过；没有修改产品保护。最终结果见[verified.log](schema-mdl-evidence-2026-10-23/verified.log)及[汇总](schema-mdl-evidence-2026-10-23/delivery.json)。

由此确定后续实现的最低约束：只在同一可证明的事务与锁生命周期内考虑保存结构事实；当前权限、数据库上下文及临时表遮蔽必须每次新读；写入、事务结束和归属未知均不得沿用证书；保留现有因子、会话、账号与最终返回检查。上述条件尚不是实现或性能验收，本轮未启用跨回调复用。

全部产品运行时和SQL资源摘要仍与上一轮实际归档消费者一致，所以没有重跑无变化的归档安装。测试仅创建自己的表、连接和私有数据库服务；最终控制器退出0，测试表清理完成，没有外部投递、提交、推送或部署。默认3000ms真实时钟签发仍以前一轮失败为当前证据，本轮未重复等价实验；暂缓链路、外部验收和当前goal均未关闭。


后续代码路线限定在现有账本双表结构证明：把固定DDL事实与当前可见权限分开；首次仍完整校验，复用时仍执行实际表解析、原有直接TRIGGER权限条件及当前数据库核对。结构事实只绑定同一事务见证、数据库和固定契约；数据库变化退回完整校验，权限不足直接拒绝。

只允许既有原生PDO／语句、SystemClock和无宿主回调入口使用这个路径。其他配置继续逐次完整校验，写入、结束事务、清理异常及归属丢失清空证明。原账号／因子权限回调和普通会话触达不变；不通过缓存actor、scopes或授权结果减少工作。

实现后需实际验证撤权、临时表遮蔽、切库、回滚到早期保存点、跨连接DDL等待和失败清理，再执行原3000ms真实时钟首次签发。以上是尚待实现的路线，不代表新缓存已存在或已有通过结果。
