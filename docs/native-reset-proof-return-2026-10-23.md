# 独立重置证明的原生最终返回核验

本批仅验证 `Password\ResetTokens` 的一次性证明原语和自有SQL事务边界：使用新建测试账号，SQL回调只修改隔离计数表，不修改密码、不恢复或重新启用账号、不交付通知。最终版本还逐次核对账号行摘要完全不变。最终账号恢复、未知回执续办和跨代际交接仍排除。

修前正常签发对照通过；issue在最终撤权／到期后、consume在最终撤权／到期后、execute在最终撤权后仍交付结果的五个反例已独立复现。源码及日志见[native-reset-proof-return-evidence-2026-10-23](native-reset-proof-return-evidence-2026-10-23/)。

原生请求完成后增加只读核验：重新捕获当前账号记录并调用原请求守卫，检查证明期限、时钟及整体预算。纯证明入口必须保持原账号绑定；已有业务回调可能有意改变版本，因此execute在当前账号记录上重新授权，不将旧记录当作当前权限，也不重新消费证明。账号不存在时拒绝返回。准入、事务和最终核验共用原30秒事务上限内的Deadline，单次见证预算保持。时间源异常转换为固定reset.clock，不串联原异常。

后置拒绝不退款证明、不撤回已提交SQL，不自动继续或重放。测试在已知完成的消费／撤销后再次提交同一证明，确认只读拒绝且见证版本不增加；这不是未知结果续办。业务变更、证明消费和返回结果分别断言，账号数据保持不变。

公开API及277类型不变。宿主边界需支持 `password.reset.issue_check`、`password.reset.consume_check`、`password.reset.revoke_check`、`password.reset.execute_check`。请求守卫会再次接收原动作、范围和当前AccountRecord，需有界、只读、可重复；参数仍通过局部副本传递。没有新增恢复工作流、审批或宽松降级。

PHP8.5首轮13个场景与静态分析通过；共享预算场景使用20秒测试事务＋11秒最终守卫，确认已提交后超时拒绝且账号记录不变。最终九版本定向矩阵42/42、私有MySQL8/8（PHP7.2显式单调时钟包装与PHP8.5）、离线归档／全新消费者12/12（默认PHP7.2与PHP8.5）通过。安装运行时摘要匹配，临时消费者已清理；逐项命令与退出码见[汇总](native-reset-proof-return-evidence-2026-10-23/summary.json)。不能用这些证明原语检查代替账号恢复链路或全项目验收。既有默认时钟、默认预算及外部关口保持开放。未提交、推送、部署或外部投递。
