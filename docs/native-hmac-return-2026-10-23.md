# 原生 HMAC 验签及业务结果的最终复核

新建隔离账号及初始因子环境复现四个独立反例：`verifyFor` 和 `withVerification` 在最终守卫撤权或签名期限结束后仍返回成功；正常验签对照通过。原始结果见[native-hmac-return-evidence-2026-10-23](native-hmac-return-evidence-2026-10-23/)。没有执行旧账号恢复、未知回执续办或跨代际交接。

`HmacVerifier` 现于见证完成后执行只读返回核验，重新调用同一个请求守卫，核对签名期限及时间不回退；全部读取结束后再次核对时间。准入、SQL事务及返回核验共享原有30秒事务上限内的整体Deadline，见证自身预算保持。返回失败不退款nonce、不重试业务，不撤回已经提交的SQL。时间源异常转换为固定 `api.clock`，不串联私有原异常；守卫异常仍为固定 `api.request_unavailable`。

公开类型仍277，方法签名与候选清单保持不变。普通验签路径保持。原生宿主边界守卫需显式支持 `hmac.verify_check`、`hmac.execute_check`；请求守卫会再次接收原 `verify`／`execute`、固定签名身份和原业务Intent，必须允许有界、只读、可重复调用。已声明密钥环不可变，来源要求没有放宽；在线密钥提供器及密钥迁移没有新增支持。
