# Webhook 已绑定 PDO 的状态边界修复

本批继续原计划非暂缓的写入者覆盖，修复 Webhook 对已注册状态连接的绕过。运行时只在 `SqlInbox::accept` 和 `SqlProcessor` 共用事务入口各增加一次 `SqlStateAccess::assertActive`，保留此前时钟、请求权限、事务所有权及异常处理修复。

## 问题与实际行为

同一 PDO 注册语义状态边界后，绑定前构造的 SqlInbox 仍能在边界外接收并写入记录；SqlProcessor 的六种事务入口也没有查询连接注册表。现在它们在 SQL、提供器／权限回调及业务处理前检查当前状态边界。绑定前已有对象和绑定后新对象都受到约束；不能通过保留旧服务对象绕过连接保护。未注册连接保持原行为。

测试没有进入旧安全代际、没有旋转工作进程、没有续办未知回执或启用恢复账号。使用新建的私有 SQLite／MySQL，声明接收表、处理表及本次业务表的完整列、主键和行数上限，创建独立见证后绑定真实执行守卫。它直接调用内部 PDO 注册机制以验证这一底层约束，不能替代尚未实现的公开 Webhook 完整覆盖声明。

共47断言覆盖：原接收对象及两代处理对象的13个边界外有效调用全部拒绝，SQL计数和相关回调计数保持不变；边界内真实接收、领取、执行及业务SQL成功，见证摘要一致；改动已覆盖业务表后，再次执行在业务权限回调前以 `account.witness_stale` 拒绝。无效输入的纯内存提前拒绝不是SQL事务入口，不承诺其错误码变为状态边界错误。

## 兼容与剩余缺口

公开签名不变。已注册受保护PDO的宿主，先前直接调用Webhook服务的行为现在抛 `account.state_required`；这是修正边界绕过。普通未注册PDO和组件原有事务所有权保持不变。

这两处守卫检查“连接是否处于已绑定的执行边界”，不会证明当前来源声明包含Webhook的全部表、策略、提供器密钥及业务资源，也不实现正常拒绝的原生只读准入。仅手工包装 `boundary.run` 不等于完整产品接入。本批正向测试证明该底层约束可在全新环境中工作，仍不能把公开Webhook工厂接入、在线密钥权威、旧ApiKeys或维护余项记为完成。历史PHP7.2普通维护超时、暂缓项、外部验收继续保留；goal保持active。
