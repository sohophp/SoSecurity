# 快照列与主键元数据合并读取

默认 MySQL 签发诊断确认，预备语句准备是此前执行计时遗漏的重要成本。本批实际修改 `SqlStateSnapshot::mysqlSchemas`：每组最多四张表的列与主键元数据，通过带类型标记的 UNION ALL 一次读取。两个分支分别保留原有 `表数×65` 和 `表数×5` 行限制，再显式排序；原有列类型、长度、主键顺序、前缀拒绝、唯一性、BTREE、表引擎、重复列和完整性判断保持。读取业务行之前和之后的两次结构复核都保留，不缓存权限或元数据，不改变事务、默认预算和失败处理。

## 对照与产品验证

先保存修前源码并从其实际执行中提取查询，再构建候选查询。1／4 张表、每表 5／64 列、每表四列主键的三轮交替对照，共 480 次完整原始结果比较通过；没有通过转换数据类型掩盖差异。查询数从每轮 40 降至 20。聚合耗时变化分别为 -6.06%、-6.30%、-14.31%、+4.82%；极限宽表存在退化，不能宣称全面提速。比较过程包含结果校验开销，不是端到端签发验收。

产品测试保持旧摘要：单表完整快照执行次数由 20 降至 18，五表由 28 降至 24。新增 `schema-union.php` 验证前后两次完整结构读取，以及真实主键前缀和额外列拒绝，并接入显式 MySQL 分组专项。

- 已执行并通过：PHP 7.2—8.5 九版 SQLite 63 项、私有 MySQL 72 项定向程序；覆盖四表各 64 列的 8MiB 限额、结构变化、NULL／空值／二进制内容、捕获摘要、并发写入与提交后隔离。
- 已执行并通过：静态分析、277 类／接口 API 契约、离线 ZIP 归档及 PHP 7.2／8.5 全新消费者六个步骤；消费者实际运行三类 MySQL 快照测试，安装源码摘要与工作树一致。
- 已执行并通过：PHP 8.5 原生审计委托正常配置场景 77 项断言。此场景采用测试原有配置预算，不是默认预算验收。
- 已执行但失败：PHP 7.2 原生集成因持续时间时钟倒退而拒绝。原始失败保留，没有替换时钟或重跑覆盖；同一运行器未执行的 PHP 8.5 项已单独补验。

默认预算另行在其他自有测试结束后复验：PHP 8.5、默认 3000ms，首次签发观测 3.053552 秒，仍在首次 actor 校验返回 `account.completion_unknown`。没有续办 pending，后续列表／轮换／撤销未执行。耗时包括失败传播与清理，不能解释为只差约 54ms；默认产品可用性缺口仍开放。证据为 `default-timing.json`、`default-run.log`、`default-result.json`。

为量化剩余差距，另用测试原有 `normal` 配置的 30000ms 预算，仅测量全新初次签发；成功后立即返回，不执行后续操作。实际完成耗时 7.811684 秒（PHP用户态约1.033秒、系统态约0.841秒）。产品默认值仍为3000ms，没有通过扩大默认预算取得绿色结果。这是诊断，不是默认验收，且不是修前／修后的端到端性能对照。证据为 `configured-timing.json`、`configured-result.json`。后续应定位完整流程的成本，不能把默认超时截断点当作剩余耗时。
