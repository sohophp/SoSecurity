# 隔离代际中的账号处置候选

本阶段承接[受控代际交接](account-state-successor.md)，继续完整 R2.7。当前候选位于 `/tmp/sosecurity-state-containment-policy-g_vbp0nd`，尚未接入 SDK。它只提供固定账号禁用处置，不提供账号启用、密码设置、普通业务回调或采纳当前数据库的入口。

## 固定操作和准确选择

`StateAccountContainment` 绑定同一见证、准确复合来源／SQL来源、PDO、完整十列账号定义和复合主键。当前原生账号配置对应 `examples/SqlAccounts.php`：每批明确选择同一作用域内最多八个不同主体，配置构造阶段拒绝超额、重复、NUL、非UTF-8和不匹配的来源定义。原生配置之外的宿主字段语义仍须显式适配和审核，不能由同类型列推断业务含义。

每个被选账号执行同一组变更：密码设为空，角色清空，地址验证取消，状态保持禁用，强制需要MFA；凭据版本与地址版本按新的随机操作标识、计划摘要及主体分别派生。账号主键与地址保留，未选中的账号不更新。旧因子材料、会话文件和通知队列暂时保留用于后续准确处置，不能据此重新启用账号。

预览前先验证独立管理角色及实际近期认证策略。`StateContainmentReview` 绑定完整旧权威封存摘要、预期代际、交接修订、递增批次、准确观测状态、计划、数量和独立审批配置，最多有效120秒。确认仍使用真实密码／MFA会话、准备后的重新认证及一次性Grants，不接受布尔审批适配器。原生管理界面还须展示准确账号选择及处置含义，尚未完成这一界面。

## 副作用与执行权限

独立审批通过后先持久化 `remediation.phase=pending`，再在拥有提交权的单个SQL事务内更新。每条UPDATE对原有十列做完整匹配，字符串按二进制比较，包含NUL的旧值也必须完整匹配；任意选定行在采集后变化都会使本批回滚。提交前再次核验当前独立身份、授权期限和同一pending权威。

固定写入能力只在原见证的准确进程／原生Fiber、相同计划及操作标识、有效句柄和活动范围内有效。直接调用、克隆见证、跨进程／Fiber或工作结束后的调用均不能借用它。普通请求预算回调不成为业务写入回调。

完成后仍为 `quarantined`，原可信摘要和旧未知操作保留，不能用本批的观测摘要替代可信基线。交接头保持原始交接语义；`remediation.review.sequence`单独递增，每批通过完整前驱权威摘要关联。后续批次需要新的准确预览及新一轮授权。完整历史的外部归档与最终恢复提交仍待完成；文件仅保留有界当前回执，写入前检查完成回执仍能容纳在4096字节内。

pending确认失败、提交前撤权、COMMIT确认丢失或最后预算拒绝，都返回未知完成语义并保持隔离。存在pending回执时拒绝下一批；完成回执写入后丢失持久化确认时，可能读到complete字节，但这不开放普通业务，也不允许重用原授权自动重试。必须重新核对实际回执和账号状态，再决定明确的后续处置。

## 数据库结构和可见性

首版固定更新仍可经触发器改变未选账号，或经外键级联改变其他表。两个版本的本地SQLite均已复现真实侧作用，修正类在预览前拒绝相关表；外键约束关闭时仍检查其声明。执行事务内还会锁定实际账号表后重复检查，避免把预览时的检查当作提交时的事实。

MySQL不能把空的触发器元数据当作没有触发器：官方说明这些信息受到`TRIGGER`权限过滤，见[MySQL触发器元数据](https://dev.mysql.com/doc/refman/8.4/en/show-triggers.html)。私有实例的准确对照已复现：普通DML连接看不到root定义的触发器，旧检查仍执行更新并造成真实额外SQL；修正版在预览前以 `account.containment_visibility` 拒绝。

当前严格候选只接受能够从直接授权中证明全局元数据检查权限的独立恢复连接，无法证明时拒绝。部分撤权也可能让全局授权标志与实际元数据可见性不同，当前恢复候选拒绝启用 `partial_revokes` 的MySQL检查配置，查询能力不可用时同样拒绝；不自动更改服务器设置。见[MySQL部分撤权说明](https://dev.mysql.com/doc/refman/8.0/en/partial-revokes.html)。角色间接授权等配置不在当前已验证范围；这是恢复候选的适配限制，不能作为给普通应用账号扩大权限的部署建议。测试权限只配置在自有、无TCP的临时实例内。低权限业务连接与独立元数据读取的正式适配、相关共享SQL检查和完整MySQL结构新鲜度复核继续 R1／R4.5，尚无全SDK整改结论。
