# 幂等原生首次执行与已知结果查询（2026-10-22）

本批接续初始化／维护，新增 `SqlExecutor::executionTarget()`、`executeFor()`、`lookupTarget()`、`lookupFor()`。使用准确状态连接、真实会话权限、已有宿主请求授权和完整 SQL 来源；首次业务写入与幂等记录在同一 PDO 事务提交。公开类型保持275个，旧方法签名逐项保持，新增方法见证据目录的 `api-review.json`。

## 调用与边界

`executeFor($policy, $permission, $request, $businessTables, $handler)` 必须声明1—4个业务表及准确 columns／primary／where 定义。定义必须被连接的 SQL 来源覆盖，并进入权限目标摘要。宿主应先调用 `executionTarget($request, $businessTables)`，据此构造操作为 `idempotency.execute` 的真实 `StatePermission`。查询使用 `lookupTarget($request)` 及操作 `idempotency.lookup`，传入 `lookupFor($policy, $permission, $request)`。权限包含当前会话、角色、强度和时效，不能从请求subject推导。

业务表声明是可信宿主处理器的契约，不是任意PDO语句的沙箱。宿主必须只修改声明覆盖的业务表，不能自行提交事务、外部投递或修改无关安全状态。声明至少一个业务表；未覆盖定义在业务执行前拒绝。SQL 来源的物理容量和原幂等策略容量同时生效。

进入pending前，只读事务校验根、永久键历史、具体记录及正文；无角色、普通请求／执行拒绝、缺失结果查询、冲突、已过期结果和已满记录表均不推进见证。准入生成的执行ID、请求指纹、创建时间与期限用于实际执行，不能被按引用修改的授权回调改变。实际事务第一笔根／记录读取必须与准入完全相等。

原事务负责写入、正文预算、授权、提交与错误脱敏。原生入口使用最初的期限，不重置I/O预算；完成独立见证后再次检查宿主权限、真实会话权限、业务时钟和结果期限。同一连接的重入执行拒绝。已知完成结果可查询和重放，不再次调用业务处理器；成功查询会记录观察时间并推进见证。

失败处理保持默认拒绝。处理器异常导致业务和幂等SQL回滚，独立见证保留pending；测试到此停止。最终返回撤权或过期时不返回结果，已提交状态保留。未实现未知结果续办、跨安全代际工作进程交接、最终恢复启用及其完整F01链路。

## 验证与限制

专项覆盖准确请求绑定、未覆盖业务表、无角色、缺失查询、宿主拒绝、回调异常隐私及引用修改、重入、同PDO首次提交、已知查询／重放、冲突、物理容量、已过期记录、业务异常回滚与pending保留，以及最终拒绝／到期。默认10秒配置另列；测试不会放宽保护获得绿色结果。

测试仅在自建SQLite、私有禁TCP MySQL及离线全新Composer消费者运行。PHP7.2 MySQL使用已有真实单调时钟包装，不能据此关闭默认时钟的历史提前超时。首轮测试表声明不匹配的失败、后续测试失败均保留。完整统计见 [result.json](native-idempotency-request-evidence-2026-10-22/result.json)，源码摘要、命令、日志和API比较位于同目录。

本批为定向验证，不是全项目或完整稳定版验收。历史默认时钟失败、其他非暂缓事项的最终盘点、暂缓能力及外部验收仍开放；goal保持active。没有提交、推送、部署、生产数据库操作或外部投递。

最终结果：九版定向72/72、私有MySQL两端12/12、语法10/10及全量PHPStan通过；归档／新消费者15/16。PHP7.2消费者normal场景约6.241秒发生SQL提前超时，失败保留；未重跑覆盖。四个归档运行时文件摘要相同，验证期间五个源码／测试文件摘要保持。临时消费者和自建MySQL已由各自测试运行框架清理。
