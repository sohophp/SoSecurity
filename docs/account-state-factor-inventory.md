# 隔离恢复中的历史因子清单

更新：2026-10-19。此阶段是独立状态候选的只读基础，不是物理因子销毁、业务恢复或完整 R1—R6 的交付。当前候选为 `/tmp/sosecurity-state-factor-inventory-bound-dedb6bik`，尚未接入主 SDK。

## 需要解决的问题

当前因子指针不能代表全部秘密材料。账号可能同时拥有旧版原始槽位、正在准备的替换因子、已取消的绑定，以及尚未清理的独立恢复槽位。直接对当前指针调用普通撤销，也不能证明这些历史槽位已经处理；隔离状态下更不能为了调用普通接口而重新开放旧权威。

`StateFactorInventory` 从准确绑定的目录和已保留工作流历史中枚举坐标。它不运行宿主权限、审批、通知、因子证明或业务回调，不消费恢复码，不返回密钥、恢复码、密码或原始载荷。返回值和游标都是数据，不授予销毁或启用权限。

## 固定来源和完整验证

构造必须绑定同一格式3见证、完整组合来源、实际 PDO、SQL 与文件来源、目录、受管理因子、完整密钥对象、时钟及四个真实工作流服务。四个工作流的实际策略和工作进程权威必须一致；不能从数据库中随意选择一个权威标识来满足检查。

四个服务新增候选内部 `stateHistory`／`stateSlots` 读取入口，复用各自真实解析器，覆盖正常管理／首次绑定、因子替换、独立新因子恢复及旧版迁移。历史解析沿用真实读取器的规则，不要求旧预览的封存键仍在独立预览密钥环中，但整个账本记录仍须由当前保留的账本密钥验证。迁移旧指针还须验证目录结构和原始固定坐标。

每次读取先验证准确目录及其单条集合，再完整扫描共享工作流账本：验证根、每条记录封存、完整载荷摘要、全局记录数和按实际顺序计算的历史摘要。其他账号的记录也参与集合验证；不以当前账号筛选后的数量替代全局历史。替换和独立恢复游标指向的记录必须实际存在，并属于相同用途和账号。无根却存在记录、有效旧签名记录替换、删除、错误格式和悬空游标均拒绝。

每个采集使用同次摘要与页面数据，组合来源还会进行两次一致性采集。目录、各历史页及游标目标之间必须保持同一个完整组合摘要；不能将第一次目录值和后来的历史值拼接后返回。

## 分页与边界

返回顺序为固定旧版坐标、当前有效目录坐标，然后按账本主键顺序展开已保留记录中的坐标。相同物理文件来自不同历史记录时保留各自证据，不静默去重或遗漏。固定旧版坐标的因子代号为 `null`，表示仍需检查实际物理内容，不能推定为空或据此删除任意代号。

每页最多8个坐标；完整账本每次只保留7条有界记录，载荷每条最多16KiB，沿用选定行64KiB／总量256KiB预算。游标绑定配置、主体和完整观测摘要，状态改变后旧游标拒绝。默认总读取期限30秒；复杂历史超过预算时安全拒绝，不返回未完成清单，也不承诺数据库内部缓冲区或总RSS受相同限制。

当前物理来源仅支持已覆盖的原始 FileStore。文件坐标须由实际因子服务推导并受文件来源覆盖；尚未实现其他存储适配。清单覆盖固定旧版、当前目录及仍保留的已知工作流历史，不宣称能够反解哈希文件名或识别已失去所有引用的孤立秘密。
