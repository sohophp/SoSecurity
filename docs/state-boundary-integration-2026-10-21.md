## 本次实际接入

本专项冻结时主 SDK 为 303 份源码、251 个公开候选类型及 52 个内部类型。本阶段新增 19 个公开候选类型和三个内部辅助类型；原 232 个类型的既有成员、参数顺序、默认值和返回类型保持，仅追加可选参数及方法。准确差异见[接口兼容核对](state-boundary-evidence-2026-10-21/api-compatibility.json)。这些仍是未发布候选，不是稳定版接口冻结。

逐项核对并迁入历史候选中的运行逻辑，没有替换整个源码目录；保留主仓库后续的账本校验顺序、目录载荷上限、幂等读取修复和设备风险处理。初始迁入位置及双方摘要见[迁入记录](state-boundary-evidence-2026-10-21/integration.json)，后续修正以实际冻结执行清单为准。运行源码和测试不加载历史原型或其自动加载器。

| 部分 | 当前主仓库行为 |
| --- | --- |
| `LocalStateWitness` | 默认显式格式 2；持有稳定 inode 的排他锁，检查准确 PDO／来源／物理域／签名／摘要，先确认 pending 持久化，再执行业务，完成后保存 current。未知效果不重放、不自动采用数据库 |
| `StateBoundary`／`WitnessedStore` | 最外层操作完成一个检查点，内部调用共享上下文；进程、子进程和 Fiber 不能借用其他上下文。作用域、不同权威、缺覆盖或不支持的物理后端拒绝 |
| 认证／会话／持久登录 | `AuthenticationFlow` 三个入口、`SessionRegistry` 七个状态入口及 `RememberedLogin` 五个入口可显式绑定同一权威；保留现有设备风险处理。受保护认证拒绝弱格式 1 |
| 原始 FileStore | 按完整物理目录登记访问门槛，同目录中新建实例、不同 namespace、克隆和包装都不能在边界外 transact／prune；最多 128 个进程内目录绑定，不自动移除或换权威 |
| 当前权限 | `StateAccountPolicy` 仅用同次完整采集和共用纯校验检查账号、密码身份绑定、角色、会话／期限、目录账本及物理因子，不调用另一份身份提供器或消费因子证明。正常拒绝发生在 pending 前 |
| 请求准入 | 公开请求保护在锁前；只读当前准入在锁内、pending 前执行，随后复核完整摘要。普通准入拒绝保留 current，下一次合法请求可以继续；准入回调不是账号权限策略 |
| 登记因子工作进程 | `LocalEpochFence` 可绑定准确边界；实际工作进程权威读取、轮换、因子目录及已登记流程在缺活动权威时拒绝。交接不能降级为无边界权威 |
| 隔离恢复 | 独立当前管理员、近期强认证、准备后的重新认证、一次性参数绑定授权，依次关闭未决旧根、建立新隔离代际、固定账号处置及准确物理因子处置／未知结果续办。**这些步骤仍保持 quarantined，没有最终业务恢复提交** |

目录绑定仅保存小型执行状态及检查闭包，不保留完整 PDO／密钥／服务图。长驻进程需要复用一个准确边界；不能通过创建新对象热替换旧权威。跨进程仍必须正确引导全部写入者并停止旧代码，进程内登记不能阻止任意旧程序直接写 SQL 或文件。

物理域检查排除见证与已声明 SQL／文件／临时来源的明显重叠；它不证明运维人员不会把独立权威一起恢复。独立备份权限与恢复流程仍需部署验收。格式 1 仅保留通用旧接口测试用途，不能接入受保护认证／权限流程。

## 实际持久化与运行环境

`LocalStatePersistence` 是显式可选的 Linux／Python 3 平台适配。它把准确打开的文件和目录描述符传入隔离 Python 子进程，核对内核当前路径与 inode／权限／单链接，再执行文件及目录 `fsync`，有界读取输出、检查期限并回收超时子进程。它支持 FileStore 已打开临时文件被原子重命名后的同步，不根据过时的 PHP 流 URI 重开文件。

构造不启动子进程、不创建状态；基础密码／CSRF 组件不要求这个适配。其 I/O 位于明确的见证／物理处置过程，不能放入可重试 AtomicStore 回调。真实文件同步调用不等于已完成掉电、存储控制器或网络文件系统验收。

PHP7.2 两次检查出现不同位置的超时；一次额外诊断在实际运行中捕获墙上时钟倒退，证据见[诊断记录](state-boundary-evidence-2026-10-21/deadline-diagnostic.json)与日志。SDK 原有倒退拒绝逻辑保持。后续 PHP7.2 检查使用私有、原生 `CLOCK_MONOTONIC` 测试扩展提供 `hrtime()`，不是模拟时间，也没有修改系统 PHP。扩展源码在 `tests/runtime/php72-monotonic/`，头文件 RPM 仅提取到临时目录，没有系统安装；构建与二进制摘要见[构建记录](state-boundary-evidence-2026-10-21/monotonic-build.json)，实际解释器见[运行环境](state-boundary-evidence-2026-10-21/runtimes.json)。这不能写成当前 WSL 的普通 PHP7.2 已通过整轮。

同时补齐 `Deadline` 对原生／墙上时钟异常、负数及非有限数值的拒绝，错误码为 `storage.clock`，保留正常期限和倒退过期行为；独立的两种时钟分支故障测试加入常规入口。

## 固定验证及准确范围

冻结的执行计划包含：两端各 27 个边界／隔离恢复用例、基础组件、时钟故障、认证、完整加密 MFA、持久登录、设备风险、API；受影响源码静态检查、入口语法及控制器自建禁 TCP MySQL。前一快照两端各八项命令已通过，包含 27 个 SQLite 边界用例；随后静态分析达到工具默认 128 MiB 上限而中止，未启动 MySQL，见[前序记录](state-boundary-evidence-2026-10-21/final-execution.json)。提高分析工具限额至 512 MiB 后发现守卫闭包中可变匿名对象的状态推断问题；已改为专用内部 `StateExecutionContext`，集中维护进程／Fiber 所有权，保留最小依赖。修正后 39 份受影响源码静态检查、两端上下文／原始存储／入口强制及 API 检查通过；SDK 测试仍使用 16 MiB。

最新快照与前序只有内部执行上下文、边界委托及内部类型清单三份变化，逐项摘要及检查见[增量收口记录](state-boundary-evidence-2026-10-21/closure-execution.json)。增量收口的 11 条命令均退出 0，包括两端各 27 个完整 MySQL 用例。开始／结束的运行输入摘要一致，控制器创建的 `/tmp/sosecurity-mysql-magr7dng` 已关闭并删除；[交付核对](state-boundary-evidence-2026-10-21/delivery-check.json)已通过。该阶段保留前序静态失败与三份输入差异，不合称同一快照整库门禁。检查过程中另外复现的 `Grants` 及嵌套包装入口缺口已由后续入口修复单独收口，不改写此处冻结快照。静态分析可选 turbo 扩展因系统 GLIBC 版本不足未加载的启动警告保留，检查本身退出 0，不宣称零警告。

完整备份用例分别实际撤销会话、改密、禁用因子、轮换恢复码，然后恢复测试宿主声明的七张 SQL 表全部字段及会话／因子／持久登录原始文件，保留独立见证。受保护入口必须在业务回调前拒绝，且不读取另一份提供器状态；独立进程明确省略见证后，实际旧会话／持久登录及旧恢复码会重新被接受。负面对照使用真实恢复数据及 SDK，凭据只通过私有文件传递，不写进命令行或输出。

此处“完整”仅指该固定宿主已声明的认证服务图；未启用的 API 凭据、链接、其他生命周期／通知写入者和联合身份不由这个用例证明。MySQL 组表示账号及账本后端为 MySQL，物理认证状态仍为 FileStore，不证明受保护的 Redis／MySqlStore 已实现。固定账号处置要求完整依赖元数据可见性；测试只在自建临时服务器给专用测试账号授予对应检查权限，不能推导为普通业务账号已支持，也不建议生产扩大授权。
