# F01 生命周期连接声明与原始 SQL 入口保护

日期：2026-10-21（Asia/Shanghai）。本组属于既定 P1，不增加阶段或预算。主 SDK 已实现下述保护；有限检查结果见[固定执行记录](state-lifecycle-evidence-2026-10-21/execution.json)。固定 28 条命令已执行并通过，输入一致，临时 MySQL 已清理；两端 SQLite／MySQL 新测试各 171 条。完整 G1、最终恢复及 R1—R6 尚未完成。

## 实际行为

新增 `StateAccountConnection`，由现有纯 `StateAccountPolicy::accountConnection()` 或显式认证工厂 `Security::stateAccountConnection()` 构造。声明绑定准确边界、见证、组合来源、SQL 来源、PDO、账号仓库、站点／作用域／代际、时钟和账号策略。它要求来源覆盖十个账号字段及完整 SDK 账号账本／Outbox 表，并核对主键及过滤条件；不接受只有八个认证字段、遗漏邮箱版本或遗漏通知表的声明，不进行运行时自动推断。

四类服务 `Registration`、`AddressChange`、`Recovery`、`MailboxRecovery` 的构造函数末尾新增可空 `state` 参数，原参数、默认值和顺序保留。其状态入口要求准确边界当前处于执行阶段。提前创建的旧无边界对象，在连接登记后也会拒绝执行；同一逻辑站点／作用域／代际不能以另一 PDO 构造旧的生命周期对象绕过登记。地址变更还核对准确会话及操作授权服务。

同一外层边界包住整个生命周期操作，不能只分别包装内部 SQL 事务。注册的通知队列初始化发生在账本事务前，注册确认及两类恢复也可能跨越多个事务或外部审批阶段。当前调用方必须先完成公开请求检查，再显式进入准确操作边界；`run()` 本身不提供身份或业务权限。需要当前账号权限的操作仍须使用纯策略与 `authorized()`。

工厂可先构造纯认证策略，再调用 `stateAccountConnection($policy, $addressColumn, $addressVersionColumn)` 缓存声明，随后创建四类生命周期服务；也可通过 `accounts.state_connection` 注入事先审查的声明。没有完整声明时继续明确拒绝。保护模式的恢复服务使用准确受管理因子适配器，显式注入其他适配器会拒绝，不能静默覆盖配置。

进程内连接登记同时保护普通 `SqlTransaction`、账本首次模式检查、`SqlOutbox` 和账号通知 `Dispatcher`，示例 `SqlAccounts` 也在读取前核对执行状态。快照与元数据使用内部观察事务；它仅允许 SDK 固定的读取查询和必要的事务控制，不是通用不可信 SQL 过滤器。固定账号隔离写入则校验准确见证、隔离计划及当前隔离操作能力。

登记最多保留 128 个准确 PDO 引用及小型执行守卫，不在全局注册表保留整个认证服务图。不提供热替换或注销后重新采用旧权威的入口。

## 固定验收及已知边界

本组固定检查两端 PHP 7.2／8.5 的新增生命周期、既有认证工厂、隔离／后继恢复、注册／改邮箱／两类恢复、各工厂和 SQL 事务；API 核对、独立禁 TCP MySQL 以及 PHP 7.2 目标静态检查。准确命令、退出码及输入哈希以执行记录为准。工具可选 turbo 扩展存在 GLIBC 兼容警告，实际静态分析完成且无错误。PHP 7.2 使用已有私有 sodium 与原生单调时钟扩展，不能写成未增强系统 PHP 通过。新 API 的兼容性见[接口差异](state-lifecycle-evidence-2026-10-21/api-compatibility.json)。

新增测试验证登记及构造无查询／回调副作用、旧与新裸入口在副作用前拒绝、观察事务拒绝 UPDATE 与写入 PRAGMA、四种初始化、实际注册通知及确认、错误证明／弱密码返回后仍为 current、恢复旧 SQL 后在宿主回调前拒绝，以及工厂四种服务接线。其余三种完整受保护业务流程尚未在本组逐一完成，不把原有无保护模式回归检查当作这些流程的联合恢复验收。

首次将观察查询限制收紧后漏掉内部读取 `PRAGMA busy_timeout`，测试失败；补入准确只读语句后重测。新工厂测试首次遗漏必需的授权配置也失败，修正测试配置后重测。原始日志均保留，未删除失败证据；此前 142／164 条测试属于开发快照，不与最终快照累计。

以下仍是 SDK 工作，不能改写成宿主责任来关闭：公开输入／预算在 pending 前的原生生命周期接入、其他授权与重放入口、全部声明后端、未知结果后最终安全恢复与重新可用，以及完整候选冻结后的整轮验收。当前恢复仍以隔离中间态为主，不能宣布已完成旧备份风险修复。

进程内守卫不能拦截任意直接 PDO SQL、其他进程或旧部署；实际宿主必须登记写入者并停止旧代码。真实 SMTP、第三方 OIDC、实体 WebAuthn、目标代理／WAF、远端 CI 与独立复核分别保留验收要求，见[环境边界](testing-environment-2026-10-21.md)。未提交、推送或发布。
