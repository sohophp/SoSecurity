# 独立审批关闭未决旧权威

当前修正版为隔离候选 `/tmp/sosecurity-state-retirement-bound-rwhdrz_u`，前版为 `/tmp/sosecurity-state-retirement-dgpmpm_b`，尚未接入主SDK。它承接[持久化操作记录](account-state-operations.md)，实现独立管理身份批准后永久关闭未决旧权威；不自动恢复业务、不重放原操作、不采纳数据库，也不启用新代际。安全的新代际交接、业务账号处理、全部宿主写入者和完整R1—R6继续。

## 审批与准确选择

`StateRetirementControl` 绑定真实 `StateBoundary`、`StateAccountPolicy`、`SessionRegistry` 和 `Operation\Grants`。控制侧须使用格式2、准确会话服务及其受保护存储、同一可信时钟；Grants要求强度2、仅TOTP／WebAuthn、近期性最多300秒和票据期限最多120秒。拒绝密码单因素、恢复码方法、过宽期限和其他服务图，不提供返回true即可批准的适配器。

`retirementReview()` 要求独立控制侧当前有效、近期且拥有 `state_recovery_operator` 角色的身份。预览封存准确权威、修订号、原操作号、原摘要、现在观察到的完整摘要、原操作语义摘要、控制侧绑定及120秒期限和随机数。预览不是授权；操作参数中的大整数转为十进制字符串，避免2038年或长修订号被操作参数预算误拒绝。

随后 `begin()` 展示并绑定准确预览；操作者通过同一会话的新一轮真实强认证后，`confirm()` 才可签发一次性授权。已有的同一认证不能直接确认。`retirePending()` 重新核对封存、准确选择、实际状态和最终请求预算，再消费授权并复核当前角色及有效期。错误预览的票据不能用于另一个选择；撤权、停用、过期、状态变化及最终预算拒绝均不关闭业务侧权威。

## 独立状态边界

控制侧与业务侧须使用不同PDO，并从实际SQL连接识别物理数据库：SQLite使用主文件设备号／inode，MySQL使用服务器UUID和数据库名。更换PDO对象或表声明不能把同一数据库变成独立控制源。文件来源、临时排序目录和权威目录不能重叠；拒绝相同目录、别名及目录包含关系。只支持已确认的具体SQL／文件组合来源，不能通过插件摘要回调声称独立。

这些检查证明当前本地连接和目录的分离，不证明运维备份、密钥管理、操作系统身份或外部权限域已经隔离。正式部署仍须让控制侧和独立权威处于业务备份之外，且将所有宿主写入纳入同一边界；本阶段测试不代表上述部署已完成。

## 永久关闭与故障

业务侧关闭后保留原pending的修订号、操作号、原摘要和语义记录；追加封存的准确预览、控制侧绑定、操作者摘要、消费的授权ID及关闭时间。结果仍是未知，原SQL写入不被撤销或重复。普通入口继续阻断；重复关闭不能再次消费授权，旧格式2读取器也会因未知closed状态／字段拒绝。没有重开接口或缺失文件自动初始化流程。

关闭回执丢失、持久化阶段撤权或过期均报告结果未知，已关闭的权威不会被重新打开。关闭前请求失败仍保留pending，必要时须重新取得独立审批；不承诺票据退款或跨控制存储与业务权威的原子提交。

活动上下文另外绑定进程及当前Fiber；只有同一执行上下文可嵌套使用保护能力。派生子进程、挂起Fiber之外的调用均不能继承活动写权限。PHP7.2—8.0没有Fiber时明确跳过该专项，不记为已执行；实际进程检查仍执行。

## 绑定实际授权策略的复核

首版虽有945条关联检查通过，后续实际复核发现：控制入口另写了300秒期限，也未在只读权限阶段约束具体认证方式。真实Grants策略收紧到30秒时，期限边界会在pending后才拒绝，把正常拒绝变成控制侧未知结果；真实恢复码MFA会话也能通过TOTP专用策略的预览。准确旧源代码反例使用真实密码／MFA会话，不能把首次绿色矩阵当作该部分最终验收。旧结果已标记为results-known-policy-gap，原日志保留。

修正版让预览、准备、确认、消费和当前权限复核都沿用实际Grants的maximumAge／methods；StatePermission增加服务器指定的认证方式集合并规范化复制，当前评估器在达到maximumAge时即拒绝，与VerifiedSession.recent一致。摘要域推进为版本2；不改写已封存的旧操作或未知结论，旧策略预览不会自动升级为新策略授权。普通权限入口省略方法集合时沿用已有强度检查，控制入口始终传入实际非空方法集合。

修正版最终原九版会话86690实际退出0：990条命令全通过，638份冻结输入保持，九次SQL摘要与首版完全相同；关闭／策略／身份专项每版314项，含实际Fiber的五版为317项，权限输入另增6项。原211类API九版保持；26个既有准确反例、三个准确上下文反例、四个准确首版期限／认证方式反例均触发预期危险行为标记。两版另确认期限反例的底层原因为实际operation.authentication导致account.completion_unknown，未把基础设施失败算作有效反例。
