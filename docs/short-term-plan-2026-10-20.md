## 目标与固定范围

用一个有限周期判断现有候选哪些部分可接受、哪些问题阻止进入发行验证，交付一份可追溯的审查报告。本轮不以完成 R1—R6 或达到稳定版发布条件为目标。

- 审查基线：`0974949d8c9464122fec7f75a53985170e194aaa`，变更基线：`3ea8812ead75b99a58f14b44b32862fe3336da76`。
- 范围：两提交之间的 821 个变更文件；未变化文件仅作为理解调用链的参考，不扩大为全库安全审计。
- 本轮只产出审查记录、必要的有限验证证据和下一轮建议，不修改运行时代码、接口、数据库结构或依赖。
- 新增交接、计划及审查报告属于候选之后的文档增量；核对候选内容时使用准确 Git 树，不改写旧清单。
- 不提交、推送、打标签、发布或部署，不改造下游项目。

## 周期和执行安排

预算为累计 **3 个工作日、最多 24 个有效工作小时**，从实际开始审查计时，不是自动定时任务。每日最多 8 小时；到达上限立即整理报告并停止。时间不足的项目标为“未完成”，不能据此判定审查通过，也不自动延长周期。

| 顺序 | 工作与时间上限 | 交付物 | 验收目标 |
| --- | --- | --- | --- |
| 1 | 候选身份和检查清单，2 小时 | 报告中的候选身份、变更文件台账、固定检查命令 | 821 个变更文件均登记所属批次和检查方式；提交、内容摘要及文档增量可区分；执行测试前固定命令与适用环境 |
| 2 | 五批审查，14 小时 | 每批结论及问题清单 | 五批均给出结论、检查位置与依据；逐文件标注已检查／仅辅助核对／未检查，不把归类冒充逐行安全审查 |
| 3 | 有限验证和证据整理，5 小时 | 命令、退出码、日志、源码身份 | 完成下述固定基础检查；仅对已有疑点执行限定的复现；明确区分通过、失败、未执行 |

五批采用[候选说明](review-candidate-2026-10-20.md)的顺序：①基础依赖和通用基础；②SQL／Outbox；③认证、账号和权限；④其他可选能力与通知；⑤适配包、打包和文档。14 小时内优先检查生产入口、授权和事务边界、敏感状态、安装依赖；测试和文档核对其覆盖及陈述是否成立。

## 固定验证范围

1. 对准确 Git 树核对候选摘要、文件集合、类型和可执行位；现有交接文件等后续文档不纳入旧摘要。
2. `composer validate --strict --no-check-publish`。
3. PHP 7.2 与 8.5 各执行一次 `tests/portable-core.php`，并核对未配置 Outbox 时基础工厂不加载 Outbox／SMTP／Worker 的可选性约束。
4. 检查本轮新增或修改文档的相对文件链接、`git diff --check` 和新增文档的补丁空白。
5. 审查发现疑点时，最多选择 **3 个问题**做定向复现，每个问题最多执行 **2 次**：首次复现与一次必要确认。超出部分保留源码依据、触发条件和未验证状态。

上述命令需在执行前补齐准确解释器路径、候选运行目录和日志目录。测试针对固定候选运行；不把后续工作树结果归给旧提交。环境缺失时标为未执行并说明影响，不将环境搭建发展为本轮新项目。数据库复现仅使用自行创建并清理的本地临时实例，不接触业务库。全部测试进程和自建服务必须在本轮结束前退出或清理。

本轮不执行九版本完整门禁，不重复既已关闭的 Outbox 大型矩阵，不新增消费者／浏览器／第三方服务验收。存在具体疑点时，已有对应专项可以占用上述定向复现名额。

## 问题判定与验收

每个问题至少记录：编号、严重程度、源码位置、触发条件、影响、证据、验证状态和建议处置。可复现的越权、认证绕过、敏感信息泄露、数据／事务破坏，以及基础安装或声明兼容性失败列为阻塞项；范围外的新需求列入后续清单，不在本轮实现。

已知的“完整旧备份恢复可能重新激活旧认证状态”必须保留为未关闭的安全阻塞项，不因已有文档或临时原型降级为已解决。详细边界见[交接说明](session-handoff-2026-10-20.md)和[状态新鲜度说明](account-factor-freshness.md)。

| 验收项 | 完成标准 |
| --- | --- |
| A1 范围可追溯 | 唯一候选提交明确，变更文件台账无遗漏；后续文档增量单列 |
| A2 审查有结论 | 五批各有可接受项、需修复项、未验证项及位置依据；未检查文件明确标出 |
| A3 验证可复核 | 固定检查均有准确命令和结果；失败或未执行项注明原因与影响；不混用历史源码证据 |
| A4 风险不掩盖 | 已知旧备份风险及新增阻塞项明确保留，范围外项目不标为完成 |
| A5 按时收口 | 汇总报告交付，进程／临时服务清理完成，下一轮最多 3 项，实际耗时和未完成项写入报告 |

A1—A5 满足且固定基础检查通过、五批计划内检查完成时，判定“本轮审查交付完成”。存在安全阻塞项时仍可完成审查报告，但必须判定“候选暂不进入发行验证”。环境缺失、检查失败或审查覆盖不足时，交付“部分完成”报告并停止，不能宣称全部验收通过。

## 停止条件和后续边界

- 验收完成或达到 24 小时上限，任一条件触发即停止；不得以新增断言、发现更多功能缺口或追求全部通过为由续期。
- 已通过检查不重跑；仅在源码变化、命令执行错误或证据无效时重新打开对应检查，并计入原时间和执行次数预算。正确复现产品缺陷的失败结果保留，不反复运行直到偶然通过。
- 发现严重问题立即记录并调整剩余审查优先级；本轮不自动进入修复循环。报告可以明确建议暂缓发行。
- 已知旧备份修复、审查新增缺陷修复、准确候选九版本发行门禁分别另立工作单；下一轮开始前固定具体问题、交付物、检查和停止条件。
- R1—R6 全部余项、真实宿主、外部 SMTP、OIDC 发行方、WebAuthn 实体设备、独立安全审查、远端 CI 和公开发布继续保留，不作为本轮完成条件。

本计划保留执行前确定的范围及停止条件；实际审查覆盖、检查结果、失败和未执行项以[本轮报告](candidate-review-2026-10-20.md)为准，不据计划推定修复或发行通过。历史依据见[交接说明](session-handoff-2026-10-20.md)及[发行验收工作单](release-readiness.md)。
